**Three things matter most:**

- **The archive can miss content before summarization begins.** The ingest cursor skips edits to previously seen messages, and replay reconciliation can mistake ordinary user text for generated scaffolding. These are additional defects beyond the proposed plan. [Cursor handling](engine.py:4587), [scaffold classification](engine.py:4373)
- **Some preprocessing still destroys the index.** Sanitization can remove a decision between two memory blocks, and tool-pair repair can discard a real result while claiming it is covered by a summary. Raw storage alone does not satisfy the doctrine in either case. [Memory-block stripping](extraction.py:186), [tool-result replacement](engine.py:5569)
- **The curve degrades behavior immediately above 256k.** In an isolated probe, increasing the window from 262,144 to 262,154 tokens reduced the protected tail from 32 messages to **one**. The numerical cap changes from “disabled” to one token. [Anchor](window_scaling.py:73), [cap interpretation](fresh_tail.py:61)

I made no file changes. This report combines source inspection with isolated, in-memory probes; it does not claim a live 1M-token run or provider-level validation. “Default” below means reachable under the documented defaults, including exceptional paths—not that it occurred in the operator’s live database. Optional feature families are identified in the [README](README.md:105).

Findings are ranked by doctrine impact and reachability. Effort estimates: **S** = local correction; **M** = several cooperating components; **L** = schema or host-protocol work. Existing findings are identified where the required change is an extension of the earlier plan.

**1. Critical: ingest assumes an unchanged prefix without establishing that it is unchanged.**

**Reachability:** default; an already-seen message changes or the host supplies a replacement history.

The cursor is bounded by the new list length, but ingest subsequently processes only `replay_messages[cursor:]`. A failed identity-cache comparison prevents cache reuse; it does **not** reset the cursor or persist a revision to the changed prefix. [Cursor](engine.py:4587), [identity comparison and suffix selection](engine.py:4645)

**Probe:** ingesting `"Before correction"`, then replacing that same row with `"After correction"`, left only the first text in SQLite. A second same-length replacement was also skipped.

This is not merely a hypothetical edit API. Hermes can fill an existing assistant row’s `content` during finalization and clear its own persistence marker. B does not use that marker to recognize the revision. Host mutation (Hermes Agent host internals; path elided)

**Fix:** replace positional admission with stable event identities plus content revisions. Verify the prefix before the cursor fast path; retain original and corrected versions with their relationship. Test finalizer mutation, same-length replacement, shortened histories, and restart reconciliation. **Effort L; value critical.**

**2. Critical: text resembling scaffolding can be skipped before it acquires a stored source.**

**Reachability:** default replay reconciliation against an existing session; also the leading-scaffold compaction path.

The scaffold classifier recognizes textual summary wrappers without requiring a trusted generated-message marker, an existing node, or a matching persisted receipt. Reconciliation removes those candidates; its caller allows an empty remaining candidate prefix when the session already contains rows. [Classifier](engine.py:4373), [filter](reconcile.py:449), [empty-prefix acceptance](reconcile.py:497), [caller](engine.py:844)

**Probe:** a user asking to debug an example containing `[Recent Summary (d0, node 123)]` and `[Expand for details: …]` was classified as scaffolding; reconciliation skipped it against an existing stored session. Compaction likewise removes leading classified scaffolds before source-ID mapping. [Compaction removal](compaction.py:727)

The placeholder ledger has a related weakness: persisted hashes and dependent-reply receipts are silently reduced to the last **512** entries. Those receipts affect whether a message is recognized as generated. I verified the bound; I did **not** establish an additional raw-message deletion caused by eviction. [Hash eviction](placeholder_ledger.py:192), [receipt eviction](placeholder_ledger.py:486), [recognition](placeholder_ledger.py:527)

**Fix:** require durable origin evidence for exclusion; literal wrappers remain ordinary source text. Put provenance receipts in a durable, paginated relation rather than a bounded metadata list. Test quoted wrappers, nonexistent node IDs, and replay after more than 512 generated replacements.

A offers a useful narrower pattern: messages without raw replay IDs are retained, and replay candidates are checked against stored coverage and identity. That is a pattern to adapt, not proof that all A admission paths are lossless. [A replay filtering](lossless-claw v1.0.0 src/raw-id-replay-filter.ts:118)

**Effort M–L; value critical.**

**3. Critical: B archives a projection of a message, not its complete raw envelope. The importer repeats this loss.**

**Reachability:** default whenever messages contain additional host/provider fields; A-to-B import is optional.

The message schema and insert paths whitelist content, tool calls, selected identifiers, names, and times. Other envelope fields have no preserved representation. Hermes explicitly carries fields including `reasoning_content`, `reasoning_details`, and provider-specific message items. [B schema](store.py:364), [batch projection](store.py:537), host fields (Hermes Agent host internals; path elided)

**Probe:** a message with a unique value in `reasoning_content` and additional `codex_message_items` lost both fields in a store roundtrip. Hermes may retain another copy; B cannot claim complete recovery from its own archive.

The importer skips non-text/non-tool parts, and can drop messages rendered empty by that projection. This can discard reasoning-only or unfamiliar structured parts that A retained. [Importer part filtering](scripts/import_lossless_claw.py:379), [empty-message handling](scripts/import_lossless_claw.py:484)

A preserves reasoning metadata and raw representations of unknown message shapes in these corresponding paths. [A reasoning metadata](lossless-claw v1.0.0 src/message-content.ts:642), [unknown shapes](lossless-claw v1.0.0 src/message-content.ts:626)

**Fix:** retain a versioned complete message envelope, with searchable columns as projections. Preserve opaque fields without requiring the plugin to understand them. Import original parts and source identities before deriving B’s normalized representation. Test unknown top-level fields, unknown blocks, reasoning-only messages, and import/export roundtrips. **Effort L; value critical.**

**4. High: backup and rotate do not back up the complete recoverable corpus.**

**Reachability:** invoking backup or rotate after any externalization. Generic large-output externalization need not be enabled: inline media/base64 externalization is always active.

Backup copies SQLite only. Externalized content resides in separate payload files, so restoring the database without the original payload directory leaves references whose contents cannot be recovered. [Backup implementation](maintenance.py:79), [always-on protection](ingest_protection.py:1335), [payload file contents](externalize.py:2045)

Rotate also uses a fixed temporary backup path, creating a collision between simultaneous rotations of the same slot. [Rotate temporary path](maintenance.py:119)

A’s database backup is also SQLite-only, so copying it would not solve corpus recovery. Its unique temporary names are independently useful. [A database-only backup](lossless-claw v1.0.0 src/plugin/lcm-db-backup.ts:45), [unique names](lossless-claw v1.0.0 src/plugin/lcm-db-backup.ts:25)

**Fix:** create a backup manifest covering the database and every referenced payload, with checksums and restore verification. Publish the bundle atomically; serialize rotation of a slot and use unique temporary names. Test restoration into a fresh directory with the original payload directory unavailable. **Effort M; value very high.**

**5. High: maintenance can commit another thread’s unfinished transaction. The compaction lock is not a database-wide concurrency protocol.**

**Reachability:** concurrent ingest and maintenance on a shared engine/connection; overlapping engines or processes using the same database are a separate exposure.

Maintenance flushes the message, DAG, and lifecycle connections without acquiring their transaction-owning locks. `MessageStore.commit()` itself does not take the batch write lock. [Maintenance flush](maintenance.py:56), [unlocked commit](store.py:1722), [batch transaction](store.py:537)

**Threaded probe:** an ingest batch inserted its first row and paused. Another thread called the same store commit API used by maintenance. The writer then raised and rolled back, but the first row remained committed. This establishes broken transaction ownership, not physical SQLite corruption.

The fork’s compaction lock is per engine; clones have independent runtime state, and ingest does not acquire that lock. Therefore it cannot establish logical serialization across clones or processes. [Lock](leaf_pipeline.py:180), [clone](engine.py:633), [ingest](engine.py:1608)

**Fix:** enforce connection-owned locking for every writer, commit, and maintenance operation. Add a database/session lease or revision check covering admission and publication across engine instances. Keep provider calls outside long SQL transactions; reject publication against stale session revisions. Extend T1.3 with threaded rollback, two-engine, process, and session-rebind tests.

A’s per-database-handle transaction mutex is relevant, but does not by itself solve cross-process coordination. [A mutex](lossless-claw v1.0.0 src/transaction-mutex.ts:71)

**Effort M–L; value very high.**

**6. High: `/lcm clean` can delete sources still referenced by a retained session.**

**Reachability:** opt-in clean, matching session patterns, explicit command, and cross-session retained ancestry.

Clean excludes the currently bound session, then deletes messages and nodes belonging to selected sessions. It does not check incoming references from nodes outside that selection. `/new` can retain lower-depth nodes in the old session while carrying higher-depth nodes into the new one. [Selection](command.py:630), [deletion](command.py:1907), [retention relationship](engine.py:3590)

Thus cleaning the old session can break a parent in a session the operator did **not** select for deletion. This is a concrete destructive consumer of the relational-provenance weakness already identified as B18. Backup-first does not preserve live expandability. [Clean gating and backup](command.py:1998)

**Fix:** compute incoming-reference closure before deletion; refuse or explicitly archive sources referenced outside the selected scope. Test `/new` retention followed by cleaning the predecessor and expanding the retained parent. A checks canonical and pending summary references before deleting source messages. [A deletion guard](lossless-claw v1.0.0 src/store/conversation-store.ts:1945)

**Effort M; value very high.**

**7. High-impact configuration incompatibility: redaction and storage bypass deliberately abandon the no-loss guarantee.**

**Reachability:** sensitive redaction and session-pattern exclusions are opt-in. Recognized in-process auxiliary children can be made stateless automatically.

Sensitive redaction runs before storage and externalization. Its replacement contains descriptive metadata or a hash, not a recovery reference; status explicitly reports `lossless_recovery: False`. This is marked but irreversible loss within B. [Pre-storage redaction](ingest_protection.py:1344), [placeholder](ingest_protection.py:720), [declared recovery status](ingest_protection.py:667)

Ignored, stateless, and auxiliary bindings skip LCM ingest entirely. Their fallback trimming can delete whole messages, and its eventual omission notice supplies no exact recovery source. [Storage exclusion](bypass.py:25), [ingest return](engine.py:1621), [whole-message deletion](bypass.py:310), [fallback notice](bypass.py:398), [automatic child classification](engine.py:2841)

**Fix:** make these settings explicitly incompatible with a strict-lossless profile, or provide a separately authorized recoverable archive while excluding content from prompts. Do not silently preserve secrets contrary to an operator’s redaction policy. Auxiliary isolation should prevent foreground rebinding without necessarily discarding the child’s archive. Test every bypass reason and fallback path.

The whole-message bypass cut was already a residual; its absence from the implementation plan should not be mistaken for compliance. **Effort M–L; value high when these paths are used.**

**8. High: the source sanitizer can remove the event that a summary must index.**

**Reachability:** default source serialization; additional cases depend on structured content.

The memory-block stripper chooses the last matching closing tag, deliberately sacrificing real text between repeated blocks. An unclosed recognized opener removes the rest of the text. These transformations happen before the fork’s marked-elision wrapper. [Repeated-block behavior](extraction.py:186), [unclosed-block behavior](extraction.py:232), [serialization order](engine.py:5261)

**Probes:**

- Two `<active_memory>` blocks surrounding `THE DECISION WAS TO CANCEL LAUNCH` produced an empty string.
- A document containing a literal unclosed opener lost everything after it.
- `{"type":"json","result":{"decision":"cancel launch"}}` became only `[Structured content: type=json]`. [Structured projection](extraction.py:140)

The raw content generally remains stored. The defect is that the summary cannot hint at a decision it never received. This extends B3 beyond reasoning-tag stripping.

**Fix:** remove only blocks proven to be host-generated. Preserve literal markup as data. Unknown structured fields need content-preserving serialization or a marked field reference with a useful description. Test repeated, quoted, unclosed, and mixed structured blocks through the complete serializer. **Effort S–M; value very high.**

**9. High: tool-pair “repair” loses real results; leaf rescue can create the orphan it later removes.**

**Reachability:** default when results arrive out of expected order; rescue requires a retry-worthy summarization failure.

The guardrail walks results in call order and discards mismatches. It inserts `[Result from earlier conversation — see context summary above]` without proving that any summary covers the discarded result. Only a log reports the drop. [Guardrail](engine.py:5569)

**Probe:** calls `a,b` followed by results `b,a` produced the real `a` result and a synthetic `b` stub. The real `b` result disappeared from the assembled context.

Normal chunk selection aligns tool groups, but rescue eventually falls back to `current_chunk[:-1]`. A probe containing one assistant call and its large result returned only the assistant. If that shortened retry succeeds, compaction leaves the result outside the new node; assembly’s orphan guard can then remove it. [Rescue fallback](engine.py:1662), [remaining-source calculation](compaction.py:980), [assembly cleanup](engine.py:6374)

**Fix:** reconcile results by call identity without deleting unmatched content. Preserve excluded results as quoted data or exact recoverable references. Rescue must retain group boundaries or subdivide summarizer work internally. Test reversed results, oversized single groups, and successful rescue followed by assembly. **Effort M; value very high.**

**10. High: completed-turn capture has an interruption gap and no durable deferred-ingest obligation.**

**Reachability:** default interrupted/empty-final turns, or session-end lock contention.

B registers a `post_llm_call` ingest hook. Hermes runs that hook only when there is a final response and the turn was not interrupted. The host separately supports `on_turn_complete`; B does not implement that completion hook. [B registration](__init__.py:549), host conditional hook (Hermes Agent host internals; path elided), completion dispatch (Hermes Agent host internals; path elided), base no-op (Hermes Agent host internals; path elided)

Preflight ingest cannot capture messages generated afterward. Session-end flushing can also return after failing to obtain its bounded lock, without persisting a retry obligation. [Preflight](compaction.py:107), [session-end failure](engine.py:3511)

This is a capture gap until later replay or flushing occurs, not proof that Hermes’s own archive is deleted.

**Fix:** implement the host’s completion hook with idempotent ingest, and record an explicit completion receipt or durable deferred-ingest obligation. Test interrupted turns, empty finals, locked session end, and restart recovery. **Effort M; value very high.**

**11. High: expansion omits raw fields, while the alternate recovery tool has no aggregate response budget.**

**Reachability:** normal recovery tools; large results require sufficiently large stored rows or arguments.

Node-source expansion returns content without the stored tool-call envelope. Direct store-ID expansion also omits `tool_calls`. An assistant consisting mainly of arguments can therefore appear empty and complete. [Node-source serialization](tools.py:1293), [direct expansion](tools.py:5455)

**Probe:** an empty-content assistant containing a function call expanded as empty content with `has_more: false`; `lcm_load_session` returned the arguments. Thus the arguments are **not wholly unrecoverable**, but the advertised expansion path is incomplete. [Alternate serializer](tools.py:1826)

`lcm_load_session` limits rows and each content field separately, then serializes them together; tool-call arguments are copied without that content limit. At 1M, allowed settings permit 200 × 80,000 = **16 million content characters**, before arguments, without an aggregate rendered-token budget. [Limits](tools.py:1848), [result construction](tools.py:1903)

**Fix:** share a field-aware recovery serializer across tools, with explicit paging of content, arguments, and preserved envelope fields. Apply a total response budget and return exact continuation handles. **Effort M; value high.**

**12. High: source-filtered FTS can return a false empty result after silently bounding candidates.**

**Reachability:** default lexical retrieval with a source filter and enough matching summaries.

Search selects a bounded candidate pool before checking descendant source eligibility. The pool is `min(max(limit × 20, 500), 5000)`. Consequently, eligible rows outside that pool disappear without a coverage warning or continuation. This is distinct from the previously identified LIKE-ordering defect. [Candidate sizing](search_query.py:366), [SQL limit and later filtering](dag.py:624), [reported result count](tools.py:2788)

**Probe:** 501 matching nodes, with the oldest the only node from the requested source: `limit=20` returned nothing; `limit=50` found it.

**Fix:** apply source eligibility before the result limit, preferably through relational provenance. Otherwise paginate the candidate scan and report incomplete coverage explicitly. Test an eligible source beyond each candidate bound. **Effort M; value high.**

**13. High under semantic retrieval: “full” chunking is still sparse, and long sentences can exceed embedding capacity.**

**Reachability:** opt-in embeddings; reranking requires its additional configuration.

Conversational chunking skips short messages below its minimum, including potentially decisive instructions. “Full” mode switches oversized messages to head/error-oriented sampling. The sentence packer does not split a single oversized sentence. [Defaults](chunking.py:27), [mode filtering and sampling](chunking.py:201), [sentence packing](chunking.py:118)

**Probes:** `"Cancel the launch."` yielded no chunk; a 162,034-character full-mode message yielded only an initial chunk ending at character 2,160; a single 200,000-character sentence yielded one oversized chunk.

Vector-search coverage describes the vector corpus scanned; it does not establish that all raw source spans were indexed. [Coverage fields](vector_store.py:251), [tool coverage handling](tools.py:4297)

One optional reranking request explicitly sets `truncation: True`, permitting provider-side cuts. [Rerank payload](embedding_provider.py:1258)

**Fix:** persist source-span indexing coverage; index short substantive messages; split oversized sentences with exact offsets. Expose intentional omissions to retrieval callers. Disable implicit provider truncation and handle declared capacity explicitly. Test short negation, middle/tail decisions, punctuation-free input, and oversized rerank requests. **Effort M; value high.**

**14. Medium–high: completion and omission checks do not cover all auxiliary/evidence paths.**

**Reachability:** pre-compaction extraction is opt-in; expansion synthesis and evidence compilation are tool-driven.

The extraction call uses a 2,000-token generation limit and reads content without checking completion status. Expansion synthesis has a separate content-only response path. Fixing only `_call_llm_for_summary` under B1 would leave both uncovered. [Extraction call](extraction.py:69), [expansion synthesis](tools.py:1729)

Evidence compilation slices references before complete validation/deduplication and builds its baseline from the reduced selection. **Probe:** 79 supplied exact references became 40 selector references without an omitted-reference manifest. Assertion extraction also cuts source quotes to 300 characters without a quote-elision indicator. [Reference normalization](evidence_compiler.py:340), [selector input](evidence_compiler.py:1044), [quote slicing](assertion_extraction.py:184)

**Fix:** use one completion-aware auxiliary-call interface. Track received, validated, included, and omitted references; deduplicate before applying budgets. Every bounded quote needs an exact source/span and cut indicator. Add completion-limit tests for each auxiliary caller and over-budget evidence requests. **Effort M; value high.**

**15. Medium–high: assertion extraction turns unknown observation time into a known observation time.**

**Reachability:** opt-in assertion extraction, particularly legacy or late-imported rows.

`SourceSnapshot` falls back from `observed_at` to the row’s ingestion timestamp. The extractor then labels that value `observed_at`. The message-store migration explicitly distinguishes ingestion time from unknown observation time. [Fallback](assertion_store.py:325), [relabeling](assertion_extraction.py:211), [original distinction](store.py:425)

**Probe:** a row with `observed_at=None` and an ingestion timestamp reached the extractor with that timestamp presented as observation time. This can give temporal retrieval unjustified certainty.

**Fix:** carry nullable observation time, ingestion time, and time basis separately through extraction and query evaluation. Test unknown observation, late import, and historical/as-of queries. This extends the earlier timestamp work beyond summary headers. **Effort S–M; value high for temporal users.**

**16. Medium: summarization-failure cooldown survives an unrelated session reset.**

**Reachability:** default after a failure, when the engine instance is reused across a reset/rebind.

The cooldown deadline is stored on the engine. Session-scoped reset does not clear or re-scope it; the explicit force path is what clears it. **Probe:** recording a failure, then invoking session-scoped reset, left compression blocked. [Cooldown](host_cooldown.py:65), [reset](reset_state.py:14), [force clear](host_cooldown.py:123)

**Weighted-curve assessment**

**W1. The fresh-tail cap has a behavioral discontinuity. — Must fix; S–M / very high.**

With the same synthetic 500-message input and counter:

| Context window | Resolved count preference | Resolved token cap | Actual protected messages |
|---:|---:|---:|---:|
| 262,144 | 32 | 0: disabled | 32 |
| 262,154 | 32 | 1 | 1 |
| 270,000 | 36 | 431 | 4 |
| 1,000,000 | 400 | 150,000 | 400 |

The arithmetic interpolation is smooth before rounding; the meaning of zero is not. A tiny positive cap enables a restrictive suffix selector that previously was disabled. [Curve](window_scaling.py:73), [selector](fresh_tail.py:61)

Interpolate an actual protection allowance or gradual reduction policy rather than an “off” sentinel. Add tests immediately above the low anchor, with both ordinary messages and large tool groups.

**W2. The drain-stop interpolation uses a moving low anchor. — M / high.**

The resolver first curves `context_threshold`, then uses that already-curved value as the drain stop’s low anchor. With defaults:

`drain(t) = (1−t)(0.35+0.45t) + 0.30t = 0.35+0.40t−0.45t²`

At the midpoint it is **0.4375**, rather than **0.325** from fixed 0.35→0.30 anchors. It initially rises before falling. This is implemented deliberately, but conflicts with the stipulated fixed-anchor interpretation. [Resolution order](window_scaling.py:199), [sentinel interpolation](window_scaling.py:130)

Resolve the low anchor at the low window, including explicitly defined override semantics. Test quarter, midpoint, and three-quarter values.

**W3. Leaf token limits are non-monotonic, and the main model’s window is not the summarizer’s capacity. — M–L / high.**

The implementation interpolates fractions and multiplies both endpoints by the *current* window. Resolved leaf limits include **262,144** at 256k, **345,471** at 524,288, and **40,000** at 1M. Thus intermediate windows can produce larger summarizer requests than either endpoint. [Anchors](window_scaling.py:63), [fraction conversion](window_scaling.py:126)

Forced overflow bypasses even that chunk bound and selects the backlog. Rescue exists—it should not be overlooked—but it allows only three attempts, cannot subdivide one message, and has the group-breaking fallback described above. [Overflow selection](compaction.py:874), [rescue](engine.py:1685)

Separate preferred leaf size from the operator-selected summarizer’s declared input capacity. Oversized sources need recoverable span subdivision. Preserve canonical 256k DAG grouping by subdividing internal summarizer work where possible, rather than silently changing published provenance groups.

**W4. Token accounting can substantially undercount accepted message shapes. — S–M / high; applies at every window.**

Tool arguments passed as a dictionary reach `len(dict)//4 + 1`, which measures keys rather than serialized content. The message counter also projects only content and function name/arguments, omitting other potentially rendered fields. [Fallback](tokens.py:114), [accepted dictionary arguments](tokens.py:157), [message projection](tokens.py:169)

**Probe under the same fallback counter:** a large one-key argument dictionary contributed to a nine-token message estimate; JSON serialization produced a 12,512-token estimate. These are estimator results, not claims about a particular provider tokenizer.

Normalize accepted structures before counting and count the actual rendered request through a host-provided accounting interface where available. Keep a documented conservative fallback. Test dictionary/string equivalence and host-specific rendered fields.

**W5. Some consumers bypass the curve; other preferences have no declared anchors. — M / medium–high.**

Concrete omissions include:

| Area | Remaining behavior |
|---|---|
| Temporal summarization | Uses raw configuration timeout and L2 ratio, bypassing the resolved 60→200 seconds and 0.5→0.8 values. [Consumer](rollup_builder.py:247), [resolved-setting mechanism](window_scaled_mixin.py:63) |
| Summary sizing and sweep work | Ratios, minima/maxima, and pass count remain fixed configuration values. [Defaults](config.py:828) |
| Adaptive retrieval | Fixed rounds, candidate counts, context budgets, and quote sizes. [Defaults](adaptive_retrieval.py:34) |
| Semantic indexing | Fixed chunk target, short-message cutoff, per-message cutoff, and error-window count. [Defaults](chunking.py:27) |
| SQLite operation | Fixed busy timeout, checkpoint, journal-size, and mmap preferences. [Bootstrap](db_bootstrap.py:130) |

A constant can legitimately have equal endpoints. These values need an explicit inventory and justification, not indiscriminate multiplication by window size. Provider input limits and SQLite structural limits are capabilities, not preferences to increase. Provenance-ledger eviction needs durable storage, not merely a larger curve.

**W6. Exact 256k equivalence is narrower than the contract claims. — M / high.**

Ordinary low-anchor leaf scheduling and count-based condensation retain the upstream branches. However, the fork’s below-threshold cleanup path can avoid a leaf pass after ingest changes replay content, including configured filtering/externalization cases. This deviation is already admitted in the design document; it is not a newly discovered implementation secret. [Cleanup decision](compaction.py:218), [replay-change triggers](compaction.py:242), [documented deviation](docs/fork-design.md:164)

Therefore, the fixture establishing equal DAG shape does not establish equality across supported configurations. The low-anchor test matrix needs cleanup, rescue, overflow, ignored-message, and externalization cases. Under the stated doctrine, preserve low-anchor publication scheduling unless the contract explicitly changes.

**Coverage: checks that did not produce an additional defect**

These are narrow positive findings, not blanket certifications of their modules.

- **Ordinary tool-group boundaries:** the normal fresh-tail and leaf selectors preserve contiguous call/result groups; the defect is in rescue and subsequent repair. [Fresh tail](fresh_tail.py:29), [leaf alignment](compaction.py:466)
- **Ordinary content paging:** expansion reports offsets, truncation, and continuation, and guarantees progress even with a tiny budget. [Pager](tools.py:1079)
- **Externalization failure:** failure retains inline content rather than publishing an unusable replacement reference. [Failure path](ingest_protection.py:1104)
- **Payload publication:** the durable file-writing path flushes and syncs payload data; the missing piece identified here is backup coverage. [Writer](externalize.py:206)
- **Transcript GC placeholder recognition:** the fast path requires a whole recognized placeholder, avoiding deletion merely because ordinary text quotes a reference; existing B21 still applies elsewhere in this path. [Recognition](engine.py:5185)
- **Lifecycle advancement:** SQL maximums and session checks prevent the examined stale update from moving the frontier backward. [Advance](lifecycle_state.py:848)
- **Empty lifecycle-state GC:** it rechecks emptiness transactionally instead of treating absent cached state as proof that raw history is disposable. [GC](lifecycle_state.py:695)
- **Engine cloning and registry:** cloning constructs independent runtime objects; registry entries use weak references and locking. I found no SQLite deep-copy or strong-reference retention defect there. [Clone](engine.py:633), [registry](engine_registry.py:96)
- **Host signature compatibility:** Hermes filters unsupported compression keywords, so the missing `memory_context` parameter does not itself cause a signature crash. Host filtering (Hermes Agent host internals; path elided)
- **Plugin tool registration:** compatibility handling avoids registering duplicate LCM routes when the host cannot supply the expected message context. [Registration](__init__.py:497)
- **Token-cache eviction:** oversized strings bypass caching and are counted; eviction does not truncate source content, and encoder-generation keys invalidate stale counts. [Cache](tokens.py:126)
- **Schema/FTS maintenance:** the examined external-content triggers track inserts, updates, and deletes; rebuilding derives the index from source tables rather than pruning raw rows. Existing optional-FTS startup work remains necessary. [Triggers](store.py:294), [rebuild](db_bootstrap.py:3038)
- **Temporal rollup capacity:** the 4,096-item frontier bound raises an error rather than silently returning a partial rollup; it remains a scalability limit. [Bound](rollup_builder.py:124)
