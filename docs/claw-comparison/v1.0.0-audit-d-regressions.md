**The fork has three substantial regressions:**

- **A failed condensation can leave a committed leaf behind, return the original prompt, then publish an empty-provenance leaf on retry.** I reproduced this against both implementations.
- **The 1M lookahead drops host routing context, cancellation protection and the host deadline.** Its unbounded wait can also keep the new compaction lock occupied after the host abandons the attempt.
- **The scheduling contract is not satisfied at either end:** 256k can produce different DAGs from upstream, while the default 1M path creates leaves much faster than its condensation loop removes them.

The proposed condensation-input cap would introduce another direct conflict with upstream’s four-child grouping unless its acceptance criterion changes.

**1. High — ordinary condensation failure now breaks publication/retry consistency**

**Upstream guarantee.** Exhausting the summarizer routes normally produced L3 output, allowing condensation to finish and the newly assembled prompt to be returned. This did not make every database operation atomic, but it prevented ordinary summarizer unavailability from taking the exception path after successful leaf publication. [U escalation.py:671](<upstream checkout>/escalation.py:671), [U compaction.py:945](<upstream checkout>/compaction.py:945)

**Fork behavior.** B commits the leaf, separately commits its sidecar, and advances its source cursor before calling non-sweep condensation. If condensation raises `SummaryUnavailableError`, the outer wrapper returns the original input list. Source reconciliation subsequently excludes rows through the advanced cursor, while leaf publication accepts an empty source list and resets the runtime cursor to zero. [B compaction.py:999](compaction.py:999), [B compaction.py:1181](compaction.py:1181), [B host_cooldown.py:164](host_cooldown.py:164), [B reconcile.py:955](reconcile.py:955)

**Reproduction.** With three existing d0 nodes and 70 new conversation messages at 262,144:

1. Leaf summarization succeeds, referencing 38 real raw rows.
2. The resulting four-node condensation fails.
3. B returns the original list despite the committed leaf.
4. Retrying that list with a healthy summarizer creates another leaf with `source_ids=[]` and sets the runtime cursor to `0`.

U’s fallback completes the corresponding condensation and returns the changed prompt; the empty-provenance retry does not arise.

**Reachability.** Any window, ordinary non-sweep operation. At deployed 1M, the condensation gate must first open above 200k frontier tokens. The sweep path already catches condensation failure locally and retains its route to assembly; it does **not** have this same exception escape. [B engine.py:5684](engine.py:5684), [B engine.py:5884](engine.py:5884)

**Smallest repair.** Preserve and assemble successful leaf progress when subsequent condensation fails; reject a leaf whose expected source mapping is missing. Then make node, metadata and frontier publication one validated, idempotent transition. Merely adding a transaction around each leaf does not fix returning an obsolete prompt after a later phase fails.

The sidecar also adds a new failure point between node publication and frontier publication: its accessor commits independently. That is additional exposure, although upstream already had other partial-write windows. [B node_meta.py:88](node_meta.py:88)

**2. High — lookahead bypasses host execution guarantees and can obstruct recovery**

**Upstream guarantee.** U invokes the summarizer directly on the compression owner’s thread. The current host supplies progress, deadline and cancellation scopes there, and its compression executor copies context variables. [U compaction.py:733](<upstream checkout>/compaction.py:733), H conversation_compression.py:2691 (Hermes Agent host internals; path elided), H daemon_pool.py:26 (Hermes Agent host internals; path elided)

**Fork behavior.** `LeafLookahead` introduces a standard executor and carries only the progress hook. Using the fork executor and the host’s actual hook functions, the probe observed:

| State visible to summarizer | Serial | Lookahead |
|---|---|---|
| Runtime context variable | Operator runtime | Missing |
| Host stream deadline | Present | Missing |
| Interrupt protection | Enabled | Disabled |
| Progress hook | Present | Present |

This matters operationally:

- Runtime model/endpoint/auth context is context-local; outside the main thread, the compatibility globals deliberately do not supply a substitute.
- Without the cancellation scope, the host’s protected provider-call helper takes its direct-call branch.
- `take()` calls `future.result()` without a timeout. Closing the executor cannot cancel a running request.
- While that owner remains stuck, B’s new nonblocking lock refuses subsequent `compress()` calls, including forced calls.

**Smallest repair.** Propagate a separate copied context per submission and the supported host deadline/cancellation hooks. Bound waits and outstanding abandoned work, and validate session/generation ownership before publication. Retain serialization of writers; simply removing the lock would exchange an availability defect for concurrent-publication defects. Use workers that do not join indefinitely at process exit. The host already implements that distinction. H daemon_pool.py:38 (Hermes Agent host internals; path elided)

**Availability, prompt cost and storage tradeoffs**

Removing L3 necessarily gives up an upstream availability guarantee. U explicitly relied on its no-cost fallback even when the spend guard had tripped during forced overflow. B instead raises and cools down. A dead summarizer can therefore leave raw context growing through the remaining headroom until the next model request cannot fit. At the deployed threshold, nominal headroom at 1M is 150k. [U compaction.py:411](<upstream checkout>/compaction.py:411), [B escalation.py:640](escalation.py:640), [B host_cooldown.py:77](host_cooldown.py:77)

The ordinary cooldown also suppresses the host’s engine-maintenance hook, so cleanup that does not require summarization can be deferred with the failed summarization. Provider-proven overflow **does** request a cooldown bypass; it would be incorrect to say recovery always waits ten minutes. That bypass cannot create a healthy summarizer or release B’s occupied lock. H turn_context_compaction.py:287 (Hermes Agent host internals; path elided), H turn_context_compaction.py:333 (Hermes Agent host internals; path elided), H turn_overflow.py:154 (Hermes Agent host internals; path elided)

The doctrine-compatible repair is an explicit cannot-fit/deferred outcome, preserved partial progress, and an independent no-LLM cleanup/reassembly route. Restoring deterministic truncation would violate the task’s purpose. No implementation can guarantee continued bounded LLM requests through arbitrary summarizer unavailability while also requiring a complete semantic index of arbitrarily growing input.

Two broader weaknesses matter:

- **The global autouse summarizer supplies healthy, shorter head/tail summaries by default.** That is useful for deterministic engine tests, but supplies exactly the success behavior whose absence now drives the new failure modes. It also bypasses the real host call boundary unless a test explicitly opts out. [B conftest.py:100](tests/conftest.py:100), [B fixture](tests/conftest.py:123)
- **CI still targets only `main`, while the fork branch is `betterlcm`; host integration can skip on import failure.** Keeping upstream’s workflow unchanged lost its practical coverage on the fork branch. [Workflow](.github/workflows/ci.yml:3), [Host-test skip](tests/fork/test_host_integration.py:80)

Upstream merging is materially harder than the “small hook calls” description suggests. The existing-file diff changes `compaction.py` by +271/−34 lines, `engine.py` by +374/−91, and `tools.py` by +199/−35. These changes cross source selection, publication, exception handling, session ownership and assembly.

The first-base-class cooldown wrapper and duplicate `_close_leaf_lookahead` definitions also require MRO-aware review. The smallest maintenance improvement is to document actual phase invariants and require differential low-window and fault-publication checks when merging those areas. Config-field additions and isolated formatting helpers are much more mechanical.
