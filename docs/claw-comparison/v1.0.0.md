# lossless-claw v1.0.0 vs betterlcm — consolidated analysis (2026-09-08)

Four independent code-level audits (`gpt-6-astra`, reasoning xhigh, read-only, one per aspect;
full reports beside this file as `v1.0.0-aspect-*.md`). Every claim about betterlcm listed
here as **verified** was re-checked by hand against the code afterwards. Nothing below is
implemented yet — this is the analysis for discussion. Yardstick: no loss (provenance intact
AND the summary tells what is underneath); 1M works; 256k keeps upstream's DAG.

## A. Defects the fork itself introduced (must fix regardless of claw)

| # | finding | reports | verified |
|---|---|---|---|
| A1 | **`/new` leaves retained nodes whose children cannot be expanded.** Step 5 keeps shallow nodes in the *old* session and carries only depth ≥ retain; `_expand_child_nodes` (`tools.py:1393`) and the evidence walk (`:1497`) skip children whose `session_id` ≠ current. Expanding a carried d2 returns "no children, has_more=false" — a silent dead end in the index. `session_scope="all"` does not help (`_get_session_node`). Externalized refs of cross-session rows are also declared un-expandable (`tools.py:5477`). | 2, 4 | yes |
| A2 | **Rotate advances the frontier before writing its marker node.** A failed marker write only logs; rotate still returns `ok=true`; the next bootstrap skips those raw rows with no marker; repeating rotate is a no-op (frontier already ahead). | 2 | yes (own code order) |
| A3 | **Focus guidance contradicts the index contract.** Upstream text left in place: "Reduce resolved topics to one-liners or drop." (`escalation.py:460`, `:510`) — licenses exactly the omission the fork forbids. | 3 | yes |
| A4 | **Coverage doctor certifies on zero evidence.** `fraction = 1.0 if no entities` (`coverage_doctor.py:73`); a node pointing at a nonexistent child scores `pass`. Structural failure and "no evidence" need their own states. | 2 | yes |
| A5 | **Operator docs/skill still give upstream's fixed advice** ("default 0.35 → ~350k at 1M", `docs/operator-guide.md:518`, table `:189`; the skill calls that guide "the complete current source"). An operator following it overrides the curve the fork exists for. | 4 | yes |
| A6 | **CI never runs for the fork branch** (`.github/workflows/ci.yml`: `branches: [main]`; the fork lives on `betterlcm`), and the host-integration test *skips* when the host import fails instead of failing. | 4 | yes |

## B. Claw is genuinely better — port candidates (value / effort)

| # | finding | reports | verified | value / effort |
|---|---|---|---|---|
| B1 | **Provider-truncated summaries are accepted.** `_call_llm_for_summary` ignores `finish_reason`; the host exposes it. A cut-off summary is short, so it passes the "shorter than source" check — losing the tail topics and the index block. Claw detects `length`/`incomplete` and retries with more output room (its *eventual* fallback is not to be copied). | 1, 3 | yes | very high / S |
| B2 | **Publication is not atomic.** Node (`add_node` commits) → sidecar row (separate commit) → frontier (third connection). | B3 | **Reasoning-tag sanitiser removes literal examples and misses trailing reasoning.** `User asked whether <think>foo</think> is supported.` loses the example; a trailing standalone `<think>` / "Thinking Process:" section after visible text is kept. ## C. Checked and rejected (all four agents, reasons in the aspect reports)
Claw's fixed 2400/2000 targets and fixed cache sizes (no 1M policy; keep the curve); its
deterministic fallback and hard output caps; its "drop detail/references" deep prompts;
shallowest-first condensation; previous-summary delta compression and continuity text;
`synchronous=NORMAL`; its whole-message expansion cutoff; its unpaged describe dump; regex and
CJK query rewriting as default upgrades; OpenClaw-specific delegation/grants, tool factories,
model-policy plumbing; its in-process transaction mutex as a cross-process solution; its
live re-read of tool output from the filesystem; its call-count guard (we have one); its
70 %-pass drilldown scorer's verdict.

## D. Suggested order for discussion
1. A1, A2, B1, B2 — correctness of the no-loss promise (A1/A2 are ours; B1/B2 close the two
   remaining ways an index can silently lie: a cut-off summary, a half-published node).
2. B9, B10, B11, A3, A4, A5, A6, B21, B22 — small, high-value, mostly tool/prompt/doc contracts.
3. B3, B4, B5, B6, B7, B8, B14 — engine/summariser quality items, each self-contained.
4. B12, B16, B19, B20, B23 — operability and I/O at scale.
5. B13, B15, B17, B18 — the large ones; B13 is the single biggest 1M win.
