### command.py

Responsible for slash-command dispatch, operator reports, maintenance workflows, preset previews, and embedding/assertion/rollup maintenance. [File](/home/agent/projects/agentimprovement/betterlcm/command.py:1)

**C01 — Cleanup does not preserve incoming provenance from retained sessions.**

Candidate selection uses session-pattern matches, and deletion removes all messages and nodes belonging to those sessions. Neither stage checks whether a retained node elsewhere references a candidate message or node. `B/command.py:613–666,1899–1927`; `B/dag.py:296–335`.

**Trigger:** cleanup enabled, with a pattern-matched historical session that supplies sources to retained history. Carry-over makes cross-session references relevant; retaining depth-2-and-above history is the default. `B/config.py:762–766`.

**Probe:** the real deletion function removed old-session message `1` and child node `1`, leaving current-session parent node `2` with `source_ids=[1]`.

**Consequence:** the live DAG loses a working provenance chain. The backup may retain the bytes, but the surviving node contains no relocation marker connecting its broken source reference to that backup.

A is not a safe implementation to copy wholesale: its cleaner explicitly deletes both incoming message edges and parent edges referencing deleted candidates. That prevents some dangling SQL relationships by removing provenance itself, which also fails this doctrine. `A/src/plugin/lcm-doctor-cleaners.ts:547–568`.

**C02 — The “atomic” cleanup transaction uses a shared connection without its write lock.**

Cleanup directly executes `BEGIN`, deletes, and commits through `engine._store.connection`. The store documents this exposed connection as read-only for callers; its own append operation takes `_write_lock` and commits that same connection. Cleanup does not participate in that lock. Backup flushing also commits the connection. `B/command.py:1876,1892–1988`; `B/store.py:474–498,1710–1729`; `B/maintenance.py:56–76`.

**Trigger:** concurrent ingestion or maintenance sharing this engine/store connection. This is a concurrency-dependent failure, not a demonstrated failure of serial cleanup.

**Probe:** a later node-delete trigger raised an SQLite error. Without interleaving, the raw deletion rolled back. With an interleaved connection commit after raw deletion, the same failure left the raw row deleted and the nodes present.

**Consequence:** `cleanup apply rolled back` can be false, and the database can retain a partially deleted graph. `B/command.py:2040–2048`.

**C03 — Cleanup protects one bound session, not every live writer or a fixed backup population.**

Both scan and deletion protect only the invoking engine’s `_session_id`. The candidate scan occurs before the backup, and deletion subsequently selects **all current rows** in the candidate sessions; it is not restricted to rows present in the backup. `B/command.py:641–648,1881–1883,1899–1911,2008–2039`.

**Trigger:** another live clone/process uses the same database and a candidate session—for example, with an older/different filtering configuration—and writes between backup and deletion. Defaults alone do not establish this condition.

**Consequence:** another live session can be deleted; newly inserted rows can be deleted without ever having entered the safety snapshot. Protecting the current caller is insufficient to justify the “safe candidates” description.

**C04 — Several operator-output cuts lack a complete recovery route.**

Three independently reachable cuts share this defect:

- Cleanup displays only 20 candidate sessions, but apply deletes the entire candidate set. The omitted count is disclosed; their identities and a pagination/export route are not. `B/command.py:1807–1819,2037–2039`.
- Every rollup response passes through a fixed 20,000-character slicer. Its marker gives a limit and reason but no continuation, full report, or identification of the cut records. This cap also remains fixed at 1M. `B/command.py:391,412–421,2554–2561`.
- Assertion rebuild prints only five failure records. It reports an omitted count but provides no way to retrieve the omitted source IDs and error details from that report. `B/command.py:2676–2679`.

**Trigger:** respectively, more than 20 cleanup candidates, a rollup response exceeding 20,000 characters, or more than five assertion failures; relevant optional features must be enabled.

**Consequence:** these are marked *as cuts*, but not with what was cut and how to recover it. The cleanup case additionally asks the operator to review a destructive population that the command cannot fully display.

**C05 — Doctor/repair status can present incomplete checks as healthy.**

An FTS integrity result of `unchecked` becomes `needs_repair=False` and `ok=True`; the presenter prints `status: ok`. Apply also prints `status: ok` when the repair helper returns `degraded=True`. Separately, a cleanup-candidate scan error is appended to ordinary doctor observations without affecting issues or recommended actions, so an otherwise healthy report can still end with `status: ok`. `B/command.py:919–937,955–970,1008–1020,1503–1504,1700–1705`.

These helper outcomes are real: read-only, busy, and other non-corruption failures produce `unchecked`; low disk can remove FTS artifacts and return degraded operation. `B/db_bootstrap.py:2862–2878,3040–3053`.

**Trigger:** doctor/repair under those database conditions. Probes confirmed both the unchecked and degraded success presentations.

**Consequence:** detail lines sometimes disclose the limitation, but the headline health result does not. An unavailable integrity check is not evidence of intact search coverage.

**C06 — Backup output omits the external-file dependency needed for recovery.**

The command reports a successful backup path and size; the helper copies SQLite only. The response contains no payload manifest, excluded-file inventory, or instruction identifying the additional files required to restore exact sources. `B/command.py:2173–2190`; `B/maintenance.py:79–115`.

**Trigger:** any stored externalized payload. This includes the documented default storage guard for inline media/base64, even with generic large-output externalization disabled. `B/ingest_protection.py:1329–1340,1403–1406`; `B/README.md:680–688`.

**Consequence:** restoring or relocating only the advertised artifact cannot recover those raw payloads. The README correctly calls this a SQLite backup and acknowledges the exclusion; the defect is the missing operational dependency disclosure, not a claim that SQLite’s backup API should copy arbitrary files.

**C07 — Backfill completion accounting converts unreadable state into zero.**

Both remaining-count helpers catch SQLite failures and substitute an arithmetic estimate plus zero in-flight/uncertain counts. Inner `OperationalError` handlers also zero those counts indiscriminately. Final status ignores outstanding claimed work and can report `complete` based solely on selected-row completion. `B/command.py:4273–4300,4489–4520,4994–5016`.

**Trigger:** embedding backfill followed by a count/read failure, or retained claimed work outside the bounded predecessor-maintenance batch. Predecessor maintenance handles only 256 rows per state per invocation. `B/command.py:3181–3228`.

**Probe:** an unreadable count path returned `(0,0,0)` when the arithmetic fallback reached zero; the status function accepted the resulting state as complete.

**Consequence:** unresolved work and uncertain remote acceptance can disappear from the report, suppressing the recovery instructions that depend on a nonzero uncertain count. `B/command.py:3677–3684`.

**C08 — Backfill dry-run reports hide durable in-flight and uncertain work.**

Ordinary discovery deliberately excludes every in-flight state. Both dry-run presenters then use report defaults of `in_flight=0` and `uncertain=0`, without querying those populations. `B/command.py:2856–2907,3642–3643,3866–3889,4595–4646`.

**Trigger:** embeddings configured with durable claimed/dispatched/uncertain rows.

**Probe:** one real uncertain summary row produced ordinary pending count `0`, authorized-retry count `1`, and a dry-run report showing pending, remaining, in-flight, and uncertain all zero.

**Consequence:** the natural inspection command hides precisely the work requiring operator intervention. Also, `--retry-uncertain` explicitly requires `--apply`, so there is no corresponding dry-run inspection route through that option. `B/command.py:3612–3613`.

**C09 — Permanently over-cap summaries can repeatedly occupy the discovery limit.**

Discovery chooses newest eligible summaries before provider embeddability is known. Provider-cap skips are reported but their claims are cleared, making the same rows eligible again. `B/command.py:2897–2906,4136–4155,3457–3481`.

**Trigger:** a configured embedding provider rejects sufficiently large summaries, with at least `--limit` such rows ahead of older embeddable rows.

**Consequence:** repeatedly running the documented bounded backfill need not advance to older history. Overshooting a summary target is allowed by this fork, so oversized summaries cannot simply be treated as impossible. Raw sources remain stored, but semantic indexing can remain indefinitely incomplete.

**C10 — Unrecoverable uncertain chunks consume the retry limit before validation.**

Uncertain chunk IDs are ordered and limited first. Missing messages or chunks no longer produced by the policy are then skipped, and those durable uncertain records remain eligible for the next identical selection. `B/command.py:4411–4486`.

**Trigger:** chunk backfill with `--apply --retry-uncertain`, where early uncertain IDs have missing/changed sources.

**Probe:** with an orphan first and a valid chunk second, `limit=1` repeatedly selected no usable documents; `limit=2` reached the valid chunk.

**Consequence:** bad early entries can block recovery of valid later entries. Increasing the limit is a workaround, not a progressing bounded retry mechanism.

**C11 — Chunk discovery ignores the operation budget while scanning and rechunking the entire archive.**

`_chunk_pending_rows()` loads embedded/in-flight ID sets and scans every message, rechunking each one to calculate the total even after the requested documents have been selected. Apply checks its wall-clock budget only afterward; remaining-count calculation scans again. `B/command.py:4369–4408,4723–4749,4489–4495`.

**Trigger:** chunk dry-run or apply over a large archive, including `--limit 1` with a finite backfill budget.

**Consequence:** nominally bounded maintenance can spend unbounded archive-proportional time before dispatch and again during reporting. This is a throughput/operability defect relevant to 1M use, not loss of raw content.

**C12 — Some pre-dispatch provider errors lose their reason.**

In both backfill loops, exception handling calculates an error reason but records failed rows only if `latest_request_id` exists. A non-special-cased exception before the dispatch callback can therefore clear claims and continue without retaining that reason or setting the overall error. `B/command.py:4161–4216,4910–4954`.

**Trigger:** an embedding provider raises during local preparation or validation before announcing a request.

**Consequence:** the report can say partial with zero failures and no explanation of why nothing was embedded. The exception is not necessarily misreported as complete, but the actionable failure evidence is swallowed.

**Checks that turned out fine:** serial cleanup does roll back; backup failure prevents cleanup; rotate preflight refuses/no-ops before replacing the rolling backup in the serial case; retention’s apparent 20-session display cap is not presently reachable because its store query is scoped to one session; lifecycle-only cleanup rechecks emptiness transactionally. `B/command.py:1986–1988,2027–2035,827–861`; `B/store.py:971–1016`; `B/lifecycle_state.py:695–810`.

### config.py

Responsible for configuration defaults, environment parsing, selected Hermes-YAML inheritance, and configuration-source diagnostics. [File](/home/agent/projects/agentimprovement/betterlcm/config.py:1)

**F01 — The normal loader’s default-source label disables the threshold curve.**

`from_env()` records an unset threshold’s source as `"default"`. The engine preserves that label, while the mixin applies the curve only for `"manual_or_default"`. `B/config.py:121–133,865–871`; `B/engine.py:871–894`; `B/window_scaled_mixin.py:97–121`.

**Trigger:** normal plugin registration, no explicit LCM/host threshold, and no route-specific auto-raise. Registration uses `from_env()`. `B/__init__.py:385–396`.

**Probe:** at 1M, direct configuration construction yielded threshold `0.8` and trigger `800000`; environment loading yielded `0.35` and `350000`, despite the resolver reporting `0.8`.

**Consequence:** the documented default 1M behavior is wrong. At 262,144, both paths use `0.35`, so that endpoint does not expose this bug. An explicit threshold masks it. `B/window_scaling.py:59,199–208`.

**F02 — Invalid environment overrides can freeze upstream defaults instead of restoring the curve.**

Parsing falls back after an invalid value, but the resolver separately treats mere environment-variable presence as an explicit override. Thus a rejected override can remain authoritative indirectly. `B/config.py:70–87,107–133,901–906`; `B/window_scaling.py:160–182`.

**Trigger:** an invalid environment value for a curved upstream field.

**Probe:** at 1M, invalid fresh-tail and expansion-timeout overrides resolved to `32` and `120000`, identified as environment values, instead of `400` and `200000`.

**Consequence:** a typo silently disables large-window tuning; a warning saying the value was “ignored” can itself be misleading. Defaults without malformed overrides are unaffected by this particular defect.

**F03 — Numeric/domain validation is incomplete, and many invalid values are silent.**

Float conversion accepts `nan` and `inf`; scalar parsing generally checks conversion rather than finiteness or field domains. Most scalar fallback paths do not record warnings. String enums are also accepted without centralized validation; an invalid pre-answer mode later becomes `off`. `B/config.py:70–103,121–133,901–906,917–922`; `B/__init__.py:156–162`.

**Trigger:** malformed, nonfinite, or inappropriate operator values at any window.

**Probe:** nonfinite threshold/chunk-fraction values produced no configuration warning; resolving an infinite chunk fraction raised `OverflowError`. A nonfinite threshold reaches integer trigger construction. `B/engine.py:975–977`.

**Consequence:** a configuration that appears accepted can prevent engine operation or silently disable intended behavior. A has reusable finite-number validation, though that alone is not complete domain validation. `A/src/db/config.ts:219–241`.

**F04 — YAML read/parse failures silently erase configuration intent.**

Unreadable files, parser exceptions, and non-mapping YAML roots all become `{}`. An invalid `lcm.context_threshold` also causes the entire threshold lookup to return the default without considering a valid lower-priority host threshold. `B/config.py:157–168,233–250`.

**Trigger:** an existing configuration file is unreadable/malformed, or its LCM threshold is invalid. A genuinely absent optional file is not the defect.

**Probes:** read failure and parser failure returned `{}`. With invalid LCM threshold and valid host threshold `0.85`, lookup returned `(0.35,"default")`.

**Consequence:** operator preferences disappear without a configuration-error state. At large windows this also interacts with F01.

**F05 — Comma splitting can turn one intended exclusion regex into much broader patterns.**

Pattern lists are parsed using unconditional `split(",")`, including message regexes. There is no escaping or structured-list alternative for commas inside regexes. `B/config.py:17–18,940–943`.

**Trigger:** message filtering enabled with a regex containing a comma, and the optional regex engine installed.

**Probe:** `^noise,.*$` became `["^noise", ".*$"]`; the second fragment matches unrelated nonempty messages. The actual filter compiler accepts valid fragments independently, and matching messages are never persisted. `B/message_patterns.py:55–65,95–107`; `B/engine.py:4872–4892`.

**Consequence:** an intended narrow exclusion can discard substantive raw messages.

The isolated interpreter lacked the optional `regex` package, and the real filter correctly disabled itself there with a warning. The parser and resulting regex semantics were verified separately; the destructive condition requires the dependency to be present. `B/message_patterns.py:33–53`.

**F06 — Explicitly supported configurations remain incompatible with strict no-loss operation.**

Message/session exclusions, stateless sessions, and sensitive redaction remain accepted configuration options. Exclusion paths skip persistence; redaction replaces matching source values before durable storage without retaining their originals. `B/config.py:525–579`; `B/engine.py:1621–1626,4874–4892`; `B/ingest_protection.py:767–822,1346–1350`.

**Trigger:** the corresponding opt-in settings or matching session policies. This does not describe ordinary default foreground storage.

**Consequence:** these configurations violate doctrine 1 even when functioning exactly as documented. The README explicitly acknowledges irreversible redaction; this is an existing contract incompatibility, not a newly discovered implementation accident. `B/README.md:519–524`.

**Checks that turned out fine:** summary-model defaults defer to operator/host selection, and the surviving `l3_truncate_tokens` setting does not re-enable deterministic truncation—the escalation function explicitly ignores it and raises on total summarizer failure. `B/config.py:602–605`; `B/escalation.py:629–640`.

### coverage_doctor.py

Responsible for lexical source-to-summary coverage measurement and its doctor verdict. [File](/home/agent/projects/agentimprovement/betterlcm/coverage_doctor.py:1)

**V01 — Missing or unscorable evidence can become a perfect result.**

Missing message rows and child nodes are skipped. Zero extracted entities become fraction `1.0`; a session with no scored entities also receives aggregate `1.0`, and the check can pass. Node-metadata read errors are swallowed and reported as ordinary level-1/default metadata. `B/coverage_doctor.py:68–79,82–121,124–163`.

**Trigger:** dangling sources, missing children, entity-free source text, or metadata-read failure. No optional feature is required beyond invoking coverage.

**Probe:** a node pointing to a nonexistent child produced zero scored nodes, 100% aggregate coverage, and `pass`.

**Consequence:** a provenance failure can receive the strongest apparent coverage result. This reconfirms the earlier empty-source concern rather than treating it as resolved.

**V02 — Condensation coverage does not inspect raw descendants, and externalized content is not hydrated.**

For a parent, source text consists only of immediate children’s summaries. For a leaf, it reads stored content/tool-call fields without resolving externalized bodies. `B/coverage_doctor.py:82–102`.

**Trigger:** condensed nodes, or nodes covering externalized source content.

**Consequence:** details already lost from child summaries disappear from the parent’s denominator; a missing external payload can be scored through its surviving placeholder metadata. The result measures resemblance to an intermediate representation, not preservation of the underlying source index.

This is distinct from V01: all directly requested rows can exist and the wrong evidence population is still being measured.

**V03 — Multiple unmarked sampling limits conceal omissions and miscount failures.**

The implementation:

- extracts entities by category, then keeps only 400;
- cuts concatenated source text at 400,000 characters;
- reads only 200 session nodes by default;
- keeps only 20 below-floor nodes and reports that shortened length as the number below floor.

`B/coverage_doctor.py:32–56,82–102,124–163`.

The session query orders by depth and creation time before limiting, so enough old leaves can exclude later leaves and all higher-depth nodes. The slash command offers no paging/limit option. `B/dag.py:463–482`; `B/command.py:5043–5044`.

**Trigger:** crossing any of those sizes; increasingly relevant to large-window and long-lived sessions.

**Probes:** a bad 201st node was omitted while coverage passed; 25 bad nodes were described as 20; material after character 400,000 disappeared from scoring. A 401-entity source could lose the last entity without lowering the measured fraction.

**Consequence:** an incomplete audit is presented without its scope boundaries or a route through the omitted population. Category-order truncation can also exclude decisions after a large URL/path population.

**V04 — Entity matching credits unrelated strings.**

Matching accepts arbitrary substrings; its five-letter alphabetic-stem fallback applies to every entity, despite the comment describing decision keywords. `B/coverage_doctor.py:59–65`.

**Trigger:** overlapping identifiers, filenames, numbers, or ordinary words.

**Probe:** source identifier `alphaBetaGamma` counted as present in summary text `alphabet`.

**Consequence:** even within the sampled population, reported coverage can exceed actual entity preservation.

**V05 — A keyword-only summary can pass while failing the INDEX doctrine.**

The metric checks entity presence, not the relationships, actions, outcomes, or constraints that explain what happened. Its doctor result nevertheless uses `pass`. `B/coverage_doctor.py:68–79,150–163`.

**Probe:** source text “We decided to retain the archive. We rejected destroying the archive.” scored 100% against summary text consisting only of `decided rejected`.

**Trigger:** any summary retaining the extracted words while losing the account of events.

**Consequence:** this checker cannot establish doctrine 2. The module’s “heuristic, not proof” caveat is correct, but it does not make the observed pass an adequacy test. Fixing missing sources and caps alone will not fix this failure. `B/coverage_doctor.py:1–7`.

### __init__.py

**W01 — Recovery commands are unavailable when engine construction fails.**

The plugin constructs `LCMEngine` before registering the engine, hooks, tools, or slash command. Yet schema-stamp diagnosis is designed to open a refused database independently. `B/__init__.py:385–399,530–543`; `B/command.py:1024–1076`.

**Consequence:** the operator cannot invoke the plugin’s own repair/diagnostic surface precisely when needed. A’s independent read-only database opener demonstrates a useful separation to port without requiring its context engine to initialize. `A/src/cli/database.ts:8–37`.

**W02 — Post-turn persistence bypasses Hermes’s registration ownership ledger.**

Most hooks use `ctx.register_hook`; post-turn ingestion instead appends directly to the manager’s private `_hooks` mapping. `B/__init__.py:429–465,558–606`.

Hermes’s official registration creates a tracked removal handle. Targeted unload disposes those tracked registrations; it does not sweep arbitrary callbacks. `H/hermes_cli/plugins.py:893–915`; `H/hermes_cli/plugins_ledger.py:227–253`.

**Trigger:** targeted plugin disable/unload/reload on the supplied host.

**Consequence:** the old ingest callback survives and retains its captured engine. Reload can accumulate callbacks, and a disabled plugin can continue reacting to turns. Full unload-all has a different reset path; this finding concerns targeted unload.

**W03 — Singleton fallbacks can select the wrong runtime and also defeat command isolation.**

The post-turn hook discards an explicitly supplied non-LCM compressor, then falls back to the captured LCM prototype if registry resolution fails. It binds that prototype to the supplied session and ingests the history. `B/__init__.py:562–599`.

Command routing likewise returns the captured prototype after unresolved or failed task-local session lookup. That prototype is not guaranteed to remain unbound because the post-turn fallback can bind it. `B/__init__.py:313–347`.

**Trigger:** plugin loaded while another engine is serving the turn, unavailable/stale registry binding, or failed command session-context lookup. The supplied host’s post-turn payload does not include a compressor object, making correct registry ownership important. `H/agent/turn_finalizer.py:419–429`.

**Probe:** a turn explicitly marked with a native compressor still bound and ingested through the captured LCM prototype.

**Consequence:** histories and operator actions can be attributed to an unintended runtime. Concurrent fallback turns additionally share a mutable session binding. The registry’s correct refusal is undone by its caller.

**W04 — The optional registered-tool path captures the prototype rather than the active clone.**

Every registered tool handler closes over the bootstrap engine. Forwarding active messages is the only capability checked; no active-engine resolution occurs in the wrapper. `B/__init__.py:32–57,497–505`.

The engine dispatcher consumes `messages` but does not rebind from a forwarded session ID; it dispatches tools with `engine=self`. `B/engine.py:3843–3879`.

**Trigger:** a host advertises `context_engine_tool_handlers_receive_messages=True` and serves per-agent clones. The supplied host uses the safe native fallback instead, so this is a conditional compatibility defect.

**Probe:** a handler called with another session ID and messages still dispatched through the prototype’s existing session.

**Consequence:** recovery searches can use the wrong session, and current-turn ingestion can either be skipped on an unbound prototype or written under its stale binding.

**W05 — Pre-answer baseline construction discards retrieval completeness/error metadata.**

The hook requests a fixed 25-hit recall baseline, then reduces the response to usable hit references/quotes. Response-level errors, coverage limits, and continuation information are discarded. `B/__init__.py:119–153`.

**Trigger:** pre-answer evidence enabled and the hook supplies its own baseline; a bounded, degraded, or error recall result is returned.

**Consequence:** downstream code cannot distinguish an ordinary empty baseline from failed retrieval or identify what the baseline omitted. The fixed selection preference also does not use the window curve.

This does **not** establish that every downstream compiler certifies exhaustive coverage: selective evidence explicitly labels itself partial, and the requirements compiler has separate finite-coverage checks. The defect here is the information discarded at this hook boundary. `B/selective_recall.py:347–349`; `B/requirements_compiler.py:1752–1773,2199–2217`.

**W06 — Pre-answer exceptions disappear from the injected context and can leave a stale success trace.**

The outer exception handler logs a warning and returns only the normal recall policy. It does not replace `_last_preanswer_evidence_trace` with the failed attempt. Selective-compiler exceptions similarly omit a failure result from the eventual trace. `B/__init__.py:239–299`.

**Trigger:** pre-answer evidence enabled and retrieval/compiler execution raises.

**Probe:** a retrieval exception returned only the unchanged policy while `_last_preanswer_evidence_trace` still contained the preceding success.

**Consequence:** neither the current prompt nor the exposed last-attempt trace reliably states that expected evidence work was skipped. Keeping the turn alive is reasonable; making the degradation indistinguishable from ordinary operation is not.

**W07 — Post-hook registration and session-binding failures have only debug-log visibility.**

Failure to register the post-turn hook is caught at debug level, after which the plugin logs that lossless context management is active. Exceptions around rebinding/ingestion are also caught at debug level. `B/__init__.py:588–608`.

**Trigger:** incompatible hook-manager interface, hook registration failure, or `on_session_start()` failing before ingestion.

**Consequence:** a completed short conversation may not reach LCM storage, without a durable pending-ingest record or operator health failure.

This finding is deliberately narrower than “all ingest errors are swallowed”: errors inside the real `engine.ingest()` already call `_record_ingest_failure()`. `B/engine.py:1627–1642`.

**W08 — The pre-answer toolset gate relies on metadata the supplied host does not send.**

The hook treats absent `enabled_toolsets` as enabled. The supplied host’s pre-LLM payload omits that field, although tool-schema injection separately respects the agent’s enabled toolsets. `B/__init__.py:165–175`; `H/agent/turn_context.py:608–629`; `H/agent/agent_init.py:1933–1955`.

**Trigger:** pre-answer evidence enabled while the serving agent/platform excludes the `context_engine` toolset.

**Consequence:** automatic recall/evidence work can still run despite that exclusion, and injected recovery references can name tools absent from the agent’s available surface. Default-off pre-answer evidence avoids this condition.

## D. **Cross-partition notes**

1. **Rotate still separates frontier advancement from marker creation.** The engine commits the lifecycle advance before trying to create the marker, and marker failure can return `None`. The command trusts the engine’s successful result without requiring a marker receipt. This confirms an earlier concern rather than superseding it. Audit/fix belongs principally to engine/lifecycle publication: marker and frontier must publish together, and success must require recoverable provenance. `B/engine.py:6841–6876,6881–6927`; `B/command.py:873–905`.

2. **Rotate-marker source/index quality needs separate treatment.** The marker reads with a one-million-row limit and derives its content hints from only the first and last message heads, 160 characters each. Even a successfully written marker can fail to explain important material in the middle. Require explicit population completeness and a useful index of the rotated span. `B/engine.py:6887–6905`.

3. **Backup filenames and concurrent rolling backups need maintenance-layer repair.** Timestamped backups use second precision, so two backups of the same DB in one second target the same destination. The file helper accepts existing regular files. Rolling backups share a single `.tmp` name and may unlink it before writing. These are distinct from C06’s payload dependency: use uniquely created snapshot files and serialize publication of the rolling slot. Power-loss durability of the rename was not tested. `B/maintenance.py:88–99,134–159`; `B/sqlite_util.py:73–96,155–172`.

4. **Chunk-vector publication lacks source-generation validation.** Command discovery captures text/spans, then publishes after provider work. The vector write validates embedding/lease identity but writes offsets without a raw-content generation/hash check. Meanwhile transcript GC can rewrite the same `store_id`. Audit the race in which GC archives old chunks and a late publish recreates an active vector with obsolete offsets. `B/command.py:4388–4406,4818–4836`; `B/vector_store.py:2367–2410,2453–2490`; `B/store.py:592–630`.

5. **Chunk policy itself contains substantive unmarked exclusions.** “Conversational” skips all turns below 40 tokens; “full” reduces messages over 32,000 tokens to a head and at most three error chunks. Those policies can omit a short decisive answer or the middle of a long source. Raw storage survives, but the chunk-index partition must establish how omitted material and its recovery are disclosed. `B/chunking.py:25–36,177–198,201–229`.

6. **Node-metadata cleanup swallows every `OperationalError`.** Its exception handler assumes the table is absent, but also suppresses lock/read-only and other operational failures. This can let a larger cleanup report success while leaving sidecar state inconsistent. Narrow the exception handling and let genuine failures roll back the owning transaction. `B/node_meta.py:119–130`; `B/dag.py:296–335`.

7. **Do not mistake retained compatibility names for restored truncation.** I verified that the deterministic L3 fallback remains removed; `l3_truncate_tokens` is explicitly ignored. The remaining concerns above arise elsewhere and should not be “fixed” by reinstating that fallback. `B/escalation.py:629–640`.

8. **A supplies patterns to examine, not a no-loss reference implementation.** Its independent read-only diagnostic connection and finite numeric parsing are useful directions for W01/F03. Its cleaner’s removal of incoming provenance edges fails this operator’s stronger doctrine and should not be ported as the C01 solution. `A/src/cli/database.ts:8–37`; `A/src/db/config.ts:219–241`; `A/src/plugin/lcm-doctor-cleaners.ts:547–568,656–677`.
