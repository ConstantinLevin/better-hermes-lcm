Found **15 reproducible regressions in the audited snapshot**, including direct provenance loss and broken recovery paths.

I compared `cfcbb9f~1..f1bb108` with the pre-batch fork, `8c05151`, and upstream `8d1b1e6`. Probes used real functions, in-memory SQLite, and injected failures; I modified no files. During review, another process landed `9161dd6`, fixing the Python 3.14 crash identified below. Citations refer to committed revisions, avoiding ambiguity from concurrent edits.

1. **P1 — Spillover recovery and ingest disagree about the Hermes home, dropping tool-result provenance.**

   Replay recovery now passes `self._hermes_home`, but `protect_message_for_ingest()` still calls recovery without its `hermes_home` argument. With an explicit profile home different from `$HERMES_HOME`, ingest stores the preview, while replay adds recovered-file identity metadata. The identities no longer match.

   **Probe:** With large-output externalization enabled, source mapping changed from `[1, 2, 3]` to `[1, 3]`. A complete compaction fixture with an assistant/tool pair published sources **`[1, 2, 4]`**, advanced the frontier to **4**, removed tool result **3** from the prompt, and reported **`compacted`**.

   **Sources:** After: `f1bb108:reconcile.py:139`, `f1bb108:ingest_protection.py:1388`, `f1bb108:compaction.py:1088`. Before: `8c05151:reconcile.py:139`.

   **Fix:** Pass the same home through every recovery call, especially ingest. Test ingest → replay identity → leaf publication with differing engine and environment homes; the new direct-recovery test misses this integration failure.

2. **P1 — Preserving the bypass receipt deletes the newest request.**

   When the remaining messages are `[first, receipt, newest]`, the trimming loop skips the receipt at index 1 and deletes the newest message at index 2. The receipt takes precedence over the request the agent must answer.

   **Probe:** With `protect_first_n=protect_last_n=1` and a 400-token cap, the previous function retained `LATEST REQUEST`; the new function returned the old first message plus the receipt and discarded that request. The returned context used only 349 tokens.

   **Sources:** After: `f1bb108:bypass.py:375`, `f1bb108:bypass.py:437`. Before: `8c05151:bypass.py:329`, `8c05151:bypass.py:376`.

   **Fix:** Reserve space for the newest request and a compact receipt before trimming older content. Account for subsequent removals in the receipt.

3. **P1 — Truncated index blocks point to a continuation that cannot return the missing text.**

   `_node_index_block_payload()` now cuts at 4,000 characters and directs callers to `lcm_describe(node_id=…)`. That mode returns subtree metadata, without the node’s summary or index block.

   **Probe:** A 12,315-character index became 3,981 characters. Following its exact continuation returned neither the index nor its final topic. Previously the helper returned the complete block.

   **Sources:** After: `f1bb108:tools.py:169`, `f1bb108:tools.py:5483`, `f1bb108:dag.py:1024`. Before: `8c05151:tools.py:163`.

   **Fix:** Implement and test actual index-text pagination before truncating responses. The new test checks the continuation’s node ID but never follows it (`f1bb108:tests/fork/test_node_meta.py:232`).

4. **P1 — Tool-call expansion multiplies the token budget and provides unusable pagination.**

   The new tool-call slice receives a budget, but its tokens are never added to `budget_used`. Every call-only row therefore receives the entire remaining allowance. Pagination considers only message content, and the advertised continuation enters a raw-message mode that does not return tool calls.

   **Probe:** Twenty call-only rows with `max_tokens=50` returned **1,000 tool-call tokens**, twenty truncated calls, and top-level **`has_more: false`**. Following a continuation returned empty content, no tool calls, and another `has_more: false`.

   **Sources:** After: `f1bb108:tools.py:1371`, `f1bb108:tools.py:1421`, `f1bb108:tools.py:5610`. Before: `8c05151:tools.py:1335`, `8c05151:tools.py:1387`.

   **Fix:** Charge actual call tokens against the shared budget and implement a consumed tool-call offset across both expansion modes. Test multiple oversized calls, rather than one small call.

5. **P1 — Frontier recovery mistakes a maximum source ID for complete prefix coverage.**

   The new DAG floor advances over every earlier row, although a message-sourced node can cover a sparse selection. Imported graphs are particularly exposed: the importer accepts mapped source selections without requiring prefix coverage.

   **Probe:** Stored rows `[1,2,3,4,5]`, persisted frontier `0`, and a valid leaf covering `[2,3]` produced frontier **3**. Subsequent source-mapping candidates were `[4,5]`; uncovered row **1** disappeared from consideration. Previously the frontier stayed at 0.

   **Sources:** After: `f1bb108:engine.py:1880`, `f1bb108:dag.py:509`, `f1bb108:reconcile.py:967`. Before: `8c05151:engine.py:1860`. Import path: `f1bb108:scripts/import_lossless_claw.py:916`.

   **Fix:** Advance only over a proven covered prefix, or publish an explicit consumed-frontier receipt transactionally. Extend the recovery test beyond its current “first three rows” fixture.

6. **P1 — The committed daemon pool crashes on Python 3.14. Already fixed during review.**

   The replacement pool calls CPython private worker APIs with the older attributes and signature.

   **Probe on Python 3.14.4:** The pre-batch `LeafLookahead` returned `ok`; `f1bb108` raised **`AttributeError: 'DaemonThreadPoolExecutor' object has no attribute '_initializer'`** on its first submission.

   **Sources:** After: `f1bb108:leaf_pipeline.py:118`. Before: `8c05151:leaf_pipeline.py:100`.

   **Fix/status:** `9161dd6` replaces this implementation. I verified that the same Python 3.14 probe succeeds against that commit.

7. **P2 — The condensation cap breaks structural equivalence at W=262,144.**

   Upstream’s “one pass” means one traversal of all eligible depths. The new cap counts individual groups and stops after the first group at the low anchor.

   **Probe:** With four d0 nodes, three d1 nodes, three d2 nodes, and default cache-friendly condensation disabled:

   - Upstream: merged depths `[0,1,2]`.
   - Pre-batch fork: `[0,1,2]`.
   - New fork: `[0]`.

   **Sources:** After: `f1bb108:window_scaling.py:99`, `f1bb108:engine.py:5859`. Before: `8c05151:engine.py:5702`; upstream: `8d1b1e6:engine.py:5587`.

   **Fix:** Preserve the complete upstream depth traversal at the low anchor; scale additional traversals separately. The new anchor test seeds only d0 nodes, so it cannot detect this difference.

8. **P2 — Timed-out lookahead workers accumulate across retries.**

   A timeout cancels the future, but cancellation cannot stop an already-running function. Closing the pool abandons those workers, and the wrapper releases the compaction lock, allowing another pool to start.

   **Probe:** Three calls through the real `HostCooldownMixin.compress()` wrapper, with two blocked summarizers per call, left **2 → 4 → 6 live workers**, while the compaction lock was released after each timeout. The old first-future wait kept subsequent attempts behind the lock.

   **Sources:** After: `f1bb108:leaf_pipeline.py:254`, `f1bb108:leaf_pipeline.py:271`, `f1bb108:host_cooldown.py:169`. Before: `8c05151:leaf_pipeline.py:166`.

   **Fix:** Bound outstanding workers across attempts and retain ownership of abandoned tasks. Add cooperative cancellation and session fencing; use process isolation if hard termination is required.

9. **P2 — Ordinary brackets in an expansion hint cause generated summaries to be stored as raw conversation.**

   The new trailer recognizer permits no `]` inside the hint. The renderer accepts arbitrary hint text, including normal expressions such as `items[0]`.

   **Probe:** A real assembled summary ending in `[Expand for details: Expand for details about: items[0]]` was recognized as scaffolding before the batch and rejected afterward. Passing it through `_ingest_messages()` stored the generated summary as a raw message.

   **Sources:** After: `f1bb108:engine.py:4476`, renderer: `f1bb108:engine.py:6432`. Before: `8c05151:engine.py:4408`.

   **Fix:** Recognize the renderer’s actual envelope, preferably using trusted generated-message identity. Add round-trip tests with bracketed hints.

10. **P2 — The index-shape gate rejects substantive summaries based on their opening words.**

    `startswith()` over refusal phrases rejects any summary beginning with those phrases, regardless of the information that follows.

    **Probe:** Both examples were accepted before and now exhaust escalation with `SummaryUnavailableError`:

    - “As an AI evaluation framework, Atlas compares timeout recovery and records failed routes. Expand for details about: recovery.”
    - “I cannot reproduce the timeout after raising the limit to 120 seconds; the remaining issue is DNS. Expand for details about: timeout and DNS.”

    **Sources:** After: `f1bb108:escalation.py:629`, `f1bb108:escalation.py:655`, `f1bb108:escalation.py:704`. Before: `8c05151:escalation.py:596`.

    **Fix:** Restrict deterministic rejection to complete, bare acknowledgements/refusals. Do not infer refusal from an unrestricted prefix.

11. **P2 — Condensation without leaf work spends a model call but returns the old summary prefix as a no-op.**

    The new branch publishes condensation, then follows the old no-leaf return path. Unless scaffolding was separately dropped, it never assembles the newly published frontier.

    **Probe:** Four existing summaries and an entirely fresh input produced one condensation call and a new d1 node, but returned the original input unchanged, without the new parent, with **`status="noop"`** and **`compression_count=0`**. Previously this path made no model call.

    **Sources:** After: `f1bb108:compaction.py:1203`, `f1bb108:compaction.py:1244`, `f1bb108:compaction.py:1264`. Before: `8c05151:compaction.py:1100`, `8c05151:compaction.py:1134`.

    **Fix:** Track whether condensation published anything and reassemble/account for that result. The added test checks DAG depth, not the returned prompt.

12. **P2 — Successful ordered search pages are reported as work-cap failures.**

    The new completeness calculation equates a full fetched page with an incomplete operation. An ordered page can already contain the correct requested results without exhausting every matching row.

    **Probe:** `lcm_grep(query="漢字", sort="recency", limit=1)` over 1,000 ordered matches returned the correct newest hit but reported **`complete: false`**, **200 scanned rows**, and a **500-row candidate cap**, with instructions to narrow or recover manually. No cap had been reached.

    **Sources:** After: `f1bb108:dag.py:889`, `f1bb108:tools.py:2709`, `f1bb108:tools.py:2973`. Before: `8c05151:dag.py:773`, `8c05151:tools.py:2895`.

    **Fix:** Distinguish successful top-k completion, additional available results, and an actually exhausted work budget.

13. **P2 — Every leaf publication now performs quadratic source-membership work.**

    `set(source_store_ids)` is rebuilt inside the comprehension for every published source ID—even when there are no excluded replies.

    **Probe of the committed expression:** 5,000 sources took approximately **0.36 s**; 10,000 took **1.24 s**; 20,000 took **5.61 s**, all producing an empty exclusion list. This runs while compaction is held and outside any interruptible model call.

    **Sources:** After: `f1bb108:compaction.py:1073`. Before: `8c05151:compaction.py:1014`, which proceeds directly to time bounds.

    **Fix:** Construct the source set once and reuse it for both the union and membership checks.

14. **P2 — Snippet generation adds a substantial per-hit search cost.**

    The replacement runs an ignore-case regex over the original text for each term and additionally lowercases the entire content for each regex miss. Previously it lowercased once and used substring searches.

    **Probe:** On 2.25 million ASCII characters, six absent terms and a final matching term, median helper time increased from **8.16 ms to 120.73 ms**, approximately **15×**. This is helper timing, not an end-to-end search benchmark; the helper executes for each LIKE-search hit.

    **Sources:** After: `f1bb108:search_query.py:439`, `f1bb108:search_query.py:444`; caller: `f1bb108:store.py:1563`. Before: `8c05151:search_query.py:384`.

    **Fix:** Keep a fast ASCII path. For Unicode, calculate normalization and offset mapping once rather than rescanning and reallocating per term.

15. **P2 — Consistent explicit and relative dates are now marked ambiguous.**

    The new guard treats any coexistence as conflict, even when both expressions resolve to the same day.

    **Probe:** With session date `2026-09-08`, “Today (2026-09-08) we shipped the fix” previously returned that explicit event date. It now returns **`event_date=None`**, **`event_time_source="unknown"`**, and `ambiguous_explicit_and_relative_dates`.

    **Sources:** After: `f1bb108:occurrence_time.py:110`. Before: `8c05151:occurrence_time.py:109`.

    **Fix:** Resolve the supported expressions against the supplied anchor and retain the date when they agree; report ambiguity when they conflict.
