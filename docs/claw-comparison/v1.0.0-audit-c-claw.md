**Two substantial omissions survive this audit: preserving complete host message records, and making host-to-LCM ingestion durably identifiable and replayable.** Both strengthen the foundation beneath the DAG. Neither is supplied by the planned summary-publication transaction.

The first is a demonstrated storage omission. The second is a missing guarantee: B cannot reliably establish event identity from its persisted representation. I found no third unplanned compaction or retrieval architecture that met your bar.

I inspected A at `988dee85592b`, B at `f38ed61f2746`, and Hermes at `6178e9f4eed8`. No files were modified. The probes below used synthetic data and in-memory storage; no provider calls or full test suites were run.

**C1 — Preserve the original structured message separately from its searchable and replayable projections.**

**What A implements.** A persists a plain message row plus ordered `message_parts`. Those parts retain raw content blocks, tool metadata, originating-model metadata, and top-level `reasoning_content`. Ingestion actually writes those parts; they are not merely a proposed schema. Assembly reconstructs supported structured forms from them. See [A message-part construction]( lossless-claw v1.0.0 src/message-content.ts:642), [raw-block preservation](lossless-claw v1.0.0 src/message-content.ts:745), [ingestion](lossless-claw v1.0.0 src/engine.ts:3795), and [reconstruction](lossless-claw v1.0.0 src/assembler.ts:761).

**What B loses.** B’s storage boundary projects a message onto role, normalized content, tool fields, and selected timestamps. It has no column or sidecar for the remaining message envelope. Recovery reconstructs that same reduced representation. See [B batch insertion](store.py:521) and [stored-message reconstruction](store.py:1695).

These are real Hermes fields, not hypothetical future extensions. Hermes explicitly persists `reasoning`, `reasoning_content`, `reasoning_details`, and structured reasoning/message items; it also records `finish_reason`. See Hermes field definitions (Hermes Agent host internals; path elided) and message-row construction (Hermes Agent host internals; path elided).

| Synthetic input | Result |
|---|---|
| B assistant message with `reasoning_content`, `reasoning_details`, `finish_reason`, `_row_id` | All four absent from the retrieved row |
| B structured text/image `content` | JSON values survived exactly; `to_openai_msg()` returned a string |
| A assistant message with `reasoning_content` | Preserved in part metadata |

**The suspected blanket loss of structured `content` was wrong:** B serializes it as JSON. The demonstrated omission is principally outside `content`; storing structured content and reconstructing its original type are also distinct capabilities. [B normalization](message_content.py:30)

This does **not** establish that Hermes itself has lost those fields. It establishes that B’s linked raw-message store cannot reproduce the original host message. The host’s independent copy is not attached through a persisted `_row_id` mapping in B’s normal message rows. [B stored columns](store.py:65)

**Why this changes the guarantee.** “Expand to the original source” becomes a claim about the complete structured record supplied by the host, rather than selected text and tool fields. Information cannot become recoverable through summary repair if it never entered the linked source archive. This concerns main-conversation records, independently of sanitizing a summarizer’s generated reasoning.

It is distinct from B16/T4.2’s payload catalog and B21/T2.6’s GC equality guard: those concern large-body discoverability and rewriting already-stored content. Neither schedules complete message-envelope capture. [Existing tasks](docs/TASKS.md:31), [payload task](docs/TASKS.md:47)

**Porting requirements.**

- Add a fork-owned `message_archive.py` and an additive envelope/version table keyed to existing `store_id`. Preserve host-supplied structured values, original content type, a digest, and capture-completeness status. Keep current searchable columns as projections.
- Capture before storage/replay transformations. Connect both ordinary ingestion and offline imports; the importer currently performs its own reduced-column insertion. [B ingestion boundary](engine.py:4913), [import insertion](scripts/import_lossless_claw.py:1045)
- Add bounded exact-record recovery and field-aware source rendering. Summaries must indicate meaningful additional source material; replay should pass supported fields through Hermes’s renderer rather than blindly inject arbitrary archived fields into provider requests.
- Register the new schema family in B’s strict bootstrap classifier. Backfill only from demonstrably matching host records; otherwise mark legacy capture incomplete. Never invent missing fields from a summary. [B classifier](db_bootstrap.py:309)

Tests should cover metadata-only differences, structured-content types, unknown blocks, failed externalization, restart, exact recovery through a summary node, and preservation across provider switches. Keep archive metadata out of partition-selection tuning and assert unchanged ordinary 256k DAG membership.

**Estimated cost:** 1–2 engineer-weeks, plus storage for newly retained material; duplicating whole bodies would add further storage cost. No additional model call is inherently required.

**Do not copy A’s limitations.** A’s top-level metadata is still selectively collected—it is not a universal envelope archive. Its replay layer also drops certain legacy reasoning blocks without model identity. Preserve archived values even when replay is unsupported, and expose that distinction explicitly. [A selective metadata](lossless-claw v1.0.0 src/message-content.ts:649), [legacy replay removal](lossless-claw v1.0.0 src/assembler.ts:635)

**C2 — Make runtime ingestion a durable transfer keyed by host events, with receipts and conservative reconciliation.**

**What A implements.** `commitTurn()` validates admission/terminal identity and range, hashes the accepted payload, and writes messages, context entries, and a durable advancement receipt inside one transaction. Repeating the same advancement returns `duplicate`; reusing its key with a different payload fails. See [A validation/hash](lossless-claw v1.0.0 src/engine.ts:182), [transaction and duplicate check](lossless-claw v1.0.0 src/engine.ts:4147), [receipt insertion](lossless-claw v1.0.0 src/engine.ts:4225), and [ledger schema](lossless-claw v1.0.0 src/db/migration.ts:1453).

A additionally distinguishes candidate transcript IDs from verified anchors. Suspect anchors require a new boundary instead of silently acquiring authority. [A anchor classification](lossless-claw v1.0.0 src/transcript-anchor-audit.ts:175)

Its tests explicitly cover rollback of messages/context/receipt together and recognition after restart. I inspected these tests; I did not execute them. [A rollback and restart tests](lossless-claw v1.0.0 test/engine-commit-turn.test.ts:644)

**What B currently guarantees—and does not.**

B’s raw batch insertion **is already transactional**. An injected invalid second row left zero rows in my in-memory probe. The missing mechanism is a durable receipt and source identity, not basic batch atomicity. [B transaction](store.py:537)

Runtime ingestion advances an in-memory list cursor after insertion. Restart reconciliation infers that cursor from stored content identities; the identity tuple contains role, content, tool-call ID, and tool calls—not Hermes row identity. [B cursor advancement](engine.py:4948), [restart reconciliation](reconcile.py:804), [identity tuple](reconcile.py:237)

A probe supplied two user messages with identical text but different `_row_id` and timestamps: their B replay identities were equal. That demonstrates the missing distinction; it does **not** prove that every repeated phrase is dropped.

Hermes already supplies useful identity material. Successful flushes stamp `_row_id` onto live messages, and the normal post-LLM hook receives those messages plus `turn_id`. B’s callback consumes the history but does not persist those identities. Hermes stamping (Hermes Agent host internals; path elided), hook payload (Hermes Agent host internals; path elided), [B callback](__init__.py:562)

There is another existing building block: B’s **offline importer** already records source-to-store mappings. This is a runtime architecture gap, not an absence of identity-aware import anywhere in B. [B import ledger](scripts/import_lossless_claw.py:1063)

**Why this changes the guarantee.** B could distinguish:

- the same event delivered again;
- a genuinely new event with identical text;
- an amended source record;
- history not yet transferred.

False replay suppression loses an occurrence and its provenance. Duplicate ingestion falsifies chronology and the source population feeding the DAG. A receipt also lets a caller resolve an ambiguous “commit succeeded, acknowledgement disappeared” outcome.

T1.3 schedules **summary publication**—node, sidecar, frontier, rotation marker. It does not schedule this host-to-raw-store delivery contract. [T1.3](docs/TASKS.md:19)

**Porting requirements.**

- Add `ingest_receipts.py` and `host_event_identity.py`, with source mappings and receipt tables. Namespace identities by host database/session generation; retain payload fingerprints and revisions.
- Extend B’s existing batch transaction to include mappings, receipt, and ingestion checkpoint. Keep this checkpoint separate from the compaction frontier. Serialize receipt read/write across connections.
- Use verified Hermes row IDs where available. Treat content matching as legacy reconciliation evidence, with explicit ambiguous/unproven outcomes. Do not manufacture exact identity from repeated text.
- Add durable catch-up for missed callbacks. Merely switching to `on_turn_complete` is insufficient: Hermes explicitly documents that hook as best-effort and skipped on some abnormal exits. A complete turn-acknowledgement guarantee requires a host contract or a durable reconciliation protocol over host records. Hermes hook contract (Hermes Agent host internals; path elided)
- Migrate existing mappings conservatively without deleting duplicate-looking history or rewriting existing DAG source IDs.

Acceptance tests should include lost acknowledgement, restart, concurrent delivery, identical text under different IDs, changed payload under an existing ID, missed callback followed by catch-up, and session rollover. Ordinary successful source selection must remain identical at 256k; correctness applies at every window.

**Estimated cost:** 2–4 engineer-weeks, potentially more if Hermes needs a durable event/revision contract.

**Do not copy A’s assumptions.** Its provider-shaped tool-ID regex is not a provider-independent event identity contract. Use host-issued identities, not guessed uniqueness from `call_`/`toolu_` prefixes. Also retain B’s `synchronous=FULL`; A configures `NORMAL`. [A ID heuristic](lossless-claw v1.0.0 src/stable-event-key.ts:5), [A durability setting](lossless-claw v1.0.0 src/db/connection.ts:57), [B durability setting](db_bootstrap.py:130)
