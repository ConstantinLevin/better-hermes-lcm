## A. Per-file verdicts

The three most consequential results are:

- **Normal session carry-over can break the advertised recovery chain.** A retained parent remains expandable, but its older-session children disappear from expansion without an incomplete-result marker. **T01–T03**.
- **Several tools mistake incomplete work for complete results.** Confirmed examples include search failures reported as zero matches, eleven recent sections reported as a complete ten, and an orphan check passing after inspecting only the first 1,000 nodes. **T11, T16–T17, T27**.
- **Auxiliary synthesis still accepts provider-truncated answers.** A response ending with `finish_reason="length"` is returned as an ordinary answer. **T19**.

I read all **8,207 assigned lines**, at B commit `f38ed61f2746ced66d7466e905fdd0d0d05b9318`. No files were modified. There are **39 distinct findings** below; two span both implementation and schema and retain shared identifiers.

Deployment notation:

## D. Cross-partition notes

1. **Retention needs a shared ownership/reachability contract.**  
   Engine rollover deliberately preserves raw ownership while reassigning selected DAG nodes. Tool authorization must therefore follow provenance rather than require every descendant to share the root’s current session. Fixing this only by moving raw rows would undo the host integration’s explicit recovery safeguard. [engine.py:2568](/home/agent/projects/agentimprovement/betterlcm/engine.py:2568), [dag.py:395](/home/agent/projects/agentimprovement/betterlcm/dag.py:395).

2. **The coverage doctor cannot establish the operator’s index-quality doctrine as currently implemented.**  
   Its source builder slices to 400,000 characters and skips missing sources; zero extracted entities become fraction 1.0. Session inspection samples nodes and limits reported failures. Keyword presence also does not establish that the summary explains what happened. Exposing its missing tool schema is necessary, but must not turn this metric into an unsupported “no loss” certificate. [coverage_doctor.py:68](/home/agent/projects/agentimprovement/betterlcm/coverage_doctor.py:68), [coverage_doctor.py:82](/home/agent/projects/agentimprovement/betterlcm/coverage_doctor.py:82), [coverage_doctor.py:124](/home/agent/projects/agentimprovement/betterlcm/coverage_doctor.py:124), [coverage_doctor.py:150](/home/agent/projects/agentimprovement/betterlcm/coverage_doctor.py:150).

3. **The index sidecar itself can contain a shortened index.**  
   `extract_index_block` clips the block and adds an ellipsis, without an omitted-length or continuation record. Tools need the full node-summary getter from T03, and the metadata partition should expose whether its index block is complete. [node_meta.py:61](/home/agent/projects/agentimprovement/betterlcm/node_meta.py:61).

4. **Search-layer bounds need to participate in the tool’s completeness protocol.**  
   Store search has its own candidate caps and early returns. DAG substring fallback also applies bounded fetching before its subsequent in-memory ranking. A truthful tool-level `has_more` cannot be implemented solely by inspecting the final list length; these dependencies must return scan/exhaustion metadata. [store.py:1342](/home/agent/projects/agentimprovement/betterlcm/store.py:1342), [store.py:1415](/home/agent/projects/agentimprovement/betterlcm/store.py:1415), [dag.py:692](/home/agent/projects/agentimprovement/betterlcm/dag.py:692).

5. **Host spillover changes the conclusion about oversized tool outputs.**  
   The inspected Hermes host persists oversized results and supplies a file path plus explicit paging instructions. That is a valid recovery mechanism when persistence succeeds. If all write locations fail, however, the host falls back to a preview whose omitted tail was not saved. T32 should therefore be addressed jointly with host fallback behavior, without claiming every large B result is already lost. [tool_result_storage.py:163](/home/agent/.hermes/hermes-agent/tools/tool_result_storage.py:163), [tool_result_storage.py:210](/home/agent/.hermes/hermes-agent/tools/tool_result_storage.py:210), [tool_result_storage.py:227](/home/agent/.hermes/hermes-agent/tools/tool_result_storage.py:227).

6. **Tool dispatch can proceed after ingest failure.**  
   The engine catches and records an ingest failure before dispatching the requested tool. Doctor exposes ingest health, but an ordinary retrieval result need not carry that incompleteness. The integration partition should determine how every affected result communicates that the latest turns may not have entered durable memory. [engine.py:3843](/home/agent/projects/agentimprovement/betterlcm/engine.py:3843), [tools.py:6645](/home/agent/projects/agentimprovement/betterlcm/tools.py:6645).

7. **Delegated evidence modules remain separate audit responsibilities.**  
   The assigned wrappers call `evidence_pack`, `evidence_compiler`, `reasoning` and `adaptive_retrieval`. In particular, `lcm_compute` accepts the caller’s `evidence_complete=true` assertion for open-cardinality operations; that Boolean is not itself proof of complete retrieval.
