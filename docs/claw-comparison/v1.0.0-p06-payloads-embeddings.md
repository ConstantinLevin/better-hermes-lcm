## A. **Per-file verdicts**

The three most consequential findings are:

1. **B misses the current Hermes spillover directory.** Hermes now stores oversized tool results in an expiring `cache/spillover` directory; B only accepts the older temporary `hermes-results` directory. ### embedding_provider.py

**Responsibility:** Adapt optional embedding/reranking backends, batch inputs, preserve document correspondence, and enforce provider error, timeout, and call-control behavior.

The provider findings are outside the documented default semantic configuration. Additional conditions are stated individually.

**P1 — FastEmbed can truncate inputs without B detecting or marking it.**  
B constructs the model without establishing a no-truncation contract, calls `embed/query_embed`, and validates only returned vector count and dimensions. ## D. **Cross-partition notes**

**D1 — GC’s new transaction hook does not guarantee archive/rewrite atomicity on failure.**  
The engine now invokes chunk archival inside the content-rewrite transaction, so the earlier simple “two separate commits” concern is no longer an accurate description of the successful path. However, `_archive_chunks_for_messages()` swallows archival exceptions and returns early whenever embeddings are disabled—even if historical chunk tables remain. The store then commits the rewrite. Its generic callback-failure path also lacks rollback: an isolated probe raised in the callback, then an unrelated `pin()` committed the pending content replacement. These cases can leave live chunks pointing into GC placeholders. **Trigger:** GC enabled with archival failure, or embeddings disabled during GC and later re-enabled. Fix the engine/store transaction contract together with V1; archive based on stored state, propagate failures, and roll back the rewrite.
