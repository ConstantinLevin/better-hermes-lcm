## A. Per-file verdicts

Three results matter most:

- **The trajectory store can destroy original values and commit incomplete ingests.** Its default protection replaces matching values before storing or hashing them; an interrupted transaction can later be committed by `close()`. Both were reproduced. See T01–T02.
- **“Grounded,” “verified,” and “product-validated” do not reliably mean the evidence supports the answer.** Probes accepted swapped operands, substituted another city into a valid assertion, verified unsupported prose, and computed an interval using unrelated events. See R02, R03, R07 and C11.
- **The requirements compiler can conceal incomplete consideration of evidence.** It certified a count after excluding a real event, and reported an answer sufficient after a hydration cap excluded a supplied contradiction. See C01 and C06.

I read all **7,695 lines** of the three assigned files. No files were modified.

Reachability labels used below:

| Label | Configuration and documented deployment |
|---|---|
| **Trajectory** | Explicit use of `TrajectoryStore`, including the backfill/replay paths. The backfill constructs it at `benchmarking/state_embedding_backfill.py:116–133`; replay uses it at `benchmarking/h3_composition_replay.py:149–175`. I found no ordinary Hermes runtime caller. These findings are conditional on using that corpus subsystem, rather than demonstrated active in the documented deployment. |
| **Compute** | Public `lcm_compute`, available under the documented stock tool surface. Its planner, grounder, executor and verifier are called at `tools.py:697`, `744`, `812` and `844`. Automatic evidence processing need not be enabled. See `README.md:327–354`. |
| **Compiler** | Public `lcm_compile_evidence(mode="auto")` explicitly passes `enabled=True`, independently of automatic-hook configuration: `tools.py:924–945`. Automatic invocation additionally requires `preanswer_evidence_enabled=True` and mode `requirements_v1`: `config.py:714–722`, `__init__.py:182–203`. The documented automatic configuration is off: `README.md:332–335`. |

“By inspection” findings below are distinguished from reproduced results. A derived-index defect does **not** mean its underlying SQLite text was deleted.

### trajectory_store.py

[trajectory_store.py](trajectory_store.py) stores immutable trajectory corpora, ordered states, transitions, asset references, derived search indices and exact state references; it also provides backup and retrieval APIs.

**T01 — Default protection irreversibly replaces original content and can collapse distinct ingests.**  
**Reachability:** Trajectory ingestion with the constructor default `protect_sensitive=True`. The independent protection configuration enables matching at `trajectory_store.py:405–413`, and the default is at `:546`. Both normalized states and `source_payload` are protected before serialization and hashing (`:925–967`, `:990–1007`). A synthetic `api_key=…` assignment disappeared from the stored JSON. Two same-length password values produced the same protected digest, and the second insert returned `already_current=True`. The replacement marker cannot recover either original. This violates doctrine 1 even though redaction is marked. It also differs from ordinary LCM’s documented lossless default (`README.md:519–524`).

**T02 — Cancellation can leave a partial transaction that cleanup commits.**  
**Reachability:** Writable Trajectory operations interrupted by `KeyboardInterrupt`, `SystemExit` or another `BaseException` during a transaction, followed by `close()` or `backup_to()`. Insert rolls back only `Exception` (`trajectory_store.py:996–1139`); cleanup and backup explicitly commit (`:3815`, `:3824–3834`). Injecting `KeyboardInterrupt` before the asset insert left one source and one state, no receipt, and cursor zero. Calling the real `close()` commit path committed that inconsistent state. The same exception pattern occurs in index publication (`:1428–1475`, `:1834–1857`, `:1946–1961`). This compromises durable provenance and resumability.

**T03 — A successful database backup is not a complete trajectory backup.**  
**Reachability:** Trajectory backup/restoration when the external asset tree is not separately preserved. Asset ingestion stores a relative path, hash and size, rather than owning a durable copy of the image (`trajectory_store.py:870–881`, `:1090–1102`). `backup_to()` copies only SQLite and returns the destination path without an asset-omission manifest (`:3806–3822`). A restored database alone cannot recover screenshots. Separate preservation of the immutable asset tree avoids the loss; the defect is the absence of a complete-backup operation or an explicit incomplete-backup result identifying the required assets.

**T04 — An unavailable screenshot blocks recovery of intact text.**  
**Reachability:** Trajectory exact-reference recovery after an asset is missing, changed or inaccessible. `resolve_exact_ref()` unconditionally requests the image (`trajectory_store.py:3741–3765`), and `_row_to_hit()` resolves it before returning text (`:2289–2297`). Asset validation raises on unavailable or mismatched files (`:2255–2269`). A simulated asset failure blocked exact text recovery, while `query(..., image_limit=0)` still returned text. This unnecessarily couples recoverability of separate source components.

**T05 — Original `source_payload` content has no discovery or expansion surface.**  
**Reachability:** Trajectory ingestion where `source_payload` contains information absent from normalized fields. The complete payload is stored (`trajectory_store.py:950–967`, `:1033–1049`), but FTS indexes only normalized fields (`:970–985`), semantic documents use those fields (`:1286–1336`), and exact resolution returns a state-shaped `TrajectoryHit` without the source payload (`:2308–2344`, `:3741–3765`). A unique fact stored only in `source_payload` was present in SQLite but absent from search and exact-resolution output. Direct SQL can recover it; the agent-facing index does not reveal that it exists or provide a source-payload expansion route.

**T06 — Semantic indexing silently cuts source coverage.**  
**Reachability:** Trajectory source semantic indexing; the field-coverage limitation also applies to the optional state index. Source documents sample at most 64 states, cut each combined state representation to 900 characters, and cut the final document to 48,000 characters (`trajectory_store.py:212–214`, `:1275–1284`, `:1332–1336`). There is no omission manifest. A 70-state probe produced a 48,000-character document containing only 54 state labels; a topic after the per-state prefix was absent. The state index embeds visible text, falling back to URL only when text is empty; it does not include actions, thoughts or the other normalized fields (`:1561–1573`). Raw rows survive, but neither representation records its incomplete coverage.

**T07 — Query caps omit hits and images without a returned completeness or continuation contract.**  
**Reachability:** All Trajectory queries; additional omissions occur with diversity, adjacency and sharp-budget options. Requested limits are silently clamped (`trajectory_store.py:3272–3290`); selection applies further per-trajectory and result limits (`:3005–3021`, `:3539–3550`, `:3669–3678`). Images beyond the image allowance become indistinguishable from absent image fields. Sharp budgeting can drop whole references (`:2952–3003`). The returned value is only a tuple of surviving hits (`:3739`), with no `has_more`, omitted-reference manifest or cursor. Some omissions are available through optional side-channel telemetry, but its candidate list is itself capped at 64 (`:3686–3734`). Text-excerpt markers do not describe these whole-hit omissions.

**T08 — Query preprocessing silently removes search intent and has a CJK discovery gap.**  
**Reachability:** Trajectory queries containing more than 16 accepted terms, more than eight quoted phrases, single-character/symbol-only terms, or CJK substrings. `_fts_expression()` drops terms and stops at 16 (`trajectory_store.py:2238–2253`); quoted phrases stop at eight (`:2690–2700`). An empty expression returns ordinary empty results before source semantic ranking unless state-semantic expansion is enabled (`:3291–3299`). Source semantic ranking still feeds an FTS-constrained state search (`:3357–3361`). Searching `旅行` did not find stored `東京駅の旅行計画`; searching the complete token did. A has a concrete CJK LIKE fallback at `lossless-claw v1.0.0 src/store/conversation-store.ts:1991–2033`; B’s trajectory query lacks that route.

**T09 — Casefolded match offsets are applied to the original string.**  
**Reachability:** Trajectory excerpts containing characters whose casefold changes length, such as `ß`. Both excerpt algorithms find positions in casefolded text and use them to slice original text (`trajectory_store.py:2347–2361`, `:2375–2423`). For a prefix of 100 `ß` characters followed by `TARGET`, the excerpt selected trailing filler instead of the match. The returned slice and its offset remain internally exact, but the excerpt can omit the very subject that should tell the reader why to expand it.

**T10 — Optional ranking features use silently shortened, ASCII-only representations.**  
**Reachability:** Trajectory diversity/MMR, title boosting or sharp template ranking. Candidate signatures and title representations cut combined fields to 12,000 characters and discard non-ASCII vocabulary (`trajectory_store.py:2426–2464`). Template ranking considers only the first 4,000 text characters (`:2808–2829`). Long goals or headers can consume the entire allowance before meaningful state content appears. These representations influence exclusion and ordering (`:2578–2638`) without recording which portions or vocabulary were ignored.

**T11 — Rebuilding the state index disables the working index before replacement is ready.**  
**Reachability:** Trajectory state-index rebuilds, particularly `resume=False`, profile changes, failures or concurrent rebuilding/querying. The old profile is deactivated before provider work (`trajectory_store.py:1740–1753`), because vectors are keyed only by `state_id` and progressively overwritten (`:1517–1525`, `:1834–1857`). An injected provider failure left no active profile; semantic ranking then returned `[]` (`:2195–2203`). Final completeness checking also precedes the activation transaction (`:1935–1958`), leaving a concurrency gap. The source-level builder’s transactional publication is better (`:1428–1475`); the state builder needs equivalent preservation of its last usable generation.

**T12 — Semantic degradation and attempt accounting are incomplete.**  
**Reachability:** Trajectory semantic queries, especially `state_semantic_quota>0`, skipped profiles and provider failures. Source failures now retain useful typed side-channel information (`trajectory_store.py:3324–3356`), so the earlier “all error detail disappears” suspicion is false. However, returned hits still carry no degradation status. State-semantic successes never call the success recorder (`:3463–3486`), and `last_semantic_attempt()` can retain an earlier query’s attempt (`:2012–2016`, `:2075–2079`, `:3292–3299`). A state-only successful query reported `query_calls=1` but `attempts=0`, `successes=0` and `semantic_attempt=None`. Operational evidence can therefore report an unused or failed path incorrectly.

**T13 — NumPy top-k applies the state-ID tie-break after excluding candidates.**  
**Reachability:** Trajectory state semantic retrieval with NumPy installed and equal scores across the top-k boundary. `_semantic_state_ranks()` uses `argpartition(... )[:limit]` before sorting by score and state ID (`trajectory_store.py:2216–2229`). Consequently, the state-ID ordering governs only the selected subset; it cannot guarantee the same boundary selection as the fallback, which sorts the entire population first (`:2230–2236`). This is a limit-before-order defect affecting reproducibility and which evidence survives. **Verified by inspection; NumPy was unavailable in both inspected Python environments, so this branch was not executed.**

**T14 — Optional FTS availability is a prerequisite for opening the recovery API.**  
**Reachability:** Trajectory databases on SQLite without FTS5, or databases with intact base tables but missing trajectory FTS structures. Writable initialization unconditionally creates FTS5 (`trajectory_store.py:752–773`); read-only initialization requires the FTS table and refuses to open without it (`:642–670`). This is an explicit failure, not silent success, but it blocks ordinary exact-state recovery despite intact source tables. A probes FTS capability and conditionally migrates/searches (`lossless-claw v1.0.0 src/db/features.ts:10–60`, `src/db/migration.ts:1636–1638`, `src/store/conversation-store.ts:2004–2033`).

**T15 — Retrieval tuning has no context-window resolution.**  
**Reachability:** Trajectory retrieval at any window, including 1M. Result, candidate, image, excerpt and sharp-budget preferences remain fixed (`trajectory_store.py:188–214`, `:548–560`, `:3272–3290`); the constructor and query API receive no window or resolved window policy (`:539–549`, `:3250–3269`). Thus these preferences cannot implement the operator’s prescribed resolution from the 256k anchor to a chosen 1M endpoint. This is a scaling-contract gap, not evidence of a changed summary DAG. Provider request ceilings should separately follow provider capabilities, rather than being confused with context-window preferences.

**T16 — Bounded requests coexist with unbounded working sets and large unbudgeted fields.**  
**Reachability:** Large Trajectory corpora or large goals/actions/thoughts, particularly default queries with `sharp_token_budget=0`. Source-index construction materializes source documents and vectors for the whole corpus (`trajectory_store.py:1286–1337`, `:1382–1426`); state backfill loads all state bodies before batching (`:1711–1718`, `:1822–1832`). Query text limits apply to visible text, while goal, outcome, URL, action and thoughts are returned whole (`:2293–2323`), each potentially accepted up to two million characters (`:210–211`, `:527–532`). Provider batching therefore does not bound process memory, and an excerpt allowance does not bound the returned context. Exact resolution also has no paging for these large fields (`:3741–3765`).

**T17 — A fully indexed state corpus still makes a provider call on resume.**  
**Reachability:** Trajectory state indexing with no matching source-level semantic profile, even when a complete matching state profile exists. Dimension discovery consults only the source profile (`trajectory_store.py:1697–1709`) and otherwise calls `embed_query()` before checking already-indexed states (`:1720–1734`). A second unchanged build returned `status="current"` but made one provider call. This contradicts the stated zero-call behavior (`:1665–1668`), adds avoidable cost and latency, and prevents offline idempotent confirmation. It is a throughput/resilience defect rather than raw-content loss.

**T18 — Fractional source ordinals are silently truncated.**  
**Reachability:** Trajectory callers supplying malformed non-integer ordinals; not correctly typed adapter output. Validation only checks negativity (`trajectory_store.py:889–890`), then normalizes using `int()` (`:954`, `:1027–1029`). An ordinal of `0.9` was stored as zero and advanced the ingest cursor. Unlike state indexes and steps, which receive strict integer validation (`:893–910`), source ordering provenance is silently changed.

Checks that held: oversized source/text inputs raise instead of being sliced (`trajectory_store.py:428–443`, `:527–532`); normal insert failures roll back (`:1137–1139`); transition order follows the supplied sequence (`:904`, `:1104–1119`); writable initialization performs an FTS integrity check rather than relying only on row counts (`:779–797`); Unicode embedding chunks use strict boundary-preserving decoding (`:1611–1643`); ordinary visible-text excerpts carry an offset, truncation flag and exact state reference (`:2288–2307`).

### reasoning.py

[reasoning.py](reasoning.py) plans supported deterministic operations, grounds operands against stored evidence, computes results and checks proposed final answers. It is not the reasoning-tag sanitizer.

**R01 — Numeric grounding accepts pieces of numbers and unequal values.**  
**Reachability:** Compute with such literals in exact quotes; no optional feature required. `_NUMBER_RE` lacks lexical boundaries and scientific-notation handling (`reasoning.py:41`, `:598–612`); word numbers are matched independently. Float matching additionally accepts an absolute discrepancy of `1e-9` (`:625–631`). Real grounding accepted `3 USD` from `1e3 USD`, `5 points` from `twenty five points`, and `0.0 USD` from `0.0000000001 USD`. Exact quotation has not established the submitted numeric meaning. Incorrect values can enter canonical computations without an approximation or parsing-failure marker.

**R02 — Grounding values and labels independently does not ground their relationship.**  
**Reachability:** Compute with multi-entity or multi-value quotes. Value, label and key checks establish independent textual presence (`reasoning.py:818–847`); directed-difference alignment verifies labels’ order in the question, not their association with amounts (`:1157–1170`). Two exact source rows saying “Alice paid 10 USD; Bob paid 30 USD” accepted operands `Alice=30`, `Bob=10`, passed alignment and computed `$20` for “How much more did Alice pay than Bob?” The real evidence contradicts that result. Canonical keys similarly receive token support rather than entity/relation proof (`:719–724`, `:844–847`).

**R03 — An assertion ID does not bind the operand to that assertion’s typed value.**  
**Reachability:** Compute with populated assertion storage, which is opt-in and documented off by default (`config.py:550–562`). `_ground_one()` obtains the assertion’s source and active/conflict metadata (`reasoning.py:742–778`) but accepts the caller’s value if it appears anywhere in that source quote (`:818–827`). It does not require equality with the assertion’s typed object/value. A real stored current-city assertion for **Rome**, supported by “My current city is Rome, replacing Paris,” grounded a caller-supplied **Paris** and computed it as current. Caller dates can also replace assertion-derived dates when another quoted date passes the generic date test (`:849–895`). Source validity and assertion-state validity must not be transferred to a different fact.

**R04 — Temporal restrictions can disappear while the planner still succeeds.**  
**Reachability:** Compute with relative-time questions lacking a valid question date, or temporal forms the resolver does not support. Window resolution returns `None` (`reasoning.py:287–349`, `:412–413`), but count/sum/difference branches can still produce plans (`:453–477`). The missing-date fallback runs only when no operation was selected (`:516–524`). “How many events happened yesterday?” without an anchor produced a count plan with no temporal window. A caller satisfying the separate completeness gate can then compute over an unfiltered population. The unresolved restriction needs to remain an explicit unmet requirement.

**R05 — Canonical numbers and intervals are silently rounded or reduced in precision.**  
**Reachability:** Compute with fractional quantities, large numeric latest-state values, or non-integral week/month intervals. `_format_number()` rounds to six decimal places (`reasoning.py:993–999`); non-integral arithmetic results are converted to float (`:1355–1364`); numeric latest values are passed through float even when originally integers (`:1523–1535`). Two exact `0.0000001 USD` operands produced a canonical `$0`, with calculation steps displaying zeros. Week intervals use integer division, and month intervals discard incomplete months without labeling the result “whole” months (`:1404–1425`). Exact-source citations survive, but the authoritative result omits information without an approximation/remainder marker.

**R06 — Timestamp precision is discarded before ordering, with arbitrary answers for ties.**  
**Reachability:** Compute using timestamp-bearing evidence, including ordinary raw operands. `_parse_day()` converts timezone-aware datetimes to dates (`reasoning.py:223–250`); grounded evidence stores that day (`:849–895`). Ordering then sorts only by day and uses input order for ascending ties, reversing it for descending order (`:1443–1458`). A probe supplied Alpha at 18:00 and Beta at 09:00 on the same UTC day, in that input order; “Which … came first?” returned Alpha. When only day precision exists, the order should remain unresolved instead of being invented.

**R07 — The final-answer verifier verifies arbitrary unsupported prose.**  
**Reachability:** Compute with `candidate_answer`; exposed under the documented deployment. The verifier checks citations, result-string presence, numeric/unit lists and required entity substrings (`reasoning.py:1541–1576`). It does not validate additional assertions expressed without new numbers or recognized units. Appending “Alice and Bob admitted fraud” to the computed answer still returned `verified`. The public tool then substitutes that prose as its answer (`tools.py:836–858`). This makes the verification label materially stronger than the check performed.

**R08 — Accepted input ranges contain uncaught date and decimal exceptions.**  
**Reachability:** Compute with extreme dates or large mixed integer/fractional operands; no optional feature needed. Several date operations fall outside protective exception handling (`reasoning.py:315–347`, `:262`, `:851`). “Yesterday” anchored at `0001-01-01` raised `OverflowError`. Arithmetic uses a large local Decimal precision, but formatting occurs afterward using `round(..., 6)` under the ambient precision (`:1321–1333`, `:1364`, `:993–999`). Adding `100000000000000000000000 USD` and `0.1 USD` raised `decimal.InvalidOperation`. These are failures to deliver an explicit fallback, rather than silent successful computations.

**R09 — Non-integer exact-reference components are silently converted.**  
**Reachability:** Direct library calls or calls reaching the implementation despite invalid reference types. Schema-valid ordinary tool calls declare these fields as integers (`schemas.py:326–329`), so this is a defensive API defect. `_ground_one()` uses `int()` on source IDs and offsets (`reasoning.py:783–788`, `:804–809`). Fractional values `1.9`, `0.9`, `7.9` grounded as `lcm:1:0-7`. A function promising exact reference validation should reject malformed provenance or explicitly report a permitted repair, rather than silently changing it.

**R10 — Reasoning budgets do not resolve against the context window.**  
**Reachability:** Compute at all windows. Operand count, question length, quote length, labels and verifier input remain fixed (`reasoning.py:35–38`, `:409–410`, `:791–792`, `:974–976`, `:1545–1546`). These paths have no window-policy input. The refusal markers are explicit, so this is not hidden truncation; it is a doctrine-4 gap for tuning preferences that prevent larger evidence sets from using a 1M context. Numeric validity limits and reference validation should remain distinct from adjustable evidence budgets.

Checks that held: exact spans must match the stored source (`reasoning.py:793–800`); grounding stops on an invalid operand rather than returning only the successful prefix (`:974–990`); unsupported operations receive explicit fallback (`:414–415`); directed differences reject a negative result contradicting the premise (`:1341–1349`); latest-state execution checks omitted active assertions, truncation and unresolved conflicts (`:1495–1521`). The problem in R03 survives those checks because it substitutes the fact’s value.

### requirements_compiler.py

[requirements_compiler.py](requirements_compiler.py) hydrates baseline evidence, extracts candidate facts, retrieves missing evidence, selects or computes answers, attempts finite-population proofs and renders evidence briefs.

**C01 — A complete row scan is incorrectly promoted to complete event coverage.**  
**Reachability:** Compiler finite enumeration for temporal entity-count questions; available manually under the documented deployment. `_finite_enumeration()` scans the whole corpus but excludes clauses using a narrow grammatical recognizer before counting material or unresolved clauses (`requirements_compiler.py:1711–1741`, `:1777–1787`). A corpus containing “I took a vacation to Bali …” and “My vacation to Kyoto was …” returned **one vacation**, `finite_coverage=True`, and a non-truncated certificate, although both rows were scanned. The second event was invisible to the certificate. Unknown grammar cannot establish irrelevance.

**C02 — Heuristic event keys collapse distinct events and split repeated descriptions.**  
**Reachability:** Compiler finite enumeration and related event ordering. Keys consist of an entity unit, capitalized names and possibly a date (`requirements_compiler.py:1653–1688`); enumeration retains only the first candidate for each key (`:1845–1849`). “I took a vacation to Bali …” followed by “I took another vacation to Bali …” on the same date was certified as one vacation. Adding “with Alice” to another description generated a different key and counted two. Neither equality nor inequality of these strings proves event identity; discarded supporting refs are also absent from the selected operand list.

**C03 — Numeric extraction removes the predicate, polarity and qualification needed to understand a fact.**  
**Reachability:** Compiler numeric questions with matching evidence; default budgets suffice. Clause extraction excludes punctuation (`requirements_compiler.py:394–406`), making its subsequent `endswith("?")` rejection ineffective (`:507–510`). The stored candidate quote is reduced to the number/unit phrase (`:511–524`). Negated, interrogative and conditional probes—“You do not need 15 points…,” “Do you need 15 points…?” and “If approved, you would need 15 points…”—all became `answer_sufficient` for a current requirement of 15 points. The selected citation expands only `15 points`, concealing the qualification. This directly fails the “index says what happened” doctrine.

**C04 — Numeric extraction chops ordinary numeric expressions.**  
**Reachability:** Compiler numeric extraction with decimals or compound number words. The integer alternative precedes the decimal alternative and can accept an integer prefix of a decimal (`requirements_compiler.py:38–40`); number words are matched independently (`:41–74`, `:487–500`). `twenty five points` yielded **5 points** as sufficient evidence. `1.5 points` yielded ordinary `scalar_not_found`, because the extracted integer prefix did not retain its unit relationship. Unsupported numeric syntax should be reported as unparsed evidence, rather than partially interpreted or treated as absent.

**C05 — Candidate normalization and rendering lose numeric precision.**  
**Reachability:** Compiler scalar selection or rendering with large integers or precise fractions. Parsing goes through float (`requirements_compiler.py:371–381`); equivalence grouping converts to float and rounds to nine places (`:814–819`); rendering uses six-significant-digit `:g` formatting (`:1891–1898`). `9007199254740993` became `9007199254740992`; ordinary larger amounts can also be rounded in the “source value” line. Different small values can be grouped as equal. Exact quotes do not make altered values exact, and no rounding marker is supplied.

**C06 — Admission caps can exclude supplied contradictions before declaring sufficiency.**  
**Reachability:** Compiler with more than the allowed baseline/candidate population; default hydration is 12. Baseline ranking and hydration stop before considering all supplied refs (`requirements_compiler.py:2030–2040`); extraction is also capped (`:784–792`). The compiler can then return immediately with an answer (`:2061–2080`). Twelve refs supporting 15 points followed by a thirteenth supporting 20 points returned `answer_sufficient` with `trace.truncated=False`. Input/hydration counts and digests exist (`:1260–1273`), but no omitted-ref list or incomplete-consideration state is returned. Active-frontier and retrieval capacity limits introduce further unreported exclusions (`:1454–1488`, `:1550–1605`).

**C07 — Candidate limiting precedes temporal eligibility.**  
**Reachability:** Compiler temporal questions with enough earlier candidates to fill the cap. `_candidate_inventory()` slices extracted candidates before `_temporally_eligible_candidates()` (`requirements_compiler.py:784–792`). A real probe extracted 50 candidates, of which one was in the requested month; the default 48-candidate path returned none because earlier out-of-window candidates occupied the allowance. Public compilation returned `scalar_not_found` and `truncated=False`. The limit is applied to the wrong population.

**C08 — Relevance scores suppress contradictions before ambiguity checks.**  
**Reachability:** Compiler scalar, text and named-operand selection with different anchor-overlap scores. Each selector first discards everything below the best score, then tests the remainder for uniqueness (`requirements_compiler.py:834–847`, `:870–884`, `:1129–1137`). “You need 15 points to redeem a reward” outranked contradictory “Redeem for 20 points,” and the result was declared sufficient for 15. Relevance is useful for ordering examination; it does not prove that a lower-scoring compatible statement is false or irrelevant.

**C09 — Person/place extraction can answer a different relationship or subject.**  
**Reachability:** Compiler person/place questions, including ordinary baseline-only calls. Person extraction selects the last capitalized name (`requirements_compiler.py:612–616`). Place transitions for latest/previous return before the anchor check (`:588–607`); other place extraction selects the first matching preposition phrase (`:617–624`). “Alice sent the report to Bob” answered “Who sent the report?” with **Bob**. “The package moved from Paris to Rome” answered “Where do I currently live?” with **Rome**. Both received product-validated, answer-sufficient treatment.

**C10 — “Previous state” prioritizes an old transition over newer state evidence.**  
**Reachability:** Compiler `previous` operations with explicit transition evidence and later observations, or tied transitions. `_select_state()` returns the latest explicit transition’s extracted source state before considering the complete chronological frontier (`requirements_compiler.py:1021–1032`). Given “I moved from Bali to Kyoto,” followed later by “I now live in Rome,” it returned **Bali** as the previous residence. The destination Kyoto is not retained as a separate transition state in that path (`:597–602`). The early return also bypasses the later same-time conflict handling (`:1034–1048`).

**C11 — Date-interval operands are not bound to the requested events.**  
**Reachability:** Compiler date-interval questions with two eligible dates in baseline/retrieved evidence. `_date_candidates()` gives every date every slot name and reduces the quote to the date itself (`requirements_compiler.py:658–689`). Unanchored slot selection accepts a matching cardinality (`:1093–1116`), and `_compute()` does not perform question-aware selector validation (`:1156–1220`). “How many days between the launch and the review?” computed **10 days** from an unrelated picnic date and holiday date, returning `validated_canonical_computation`. The arithmetic was right; the evidence selection was not.

**C12 — Evidence rejection is unreported, including an unconditional secret-pattern gate.**  
**Reachability:** Compiler hydration with invalid/unavailable refs or any quote matching `_SECRET_RE`; independent of ordinary LCM’s sensitive-pattern flag. Normalization returns `None` for several distinct failures and for the secret regex (`requirements_compiler.py:299–339`); callers silently skip those refs (`:2034–2038`, `:1585–1589`). The broad pattern includes ordinary text such as `token=blue` (`:76–80`). A row containing that text plus the correct points requirement became ordinary `scalar_not_found`, with no rejected-ref reason and `truncated=False`. The compatibility path also coerces/clamps supplied reference components without a repair record (`:307–314`). Raw storage survives, but the caller cannot distinguish excluded evidence from absent evidence.

**C13 — Adjacent text, generated queries and event labels are cut without markers.**  
**Reachability:** Compiler adjacency/retrieval or long event-label/key paths. Adjacent messages are sliced to a 1,200-character prefix before normalization (`requirements_compiler.py:1436–1444`); generated queries are sliced at 500 characters (`:1491–1509`); labels and event keys are sliced at 300 (`:734–745`, `:1680–1687`). No omission record names the excluded suffix or its recovery range. Late answers and late temporal restrictions can disappear. Key clipping can also discard the appended date, strengthening C02’s identity-collision problem.

**C14 — Delivered evidence is silently sliced by the novel-reference allowance.**  
**Reachability:** Compiler computations using more than six baseline operands, or a lower configured novel-ref allowance. `_deliver()` applies `max_novel_refs` to **all** evidence, not just novel refs (`requirements_compiler.py:1949–1963`). Baseline computation can bypass the later novelty check (`:2081–2094` versus `:2231–2239`). A seven-cost sum returned `$28`, seven computation citations, only six evidence entries and `trace.truncated=False`. The missing citation remains recoverable through the computation, so this is an unmarked evidence-list omission rather than complete provenance destruction.

**C15 — Retrieval failures are reduced to ordinary “not found.”**  
**Reachability:** Compiler calls using targeted retrieval when that callback fails or returns malformed/error output. Exceptions and decoding failures are caught and discarded; malformed payloads follow the same route (`requirements_compiler.py:1575–1589`). Only token-accounting completeness is changed. An injected transport failure on both retrieval attempts returned `state="unknown"`, `reason_code="scalar_not_found"` and `truncated=False`, without the failure class or reason. The compiler has not established absence of evidence; retrieval did not complete.

**C16 — The advertised budgets do not bound actual context or input processing.**  
**Reachability:** Compiler with non-ASCII evidence, large supplied quotes or many baseline refs. `_estimate_tokens()` assumes four characters per token (`requirements_compiler.py:192–193`), and `_deliver()` treats that estimate as the budget authority (`:1938–1942`). A Japanese-heavy successful brief was reported as 712 tokens while the repository’s shared counter reported 1,899, against an 850-token budget. Separately, all incoming refs are copied/ranked before admission limits, complete messages are loaded, and baseline quotes have no `max_quote_chars` enforcement (`:202–237`, `:321–359`, `:2030–2040`). This work even precedes the disabled-feature return (`:2049–2051`). Limits on selected output do not bound the work required to select it.

**C17 — Requirements budgets are fixed and upper-clamped independently of window size.**  
**Reachability:** All Compiler calls, including 1M models. `_budgets()` fixes maximum candidates at 48, hydration at 12, novel refs at six, added context at 850 tokens, retrieval calls at two, adjacent quotes at 1,200 characters and scans at 4,096 rows (`requirements_compiler.py:147–170`). Larger overrides are silently clamped. No model-window policy participates in resolution (`:2011–2027`). This prevents the prescribed window-dependent tuning; it does not establish a DAG-shape regression. The underlying store also has an independent 4,096-row scan clamp, addressed in part D.

Checks that held: quote repair is restricted to a unique occurrence inside the declared source window (`requirements_compiler.py:327–337`); missing temporal evidence is rejected where the temporal eligibility pass is actually reached (`:987–1006`); a truncated finite scan is explicitly refused (`:1757–1773`); unknown times and ungrounded keys among *recognized* material clauses prevent finite certification (`:1834–1843`); an oversized brief is refused as a whole rather than sliced (`:1938–1942`). The whole-corpus scan itself uses one SQLite statement for its rows and coverage metadata (`store.py:673–720`); C01 is a semantic-coverage error above that coherent snapshot.

## D. Cross-partition notes

1. **Do not treat the public completeness boolean as a coverage certificate.**  
   `lcm_compute` requires `evidence_complete=True` for open-population plans, but that is a host-supplied assertion (`tools.py:719–740`). I did **not** report the absence of that check inside `execute_plan()` as a bypass: public callers do enforce the gate. Its evidential strength belongs to the tools/controller partition, and should be aligned with the corrected finite-coverage work in C01–C02.

2. **The answer-contract compiler contributes to event-binding failures.**  
   The date-interval probe’s contract retained `launch` and `review` as general anchors but supplied unanchored date slots. The assigned compiler then accepted arbitrary dates for those slots (`requirements_compiler.py:658–689`, `:1093–1116`). The contract owner should preserve event-to-slot relationships, while this partition must independently refuse unbound operands. The relevant contract representation is `answer_contract.py:74–106`.

3. **The store scan clamp must change with compiler budget resolution.**  
   Raising only `requirements_compiler._budgets()` will not increase finite-scan capacity: `store.scan_evidence_rows()` independently clamps to 4,096 rows (`store.py:673–698`). Its snapshot consistency and `truncated` flag are sound (`:709–720`). Coordinate C17 with that partition without weakening the refusal of incomplete scans.

4. **Existing FTS work must include the trajectory subsystem.**  
   The proposed plan already includes optional FTS bootstrap (`docs/TASKS.md:48`). Fixing only ordinary message/DAG startup leaves T14’s independent trajectory initialization requirements intact. A offers concrete capability detection and fallback mechanisms, but its behavior should not be described as a complete doctrine-compliant recovery solution merely because those mechanisms exist: `lossless-claw v1.0.0 src/db/features.ts:10–60`, `src/store/conversation-store.ts:1991–2033`.

5. **Extend historical-data boundary work to evidence briefs and the actual host seam.**  
   Compiler rendering directly interpolates source values and quotes into `<lcm-answer-brief>` (`requirements_compiler.py:1891–1909`). Existing boundary work in the proposed plan targets summaries (`docs/TASKS.md:41`); the evidence-rendering surface needs inclusion. The current Hermes host appends pre-call context to the **user message**, with a separate spill path—not the system prompt (`(Hermes Agent host internals; path elided)`, `:979–992`). Escaping, role labeling, spill recovery and replay behavior should be reviewed together. I did not establish an exploited prompt-injection outcome in this audit.

6. **Do not copy A’s bounded expansion as if it supplies complete continuation.**  
   A explicitly marks token-cap exhaustion during expansion (`lossless-claw v1.0.0 src/retrieval.ts:462–465`, `:495–499`), which is relevant to T07’s missing returned marker. That routine also skips missing sources and stops traversal without providing a complete continuation mechanism (`:445–447`, `:483–499`). It supplies a useful component, not a finished solution to this doctrine.

7. **These findings do not establish a summarizer-model or DAG-anchor regression.**  
   The assigned modules implement storage/retrieval and deterministic evidence processing; the inspected A tool registrations expose grep, describe, expand and expand-query rather than a corresponding typed compiler entry point (`lossless-claw v1.0.0 src/plugin/index.ts:1549–1588`). Therefore the computation findings stand on B’s own evidence and correctness contract. The scaling findings identify missing window-dependent preference resolution; proving identical 256k DAG structure and complete provider generations remains the responsibility of the compaction, scheduling and provider partitions.
