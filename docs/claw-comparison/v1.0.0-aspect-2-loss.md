**Six changes are worth porting.** The strongest are recovery across session boundaries, atomic publication, and enforced lineage. Claw provides useful mechanisms for these; it does not establish an end-to-end guarantee of your stricter definition of losslessness.

A denotes lossless-claw; B denotes betterlcm. This was read-only. I also ran four isolated, in-memory probes of relevant functions, using mocked dependencies where needed; I did not run either full test suite.

**1. Preserve usable recovery paths across `/new`, including externalized payloads**

**What A does.** Claw separates the active prompt projection from the durable graph. Its new-session pruning deletes `context_items` entries while retaining the messages, summaries, and source relationships. Expansion follows the stored source-summary edges. Its retrieval scope also supports an explicit historical conversation, and file description supports content expansion. See [A: summary-store.ts:896](lossless-claw v1.0.0 src/store/summary-store.ts:896), [retrieval.ts:451](lossless-claw v1.0.0 src/retrieval.ts:451), [lcm-conversation-scope.ts:189](lossless-claw v1.0.0 src/tools/lcm-conversation-scope.ts:189), and [lcm-describe-tool.ts:187](lossless-claw v1.0.0 src/tools/lcm-describe-tool.ts:187).

**What B does badly.** B correctly preserves shallow nodes, but moves only sufficiently deep nodes into the new session. That creates valid relationships crossing session boundaries. Both direct child expansion and recursive evidence collection then silently skip children whose `session_id` differs from the current session. See [B: dag.py:395](dag.py:395), [tools.py:1391](tools.py:1391), and [tools.py:1495](tools.py:1495).

The isolated reproduction constructed `d2 → d1 → d0`, moved only `d2` to the new session, and expanded it. The child still existed, but expansion returned no children and `has_more=false`. B’s existing `/new` regression checks node preservation and reassigned depths, rather than expansion of a connected graph: [B: test_marked_loss.py:218](tests/fork/test_marked_loss.py:218).

There is a related payload boundary: raw-row expansion can expose an archived row’s externalized reference, but explicitly reports that a cross-session reference cannot be expanded. This is a limitation of the advertised recovery path, not proof that the underlying file has disappeared. See [B: tools.py:5477](tools.py:5477).

**Why it matters.** Retaining bytes and IDs is insufficient when following a retained index produces an apparently complete, empty result. Larger windows and deeper retained graphs make this boundary more consequential.

**Concrete port.** Add a fork module, proposed `recovery_scope.py`, that authorizes the requested root and then follows its verified descendant relationships independently of each descendant’s session label. Preserve original source/session identities. Add explicit archive scope for historical roots and allow payload hydration through an authorized stored row, using that row’s owning session.

Hook this into `_expand_child_nodes`, `_collect_descendant_evidence_blocks`, `_get_externalized_payload`, and the `lcm_expand` argument schema. Do not simply remove session checks globally.

Extend `tests/fork/test_marked_loss.py` with connected DAGs across repeated `/new` operations, retain depths `-1/0/2`, archived payload pagination, unrelated-reference rejection, and distinct errors for missing versus inaccessible sources.

**Effort: medium. Value: critical.**

**2. Publish summaries, lineage, metadata, and frontier changes atomically**

**What A does.** Foreground compaction inserts the summary, links its source messages, and replaces the context range inside one transaction. Pending publication similarly inserts the necessary ancestor graph and changes the visible frontier in one transaction. The transaction helper rolls back exceptions. See [A: compaction.ts:2324](lossless-claw v1.0.0 src/compaction.ts:2324), [pending-summary-publisher.ts:126](lossless-claw v1.0.0 src/pending-summary-publisher.ts:126), and [transaction-mutex.ts:166](lossless-claw v1.0.0 src/transaction-mutex.ts:166).

Claw also checks whether the pending batch’s source range and fingerprint remain valid before publication: [A: pending-summary-coordinator.ts:660](lossless-claw v1.0.0 src/pending-summary-coordinator.ts:660).

**What B does badly.** A leaf pass separately writes the node, writes its level/index metadata, performs follow-up work, and persists the frontier. `add_node()` commits independently, as does the metadata write. Lifecycle state uses another connection to the same database. See [B: compaction.py:1019](compaction.py:1019), [dag.py:250](dag.py:250), [node_meta.py:84](node_meta.py:84), [engine.py:701](engine.py:701), and [lifecycle_state.py:69](lifecycle_state.py:69).

The clearest loss-of-index failure is rotation: B advances the persisted frontier **before** writing its recovery marker. Marker read/write failures log a warning and return `None`; rotation can still return success. Repeating rotation then exits because the frontier is already ahead. See [B: engine.py:6820](engine.py:6820), [engine.py:6841](engine.py:6841), and [engine.py:6881](engine.py:6881).

An isolated fault-injection probe confirmed: ten rows, one retained tail row, a failed marker-source read, persisted frontier `9`, `ok=true`, no marker, and a subsequent no-op.

**Why it matters.** Ordinary interrupted publication can leave duplicate coverage or incomplete metadata. Rotation can additionally cause the next bootstrap to skip raw history without the promised index. The raw rows survive, but their omission is no longer represented in the prompt.

**Concrete port.** Add proposed `publication.py`. Generate summaries outside the transaction; inside one shared connection transaction, validate the expected frontier/source set, insert node and metadata, insert lineage, and advance the frontier. Introduce narrow transaction-aware hooks in `dag.py`, `node_meta.py`, and `lifecycle_state.py`; wrapping independently committing connections is insufficient.

Rotation must either publish its marker and frontier together or leave the frontier unchanged. Keep B’s useful per-pass progress behavior: each completed leaf can commit independently, but each leaf’s publication must be indivisible.

Extend the existing rotation test, currently a successful-path test at [B: test_marked_loss.py:240](tests/fork/test_marked_loss.py:240), with failures after every write step, restart/retry, stale concurrent publication, and marker-repair handling for existing gaps.

**Effort: medium–large. Value: critical.**

**3. Enforce source relationships and make structural verification exhaustive**

**What A does.** Claw stores ordered message and summary edges in relational tables. Referenced messages and child summaries have `ON DELETE RESTRICT`, and connections enable foreign keys. Its deletion helper additionally checks canonical and pending references. See [A: migration.ts:1256](lossless-claw v1.0.0 src/db/migration.ts:1256), [connection.ts:50](lossless-claw v1.0.0 src/db/connection.ts:50), and [conversation-store.ts:1945](lossless-claw v1.0.0 src/store/conversation-store.ts:1945).

A useful repair pattern also exists: perform changes transactionally, run SQLite integrity checks, reject newly introduced foreign-key violations, and verify repair-specific postconditions before commit. The transferable part is that validation pattern, not OpenClaw’s rollover policy: [A: lcm-doctor-rollover-splits.ts:842](lossless-claw v1.0.0 src/plugin/lcm-doctor-rollover-splits.ts:842).

**What B does badly.** B stores `source_ids` as JSON text and inserts them without validating referenced rows. Its orphan check tests message-source nodes only; nodes referencing missing child summaries are ignored. Furthermore, the purported “all nodes” scan inherits a default limit of 1,000. See [B: dag.py:187](dag.py:187), [dag.py:250](dag.py:250), [tools.py:6835](tools.py:6835), and [dag.py:463](dag.py:463).

The fork’s semantic coverage heuristic has separate blind spots:

- Missing source rows/children are skipped; source text is capped at 400,000 characters: [B: coverage_doctor.py:82](coverage_doctor.py:82).
- Entity extraction returns at most 400 entities: [B: coverage_doctor.py:32](coverage_doctor.py:32).
- The default scan covers 200 nodes; no evidence produces an aggregate fraction of `1.0`, which can pass: [B: coverage_doctor.py:124](coverage_doctor.py:124).

An in-memory probe inserted a node referencing nonexistent child `999999`. Insertion succeeded, and coverage returned `scored_nodes=0`, `aggregate_fraction=1.0`, status `pass`.

**Why it matters.** A positive coverage score must not conceal broken provenance. B’s module correctly describes its semantic check as a heuristic, not a proof; nevertheless, structural failure and insufficient evidence need independent failure states. See [B: coverage_doctor.py:1](coverage_doctor.py:1). Claw’s foreign keys prove only the enforced relational properties—not semantic completeness, acyclicity, or ingestion of every host message.

**Concrete port.** Add proposed `provenance.py` with additive, ordered relational edge tables, initially mirrored from existing JSON. Backfill without deleting or rewriting historical nodes; report invalid existing edges explicitly. Publish new edges in the transaction from finding 2, and validate source existence, type, ordering, and cycles.

Extend `coverage_doctor.py` with a separate structural report covering complete reachable graphs, referenced payload availability, and raw spans skipped by the frontier without representation. Pagination limits must control work per page, never silently bound the total audit. Report `incomplete` when interrupted. Keep semantic sampling separately labeled, including its sampled node/character/entity counts.

Extend [B: test_coverage_doctor.py:44](tests/fork/test_coverage_doctor.py:44) with missing child/message rows, cycles, absent payloads, frontier gaps, corruption beyond the current limits, and idempotent additive backfills. Zero evidence must not certify coverage.

**Effort: medium–large. Value: critical.**

**4. Preserve already-stored raw bodies when adding payload stubs**

**What A does.** Claw’s implemented blob-migration path writes the original content to a file and adds a `large_content` reference while retaining `messages.content`. Prompt assembly substitutes a stub in its resolved message representation. If the migrated file disappears, retrieval can recover the original from the message row. See [A: lcm-blob-migrate.mjs:311](lossless-claw v1.0.0 scripts/lcm-blob-migrate.mjs:311), [assembler.ts:1081](lossless-claw v1.0.0 src/assembler.ts:1081), and [retrieval.ts:322](lossless-claw v1.0.0 src/retrieval.ts:322).

This advantage applies specifically to that migration path; it is not a claim that every claw externalization retains an inline duplicate.

**What B does badly.** With optional transcript GC enabled, B replaces a stored tool-result body with a placeholder. Its lookup tries a sanitized version of the stored body **before** the original, and accepts the first match. The payload finder verifies equality against that candidate, not necessarily against the original stored row. See [B: engine.py:5155](engine.py:5155), [engine.py:5205](engine.py:5205), [externalize.py:1884](externalize.py:1884), and [store.py:592](store.py:592).

That sanitizer can remove whole injected-context blocks: [B: extraction.py:232](extraction.py:232). A probe supplying a matching sanitized-only legacy payload confirmed that GC invokes the destructive row rewrite without establishing an exact recovery source for the original.

The condition matters: GC is optional, and the current serializer externalizes its content before this sanitization step. This is not a claim that every newly externalized row loses bytes. See [B: engine.py:5240](engine.py:5240).

**Why it matters.** Sanitization appropriate for summarizer input is not sufficient evidence for deleting persisted text. Under your yardstick, even content classified as injected context must remain recoverable once stored.

**Concrete port.** Immediately require exact equality with the original stored body before any existing GC rewrite. Prefer proposed `payload_provenance.py`: retain the raw row and store replay-stub metadata separately, following claw’s separation between storage and prompt representation. If database-size reduction is essential, move the exact original into a durable SQLite payload/version table atomically.

Hook `_maybe_gc_compacted_tool_results`, `gc_externalized_tool_result`, replay stubbing, and payload hydration. Retain B’s paginated recovery rather than copying claw’s potentially unbounded database fallback.

Add `tests/fork/test_payload_provenance.py` for sanitized-only matches, exact matches, failed/missing files, Unicode round trips, pinned rows, and consistency of FTS/chunk references.

**Effort: small for the immediate guard; medium for storage separation. Value: high when GC is enabled.**

**5. Give externalized payloads a content index, not merely a reference and opening fragment**

**What A does.** Claw persists an exploration summary beside the externalized file and includes it in the reference. Code exploration extracts definitions/imports; text exploration considers section headers and start/middle/end samples. Its deterministic fallback still includes headings and opening/closing excerpts. See [A: large-file-interceptor.ts:660](lossless-claw v1.0.0 src/large-file-interceptor.ts:660), [large-files.ts:318](lossless-claw v1.0.0 src/large-files.ts:318), [large-files.ts:349](lossless-claw v1.0.0 src/large-files.ts:349), and [large-files.ts:515](lossless-claw v1.0.0 src/large-files.ts:515).

**What B does badly.** B’s generic placeholder contains identity and size metadata. The fork-added content preview is a fixed first 240 characters; ingestion can persist the bare placeholder, and active stubbing skips already-placeholder content. See [B: externalize.py:897](externalize.py:897), [marked_loss.py:50](marked_loss.py:50), [ingest_protection.py:1469](ingest_protection.py:1469), and [engine.py:5457](engine.py:5457).

The summary’s index sidecar merely extracts what the summarizer already wrote; it cannot introduce topics hidden from its input: [B: node_meta.py:61](node_meta.py:61).

**Why it matters.** Large logs or datasets can share identical openings while differing in decisive errors, decisions, or sections much later. A recoverable reference whose contents cannot be distinguished fails your index requirement. Claw improves discoverability, although its own sampling and definition caps still do not guarantee complete semantic coverage.

**Concrete port.** Add proposed `payload_index.py`. Before replacement, derive and persist a deterministic catalog from the full payload: sections, definitions, schema fields, distinctive errors/entities, and source offsets. Expose a paginated catalog plus a compact prompt synopsis. Label incomplete catalog construction explicitly.

Hook `maybe_externalize_payload`, `externalize_ingest_payload`, ingest protection, serializer/stub generation, and recovery tools. Existing placeholders must resolve their saved catalog after restart.

Keep the full catalog outside the prompt. Put any increased synopsis budget through `window_scaling.py`, preserving the low-window prompt budget and smoothly increasing it toward 1M using B’s existing interpolation machinery: [B: window_scaling.py:58](window_scaling.py:58), [window_scaling.py:111](window_scaling.py:111).

Add `tests/fork/test_payload_index.py`: identical first 240 characters with different later topics, huge single-line payloads, malformed structured data, unavailable LLM, restart/recovery, and low/midpoint/1M budget behavior.

**Effort: medium. Value: high, especially at 1M.**

**6. Repair degraded summaries from their preserved sources**

**What A does.** Claw has an actual source-based summary repair workflow. It recognizes fallback/truncation markers, processes leaves before condensed targets, reconstructs ordered source text, and lets repaired child text feed subsequent parent repairs. It rejects empty or still-marked replacements and updates summaries plus FTS transactionally. See [A: lcm-doctor-shared.ts:68](lossless-claw v1.0.0 src/plugin/lcm-doctor-shared.ts:68), [lcm-doctor-apply.ts:257](lossless-claw v1.0.0 src/plugin/lcm-doctor-apply.ts:257), [lcm-doctor-apply.ts:331](lossless-claw v1.0.0 src/plugin/lcm-doctor-apply.ts:331), [lcm-doctor-apply.ts:90](lossless-claw v1.0.0 src/plugin/lcm-doctor-apply.ts:90), and [lcm-doctor-apply.ts:176](lossless-claw v1.0.0 src/plugin/lcm-doctor-apply.ts:176).

**What B lacks in this workflow.** B diagnoses weak summaries and reports coverage, but its doctor repair command repairs FTS indexes rather than regenerating the flagged summaries. Removing deterministic L3 prevents new instances on that escalation path; it does not repair historical degraded nodes. See [B: tools.py:6858](tools.py:6858), [coverage_doctor.py:105](coverage_doctor.py:105), [command.py:976](command.py:976), and [escalation.py:629](escalation.py:629).

**Why it matters.** Preserved raw history makes recovery possible, but a defective historical index remains defective until regenerated. Condensing that defective text again cannot recover information absent from it.

**Concrete port.** Add proposed `summary_repair.py`, exposed through a targeted doctor repair option. Verify lineage first, reconstruct and hydrate original sources, then regenerate selected leaves and affected ancestors using B’s existing weighted budgets and failure handling.

Adapt claw’s update behavior: claw overwrites summary content; B should first preserve the previous summary and metadata in an append-only revision table. Publish the replacement and updated metadata atomically while retaining node IDs and source edges. Rebuild or mark affected derived indexes stale.

Add `tests/fork/test_summary_repair.py` covering historical L3, insufficient indexes, repaired child-to-parent propagation, unchanged raw hashes/edges, preserved revisions, failed generation/publication, and bounded work at 256k and 1M.

**Effort: medium–large. Value: high.**
