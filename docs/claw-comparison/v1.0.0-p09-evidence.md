## A. Per-file verdicts

The three most consequential results are:

- **“Sufficient” and “complete” are not reliable certificates.** The subsystem can close an unspecified total after finding two operands, treat repeated mentions as distinct-event coverage, and certify unrelated quotes as answering named facets. These are answer-contract failures even when every source row survives. [answer_contract.py:587](answer_contract.py:587), [evidence_compiler.py:1232](evidence_compiler.py:1232), [evidence_compiler.py:1259](evidence_compiler.py:1259)
- **Limits can change the answer or erase its recovery information.** Diversity filtering runs before latest selection; response overflow can discard all evidence handles; compiler overflow can even report that a successfully published view was never requested. [evidence_pack.py:835](evidence_pack.py:835), [evidence_pack.py:889](evidence_pack.py:889), [evidence_compiler.py:895](evidence_compiler.py:895)
- **The exposed tools are affected despite automatic pre-answer evidence being off.** Both proposal and automatic compilation are callable through `lcm_compile_evidence`; neither requires enabling the automatic host hook. [README.md:331](README.md:331), [tools.py:924](tools.py:924)

I found **43 numbered findings**. Some concern related failures at separately owned boundaries; they are not 43 unrelated root causes.

### 1. `evidence_compiler.py`

**Responsibility:** Derive an evidence request, constrain and validate a selector proposal, ground selected spans, assign sufficiency, and optionally publish a query view. [evidence_compiler.py:1036](evidence_compiler.py:1036), [evidence_compiler.py:1073](evidence_compiler.py:1073)

**EC1 — Baseline and retrieval bounds silently discard candidates and query content.**  
**Trigger: P**, exceeding `max_input_refs`—default 40—or supplying invalid/duplicate entries before useful ones; retrieval additionally requires missing facets. `_normalize_baseline_refs` slices before validation and deduplication. Forty invalid entries followed by one valid reference produced an empty baseline, without a rejection or omission receipt. The receipt hashes only retained references. Retrieval separately slices the query to 1,000 characters and stops collecting novel references without identifying omitted results or a continuation. This can hide the only relevant source while making the reduced inventory look ordinary. [evidence_compiler.py:340](evidence_compiler.py:340), [evidence_compiler.py:745](evidence_compiler.py:745), [evidence_compiler.py:768](evidence_compiler.py:768), [evidence_compiler.py:837](evidence_compiler.py:837)

**EC2 — Finite coverage counts spans, not distinct requested operands or events.**  
**Trigger: P**, an exhaustive request with an expected cardinality. `finite_coverage` requires the expected number of distinct `exact_ref` strings, but no distinct-event proof or correspondence to each requested entity. Two spans repeating the same Atlas event produced `finite_coverage=True` for a two-event question. Separately, nine or more quoted operands are reduced to eight, and explicit cardinality does not always make a non-arithmetic request exhaustive. Thus both the requested set and its coverage certificate can be wrong. [evidence_compiler.py:80](evidence_compiler.py:80), [evidence_compiler.py:306](evidence_compiler.py:306), [evidence_compiler.py:1232](evidence_compiler.py:1232)

**EC3 — Exact quotation is promoted into semantic answer sufficiency.**  
**Trigger: P**, a syntactically valid proposal assigning requested facet names to exact source quotes. Validation checks optional entity/value/unit/key membership, but does not establish that a quote actually supports the assigned facet. Coverage then counts the selector’s facet labels. In a probe, “Bananas are yellow.” assigned to decision, rationale and owner yielded `answer_sufficient`, no missing facets and no rejections for “Who owns Atlas and why was it approved?” The source is recoverable, but the index falsely describes what it establishes. [evidence_compiler.py:574](evidence_compiler.py:574), [evidence_compiler.py:669](evidence_compiler.py:669), [evidence_compiler.py:1178](evidence_compiler.py:1178), [evidence_compiler.py:1259](evidence_compiler.py:1259)

**EC4 — The derived temporal window is not enforced on delivered evidence.**  
**Trigger: P**, a date-filter question with a valid question date. The request records its temporal window, but claim validation passes only the question and as-of date to the pack; its explicit date check verifies source support, not membership in the requested window. The compiler subsequently delivers the validated list. “What happened five days ago?” anchored at 2024-03-20 accepted an event on 2024-03-01 and returned `answer_sufficient`, although the requested window was March 15–16. [evidence_compiler.py:332](evidence_compiler.py:332), [evidence_compiler.py:617](evidence_compiler.py:617), [evidence_compiler.py:650](evidence_compiler.py:650), [evidence_compiler.py:1197](evidence_compiler.py:1197)

**EC5 — Latest selection collapses independent facets and leaves stale completeness.**  
**Trigger: P**, `latest_fact` with evidence for multiple independently changing facts. Missing facets are calculated before the compiler retains only the single selected latest reference. Every other validated reference becomes historical, regardless of whether it concerns the same fact. A current-owner-and-deadline probe moved the owner into historical evidence because the deadline was newer, while retaining `answer_sufficient` and `missing_facets=[]`. With persistence enabled, that stale state can also determine a view’s `complete` classification. [evidence_compiler.py:1178](evidence_compiler.py:1178), [evidence_compiler.py:1217](evidence_compiler.py:1217), [evidence_compiler.py:996](evidence_compiler.py:996)

**EC6 — Compiler and pack can execute different interpretations of the same request.**  
**Trigger: P**, a question that the compiler remaps from `count_distinct` to `sum` or `scalar_fact`. The compiler changes the operation, but passes the original question into the pack, which derives its own older plan. For “How many hours do I need?”, a validated seven-hour value returned with empty numeric facets because the pack still interpreted the question as a count and removed value/unit. The compiler nevertheless reported finite coverage. The original quote survives, but the typed evidence contract silently loses information. [evidence_compiler.py:247](evidence_compiler.py:247), [evidence_compiler.py:617](evidence_compiler.py:617), [evidence_compiler.py:1199](evidence_compiler.py:1199), [evidence_pack.py:700](evidence_pack.py:700), [evidence_pack.py:414](evidence_pack.py:414)

**EC7 — Response fallback erases recovery information and can misreport committed state.**  
**Trigger: P**, serialization failure or output exceeding the configured response cap; the probe used the supported 4,096-character cap. `_finish` replaces the result with a fresh empty base: request, evidence handles, rejection details, retrieval receipt and original trace disappear; the baseline count becomes zero. More seriously, publication happens before `_finish`. With `persist_view=True` and an available query-view store, a probe observed one successful publication followed by `persisted=False`, `requested=False` and no view ID in the returned fallback. A generic truncation flag cannot recover the discarded result or accurately describe the mutation. Query-view storage is an additional opt-in, so that persistence variant is not enabled by the documented defaults. [evidence_compiler.py:866](evidence_compiler.py:866), [evidence_compiler.py:837](evidence_compiler.py:837), [evidence_compiler.py:1002](evidence_compiler.py:1002), [evidence_compiler.py:1282](evidence_compiler.py:1282)

**EC8 — Retrieval failure metadata becomes ordinary “no progress.”**  
**Trigger: P**, missing facets and a retrieval response containing timeout/degradation metadata without a top-level `error`. Only mapping shape and `error` are checked; missing or malformed hits become an empty iteration. `{"timeout": true}` produced `no_progress`. Returned metadata omits timeout, degradation and response-truncation information that real `lcm_recall` responses expose. The caller cannot distinguish unsuccessful coverage from a completed search finding nothing useful. [evidence_compiler.py:753](evidence_compiler.py:753), [evidence_compiler.py:768](evidence_compiler.py:768), [evidence_compiler.py:782](evidence_compiler.py:782), [tools.py:5190](tools.py:5190)

**EC9 — Evidence tuning does not participate in window scaling.**  
**Trigger: P**, larger context windows with default evidence budgets. The 40-reference, 8,192-character proposal, 2,400-character quote and 64,000-character response defaults are resolved without a window or effective-scale input. Window probes at 262,144, 512,000 and 1,000,000 kept the compiler response cap at 64,000, despite the fork’s tool-response scale having anchors of 1 and 4. These presentation/admission preferences therefore impose the same bottleneck at 1M. This is separate from the correctness defects caused by what happens when those bounds are reached. [evidence_compiler.py:128](evidence_compiler.py:128), [evidence_compiler.py:159](evidence_compiler.py:159), [window_scaling.py:95](window_scaling.py:95)

**EC10 — Source-read failures escape the compiler and exposed evidence tools.**  
**Trigger: P or E**, a store exception during source hydration or grounding. The compiler catches selector exceptions but not the subsequent claim-validation/pack calls. The pack likewise reads and grounds outside a source-error boundary; the exposed tool wrappers call these functions directly. Injecting `sqlite3.OperationalError` into the real store seam caused both APIs to raise it rather than return a structured failed-evidence result with affected references. This is an availability/error-contract defect; the probe did not demonstrate database corruption or raw-message deletion. [evidence_compiler.py:1116](evidence_compiler.py:1116), [evidence_compiler.py:1148](evidence_compiler.py:1148), [evidence_pack.py:330](evidence_pack.py:330), [evidence_pack.py:763](evidence_pack.py:763), [tools.py:917](tools.py:917)

**Checked and not reported as violations:** Oversized/malformed proposals and secret-pattern proposals are explicitly rejected; the latter is not raw-message redaction. Missing facets did block exhaustive arithmetic in the tested path. Publication busy/error/stale outcomes are distinguished before the EC7 finalization problem. Repeated source materialization is covered under shared finding EP7 below. [evidence_compiler.py:396](evidence_compiler.py:396), [evidence_compiler.py:1245](evidence_compiler.py:1245), [evidence_compiler.py:1009](evidence_compiler.py:1009)

### 2. `evidence_pack.py`

**Responsibility:** Resolve exact source spans, ground typed operands, evaluate completeness and computations, select latest evidence, and serialize the packet. [evidence_pack.py:700](evidence_pack.py:700)

**EP1 — A capped candidate population can still receive a closed, product-verified computation.**  
**Trigger: E**, more input references than `max_refs`; indirectly P when its combined pack reaches this situation. Input slicing precedes validation and deduplication. Completeness receives grounded/rejected counts but not the omitted-candidate count. A two-cost probe with `$10`, `$20`, then a `$99` correction, and `max_refs=2`, computed `$30` with closed/product-verified completeness while also setting `refs_truncated=True`. The flag neither invalidates closure nor names the omitted candidates. Retrieval’s separate novel-reference cap similarly lacks an omission manifest. [evidence_pack.py:460](evidence_pack.py:460), [evidence_pack.py:714](evidence_pack.py:714), [evidence_pack.py:792](evidence_pack.py:792), [evidence_pack.py:816](evidence_pack.py:816), [evidence_pack.py:578](evidence_pack.py:578)

**EP2 — Diversity limits remove newer evidence before latest selection.**  
**Trigger: E or P**, more than five relevant candidates from one session or observation date, including a latest-fact request. Diversity selection walks input order and drops quota excess before `_latest_selection`. Six chronological office updates from one session caused the sixth/newest update to disappear and the fifth to be selected as latest. Only a drop count survived; all truncation flags remained false, with no references identifying the excluded evidence. This directly changes the answer rather than merely shortening presentation. [evidence_pack.py:144](evidence_pack.py:144), [evidence_pack.py:497](evidence_pack.py:497), [evidence_pack.py:835](evidence_pack.py:835), [evidence_pack.py:860](evidence_pack.py:860), [evidence_pack.py:884](evidence_pack.py:884)

**EP3 — Latest selection discards available sub-day ordering.**  
**Trigger: E or P**, latest candidates on the same date with distinguishable source timestamps. Observation metadata retains `observed_at`, but selection compares date strings only. A 09:00 Berlin update followed by an 18:00 Paris update returned `latest_candidates_tied`. This is an explicit fallback, not a falsely selected answer, but the fallback is caused by throwing away usable temporal precision. [evidence_pack.py:298](evidence_pack.py:298), [evidence_pack.py:631](evidence_pack.py:631), [evidence_pack.py:662](evidence_pack.py:662)

**EP4 — Response overflow removes all evidence and computation recovery handles.**  
**Trigger: E**, a serialized packet exceeding 64,000 characters. The fallback empties evidence and clears computation and latest selection. A further fallback cuts rejection/exclusion lists to ten and empties retrieval references. Although `response_truncated=True` honestly signals a problem, there is no manifest or continuation naming the discarded evidence. A default-reference-count probe using long, individually valid quotes returned an empty-evidence fallback despite having resolved 25 candidates. [evidence_pack.py:889](evidence_pack.py:889), [evidence_pack.py:900](evidence_pack.py:900), [evidence_pack.py:906](evidence_pack.py:906)

**EP5 — Retrieval timeout/degradation is flattened, and diagnostic text is clipped.**  
**Trigger: E**, an incomplete evidence plan that invokes retrieval. `_run_retrieval_probe` recognizes top-level errors but not timeout/degraded status; `{"timeout": true}` returned `no_progress`. It preserves a coverage subobject, but that does not preserve the separate failure/truncation fields. Error strings are also sliced to 300 characters without a clipping marker or full diagnostic handle. Search failure and incomplete coverage can therefore be mistaken for normal exhaustion. [evidence_pack.py:560](evidence_pack.py:560), [evidence_pack.py:598](evidence_pack.py:598), [evidence_pack.py:620](evidence_pack.py:620)

**EP6 — Pack capacity remains fixed at 1M.**  
**Trigger: E**, larger windows with default budgets. Reference, quote, diversity and response limits are local constants/resolutions without the engine’s effective window scale. The response cap remained 64,000 throughout the window probe, and per-session admission remains capped at five. These preferences constrain how much of a million-token history can be represented, despite the existing tool-response scaling policy. [evidence_pack.py:32](evidence_pack.py:32), [evidence_pack.py:117](evidence_pack.py:117), [evidence_pack.py:889](evidence_pack.py:889), [window_scaling.py:95](window_scaling.py:95)

**EP7 — Small spans repeatedly materialize entire large source rows.**  
**Trigger: E or P**, several references into large messages; no optional feature required. Candidate resolution loads the full row before slicing, then `ground_evidence` loads it again. The compiler performs individual packs and another combined pack. A real-function probe with 40 four-character references into one million-character row recorded **160 store reads requesting 160 million source characters**. This measures requested materialization, not peak memory or elapsed time. The real store selects the full row, so the pattern creates avoidable I/O/allocation pressure precisely when large-window histories become valuable. [evidence_pack.py:330](evidence_pack.py:330), [evidence_pack.py:763](evidence_pack.py:763), [reasoning.py:793](reasoning.py:793), [store.py:652](store.py:652), [evidence_compiler.py:617](evidence_compiler.py:617), [evidence_compiler.py:1199](evidence_compiler.py:1199)

**EP8 — Unicode case folding bypasses the apparent no-truncation key/unit guards.**  
**Trigger: E**, or a caller supplying such facets, with Unicode whose case-folded representation grows. Raw key/unit lengths are checked before canonicalization; canonicalization then slices to 300/100 characters. A key and source quote consisting of 150 `ß` characters followed by ` alpha` passed the raw-length guard, but its canonical key became 300 `s` characters, losing `alpha` with all truncation flags false. Distinct source identities can consequently collapse. The raw guard is therefore not sufficient evidence that these slices are unreachable. [evidence_pack.py:233](evidence_pack.py:233), [evidence_pack.py:242](evidence_pack.py:242), [evidence_pack.py:399](evidence_pack.py:399)

**Shared failure:** EC10 also applies directly to this file’s source-resolution and grounding boundary; the direct pack probe propagated the injected `OperationalError`. [evidence_pack.py:330](evidence_pack.py:330), [evidence_pack.py:763](evidence_pack.py:763)

**Checked and not reported as violations:** An oversized quote is rejected rather than sliced; unique-quote repair stays within the declared source window and rejects ambiguity. Occurrence and observation metadata are separate, and latest selection refuses an ingestion-only time basis. Whole-cohort grounding failure is explicitly identified as `operand_grounding_failed`; it is not an ordinary successful empty result. [evidence_pack.py:343](evidence_pack.py:343), [evidence_pack.py:438](evidence_pack.py:438), [evidence_pack.py:650](evidence_pack.py:650), [evidence_pack.py:774](evidence_pack.py:774)

### 3. `preanswer_evidence.py`

**Responsibility:** Build an optional deterministic pre-answer augmentation from baseline evidence and one retrieval delta, producing a computation or novel latest-state evidence. [preanswer_evidence.py:481](preanswer_evidence.py:481), [preanswer_evidence.py:707](preanswer_evidence.py:707)

**PA1 — Admission silently loses baseline entries and can discard the entire useful retrieval delta.**  
**Trigger: D**, exceeding the baseline cap, supplying invalid/unhydratable references, or retrieving novel evidence after a full baseline. Normalization slices before deduplication; preparation silently omits failed hydration. Later, baseline plus novel evidence is repacked under the same input cap. With 25 baseline entries and a valid newer retrieved update, the update fell beyond the pack cap: the helper returned `delta_validation_failed` while retrieval said `novel` and its trace said `truncated=False`. It does not propagate the pack’s omitted-reference information. [preanswer_evidence.py:181](preanswer_evidence.py:181), [preanswer_evidence.py:306](preanswer_evidence.py:306), [preanswer_evidence.py:378](preanswer_evidence.py:378), [preanswer_evidence.py:669](preanswer_evidence.py:669), [preanswer_evidence.py:711](preanswer_evidence.py:711)

**PA2 — A supplied exact quote is replaced by the whole declared window.**  
**Trigger: D**, a reference containing a useful short quote within a larger declared span. `_automatic_candidate` ignores the supplied quote and hydrates the entire window. A 2,616-character window containing the supplied quote “Atlas cost $10.” became a 2,616-character candidate, which exceeds the pack’s quote limit. Larger windows containing multiple numbers can also lose otherwise unambiguous numeric extraction. This discards useful evidence that the pack’s unique-quote-within-window resolver could accept. [preanswer_evidence.py:273](preanswer_evidence.py:273), [preanswer_evidence.py:249](preanswer_evidence.py:249), [evidence_pack.py:343](evidence_pack.py:343)

**PA3 — Automatically derived identities and event labels are lossy.**  
**Trigger: D**, count/order/date-filter questions without caller-supplied facets. Event keys retain only matched alphabetic words and then take 300 characters; labels take the first 300 source characters. “Atlas visit 2024” and “Atlas visit 2025” acquire the same key. A three-event ordering probe produced a computed result with labels ending mid-word and omitting the distinguishing project noun. Exact references survive, but the displayed index does not mark or explain the clipped labels. The key collision can also defeat distinctness; it should not be described as a proven wrong count in every case because downstream counting sometimes refuses the cohort. [preanswer_evidence.py:266](preanswer_evidence.py:266), [preanswer_evidence.py:293](preanswer_evidence.py:293), [preanswer_evidence.py:302](preanswer_evidence.py:302)

**PA4 — “Exact evidence” rendering changes source bytes and leaves delimiter ambiguity.**  
**Trigger: D**, novel evidence containing meaningful whitespace or the enclosing tag text. `_render_evidence` collapses all whitespace before presenting a quote as exact evidence, losing indentation and line boundaries. It also interpolates source text containing `</lcm-preanswer-evidence>` without escaping it. A probe reproduced both transformations. Recovery through the exact reference remains possible, but the display transformation is unmarked and historical content can mimic the surrounding envelope boundary. This establishes malformed/ambiguous framing, not a demonstrated model-level injection exploit. [preanswer_evidence.py:409](preanswer_evidence.py:409)

**PA5 — Context overflow discards the successful structured result too.**  
**Trigger: D**, a valid computation/evidence augmentation whose rendered context exceeds `max_context_chars`; the supported minimum of 256 readily reaches this. `_finalize_success` checks size before storing evidence, computation and novel-reference results. A long three-event ordering returned `context_budget_exhausted` and a truncation flag, but empty evidence and no computation. The caller receives neither the full structured result nor a manifest identifying how to recover it. [preanswer_evidence.py:427](preanswer_evidence.py:427)

**PA6 — Preparation and grounding do not satisfy the advertised failure containment.**  
**Trigger: D**, a source-store or grounding exception. The helper promises baseline retention with no augmentation on failure, but normalization/preparation and both pack calls lie outside the retrieval exception handler. Injecting a source-read `OperationalError` propagated the exception. A direct caller relying on this API’s documented fallback behavior can therefore fail its pre-answer stage instead of receiving `context=None` plus a failure receipt. This is dormant in the current host routing. [preanswer_evidence.py:481](preanswer_evidence.py:481), [preanswer_evidence.py:536](preanswer_evidence.py:536), [preanswer_evidence.py:565](preanswer_evidence.py:565), [preanswer_evidence.py:616](preanswer_evidence.py:616), [preanswer_evidence.py:712](preanswer_evidence.py:712)

**PA7 — Malformed or degraded retrieval becomes ordinary `no_hit`; diagnostic tails disappear.**  
**Trigger: D**, retrieval returning a mapping with missing/wrong-type hits, or degraded empty coverage without `timeout`/`error`. `{}` and a degraded empty-hit response both became `no_hit`. The helper does recognize explicit timeout and error fields, so this is narrower than EC8. It nevertheless drops other completeness/degradation metadata and clips exception/error text to 300 characters without a recovery marker. [preanswer_evidence.py:628](preanswer_evidence.py:628), [preanswer_evidence.py:632](preanswer_evidence.py:632), [preanswer_evidence.py:649](preanswer_evidence.py:649), [preanswer_evidence.py:654](preanswer_evidence.py:654)

**PA8 — Its evidence and presentation preferences have no window curve.**  
**Trigger: D**, use at larger context windows. Defaults remain one retrieval, four novel references, 25 input references and 8,000 context characters, with a 16,000-character maximum. No window enters budget resolution; the window matrix kept the context default at 8,000. These are evidence admission/presentation preferences, rather than intrinsic arithmetic proof limits, and need an explicit scaling policy if this helper is retained for use. [preanswer_evidence.py:79](preanswer_evidence.py:79), [preanswer_evidence.py:104](preanswer_evidence.py:104)

### 4. `answer_contract.py`

**Responsibility:** Turn a question into a deterministic operation, answer type, evidence slots, cardinality, units and temporal constraints consumed by the requirements compiler. [answer_contract.py:533](answer_contract.py:533)

**AC1 — The compiler invents a finite two-operand scope.**  
**Trigger: R**, totals or order requests without a proven finite operand list, or operand lists outside the parser’s supported size. Sum sets cardinality to `len(named) or finite or 2`; unnamed arithmetic/order slots likewise default to two. “What is the total cost?” compiled into two unanchored fixed operands. With only `$10` and `$20` supplied, the real requirements compiler returned `computation_sufficient` and `$30`, despite no proof that the question’s total had two contributors. A tested nine-quoted-operand request also fell back to two instead of reporting unsupported scope. [answer_contract.py:344](answer_contract.py:344), [answer_contract.py:587](answer_contract.py:587), [answer_contract.py:674](answer_contract.py:674)

**AC2 — Numbers belonging to a duration or other phrase become operand cardinality.**  
**Trigger: R**, a question containing a numeric phrase that does not enumerate the requested operands. `_explicit_cardinality` accepts an arbitrary number-plus-word phrase, and `both` anywhere implies two. “What is the total cost in the last seven days?” became seven fixed operands. That changes a temporal constraint into a completeness requirement: seven retrieved items can appear to close a set whose true size is unknown, while a correct differently sized set can be rejected. [answer_contract.py:318](answer_contract.py:318), [answer_contract.py:559](answer_contract.py:559), [answer_contract.py:593](answer_contract.py:593)

**AC3 — Anchor shortening silently changes entity identity.**  
**Trigger: R**, long named operands, many anchors, or long quoted subjects. `_clean_operand` keeps only the last four tokens; `_anchors` keeps twelve entries, while quoted-phrase recognizers have independent 120/160-character bounds. “North region Atlas maintenance fee” and “South region Atlas maintenance fee” both became “region atlas maintenance fee.” A long question likewise lost later anchors without an omitted-anchor receipt. The resulting high-confidence contract can seek or match the wrong entity while concealing what was discarded. [answer_contract.py:301](answer_contract.py:301), [answer_contract.py:334](answer_contract.py:334), [answer_contract.py:344](answer_contract.py:344), [answer_contract.py:716](answer_contract.py:716)

**AC4 — Explicit calendar constraints are ignored or rewritten to another year.**  
**Trigger: R**, an explicit month/year or ISO date. Named-month parsing ignores an accompanying year and chooses the nearest past occurrence relative to the as-of date. “Where did I travel in March 2024?” anchored at 2026-09-08 produced March 2026. An explicit “on 2024-03-10” produced no temporal window in the tested contract. Moreover, `_time_window` does no work without an as-of date, including for absolute dates that should not require one. A source can therefore satisfy a contract for a different period than the user requested. [answer_contract.py:459](answer_contract.py:459), [answer_contract.py:497](answer_contract.py:497), [answer_contract.py:638](answer_contract.py:638)

**AC5 — Relative-time recognition is incomplete, and boundary arithmetic is unchecked.**  
**Trigger: R**, expressions such as “today” or “last 7 days,” missing as-of input, or zero/extreme intervals. The preliminary relative-expression recognizer misses supported-looking forms, so “last 7 days” without an anchor can become an unscoped ordinary contract; “today” also lost its temporal constraint in the probe. “Last 0 days” created an empty future-boundary window. Very large day counts raised `OverflowError`; “last year” at year 0001 raised `ValueError`. These cases require explicit unsupported/invalid outcomes, not high-confidence unscoped contracts or escaping exceptions. [answer_contract.py:131](answer_contract.py:131), [answer_contract.py:466](answer_contract.py:466), [answer_contract.py:513](answer_contract.py:513), [answer_contract.py:549](answer_contract.py:549)

**AC6 — Operation precedence removes current/previous and elapsed-time requirements.**  
**Trigger: R**, scalar questions with state qualifiers, or elapsed-time wording outside the narrow interval pattern. The scalar branch precedes latest/previous selection. “How many pages did I previously have?” accepted a current-page-count source; the converse current question accepted a previous-count source. Both integration probes reached `answer_sufficient`. “How long ago did I join Atlas?” became a scalar request rather than an elapsed date calculation. These are dropped question requirements, not merely suboptimal retrieval terms. [answer_contract.py:562](answer_contract.py:562), [answer_contract.py:613](answer_contract.py:613), [answer_contract.py:634](answer_contract.py:634)

**AC7 — Unit inference assumes USD and can treat ordinary words as units.**  
**Trigger: R**, non-USD or unspecified-currency cost questions, or an unrelated number-plus-word phrase. `$`, `€`, `£` and generic “cost”/“fee” all map to `usd`. A euro-cost question therefore requested USD. The fallback unit recognizer also treated `to` in “increase from 10 to 20” as a unit. The contract may reject correct evidence or accept an answer under an invented dimension. [answer_contract.py:253](answer_contract.py:253), [answer_contract.py:293](answer_contract.py:293)

**AC8 — Compound questions are reduced to one required answer slot.**  
**Trigger: R**, a supported wh-question containing multiple independently required facts.
