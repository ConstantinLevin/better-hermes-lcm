**Aspect 4 audit: nine Claw advantages worth porting into betterlcm.** The most urgent is repairing drill-down through retained session history. The next priorities are distinguishing failed searches from empty results and correcting fallback search ordering.

I inspected the working trees at A `988dee85592b9` and B `b94daab0aa7b`, including B’s existing local changes. I modified no files. Five isolated, in-memory probes exercised B’s actual helpers; results appear below. These were targeted reproductions, not full test-suite or live-host validation.

**1. Session scope should preserve drill-down through retained history**

**What Claw does.** Its shared scope resolver includes archived conversations belonging to the current session family, while supporting explicit single-conversation and all-conversation requests. Describe checks the resolved scope; expansion follows a condensed node’s actual source-summary edges without imposing active-session equality on every descendant. See [A scope resolution](/tmp/lossless-claw-v1.0.0/src/tools/lcm-conversation-scope.ts:189), [A describe authorization](/tmp/lossless-claw-v1.0.0/src/tools/lcm-describe-tool.ts:217), and [A source traversal](/tmp/lossless-claw-v1.0.0/src/retrieval.ts:450).

**What B does.** Carry-over moves only nodes meeting the retain-depth threshold; their shallower descendants remain under the old session. Retrieval then rejects those descendants because they do not belong to the current session. Both ordinary child expansion and recursive evidence collection have this check. See [B carry-over hook](/home/agent/projects/agentimprovement/betterlcm/engine.py:3721), [B ownership update](/home/agent/projects/agentimprovement/betterlcm/dag.py:395), [B child expansion](/home/agent/projects/agentimprovement/betterlcm/tools.py:1389), and [B recursive expansion](/home/agent/projects/agentimprovement/betterlcm/tools.py:1494).

**Reproduction:** after retaining a connected depth-2 → depth-1 → depth-0 chain into a new session, describing the retained root listed its old-session child. Expanding that root returned zero children and `has_more: false`. Supplying `session_scope="all"` to describe did not help: its node lookup always uses `_get_session_node`. See [B lookup](/home/agent/projects/agentimprovement/betterlcm/tools.py:166) and [B describe branch](/home/agent/projects/agentimprovement/betterlcm/tools.py:5320).

The inconsistency also affects externalized data: cross-session raw-message expansion explicitly says that its externalized references cannot be expanded. [B externalized limitation](/home/agent/projects/agentimprovement/betterlcm/tools.py:5477)

**Why it matters.** Raw rows survive, but the retained summary stops functioning as a traversable index. Deeper hierarchies at large windows make this particularly consequential. B already has global semantic recall and cross-session raw-message expansion; the missing capability is reliable, deterministic traversal from a known retained node. [B global summary recall](/home/agent/projects/agentimprovement/betterlcm/tools.py:4445), [B raw-message expansion](/home/agent/projects/agentimprovement/betterlcm/tools.py:5450)

**Port plan.** Add a fork-owned `retrieval_scope.py`, with small hooks in `carry_over_new_session_context`, `_get_session_node`, child/evidence traversal, and externalized lookup. Persist session-family relationships through the lifecycle store. Authorize a root against the requested scope, then permit traversal of its recorded source edges across retained session boundaries. Keep unrelated-session discovery explicit. Extend `schemas.py` and the recall policy to describe the same contract.

Add connected-DAG tests under `tests/fork/`: retain depths `0`, `2`, and `-1`; repeated `/new`; restart; unrelated-session exclusion; and a descendant raw message backed by an externalized payload. Existing retain tests use nodes with empty `source_ids`, so they cannot expose this failure. [B existing fixtures and tests](/home/agent/projects/agentimprovement/betterlcm/tests/fork/test_marked_loss.py:165)

**Effort: medium–large. Value: very high.**

**3. Search failures must not become “nothing was found”**

**What Claw does.** In full-text search, FTS failure falls back to LIKE. If that fallback also fails, the failure propagates through retrieval and prevents a normal success response. [A message fallback](/tmp/lossless-claw-v1.0.0/src/store/conversation-store.ts:2004), [A summary fallback](/tmp/lossless-claw-v1.0.0/src/store/summary-store.ts:1168), [A tool awaiting retrieval](/tmp/lossless-claw-v1.0.0/src/tools/lcm-grep-tool.ts:234)

**What B does.** The default full-text path catches broad exceptions from message and summary searches, logs warnings, and then emits its ordinary result object. It does not identify either failed source in that response. [B catches](/home/agent/projects/agentimprovement/betterlcm/tools.py:2563), [B success-shaped response](/home/agent/projects/agentimprovement/betterlcm/tools.py:2788), [B default dispatch](/home/agent/projects/agentimprovement/betterlcm/tools.py:3511)

**Reproduction:** making both stores raise `sqlite3.OperationalError("database is locked")` produced `total_results: 0`, `results: []`, and no error/degraded indicator.

**Why it matters.** The agent cannot distinguish missing history from temporarily inaccessible history. That creates false negative evidence even when every raw message remains stored. Larger archives and concurrent users increase the importance of reporting incomplete work accurately.

**Port plan.** Add `retrieval_outcome.py` with explicit complete/partial/error outcomes. Hook the two full-text catches and their consumers: preserve successful hits, identify failed sources, and reserve an unqualified empty result for completed searches. Return structured failures without aborting the host turn. B already has explicit deadline handling for semantic/hybrid entry points; use that reporting discipline consistently. [B deadline handling](/home/agent/projects/agentimprovement/betterlcm/tools.py:3518)

Tests: message failure only, summary failure only, both failures, successful LIKE fallback, lock timeout, and callers consuming the partial result.

**Effort: small. Value: very high.**

**4. Apply fallback recency ordering before limiting candidates**

**What Claw does.** Its ordinary and CJK summary LIKE queries order by the summary’s search timestamp in SQL, then apply `LIMIT`. Thus recency selection occurs over the matching population. [A ordinary fallback](/tmp/lossless-claw-v1.0.0/src/store/summary-store.ts:1284), [A CJK fallback](/tmp/lossless-claw-v1.0.0/src/store/summary-store.ts:1472)

**What B does.** `SummaryDAG._search_like` fetches `LIMIT … OFFSET …` without SQL ordering, sorts those rows in Python, and ordinarily returns after that first batch. This can exclude the newest matching nodes before recency ranking begins. [B candidate query and early return](/home/agent/projects/agentimprovement/betterlcm/dag.py:692)

This is not restricted to a broken FTS installation: B deliberately routes CJK and emoji queries to LIKE. [B fallback routing](/home/agent/projects/agentimprovement/betterlcm/search_query.py:183)

**Reproduction:** inserting 100 matching summaries with increasing timestamps, then searching `部署` with `sort="recency", limit=1`, returned timestamp **50**, although timestamp **100** was present.

**Why it matters.** A request for recent information can surface an older summary and hide its correction. More accumulated history makes this candidate-selection error increasingly damaging.

**Port plan.** Put fork-owned SQL ordering helpers in `retrieval_ordering.py`, with a small hook in `dag._search_like`. For recency mode, order before limiting using B’s existing timestamp semantics and a deterministic node-ID tie-breaker. Preserve its source-filter scan behavior. Handle relevance/hybrid separately; Claw’s recency fallback is not a complete replacement for those ranking contracts.

Tests: more matches than the candidate batch, newest match outside the first insertion-order batch, timestamp ties, CJK/emoji, and source filtering. Run at low, intermediate, and 1M windows; this correction should not alter DAG construction.

**Effort: small–medium. Value: high.**

**5. A small retrieval page should cause small body reads**

**What Claw does.** Leaf expansion obtains source IDs, then fetches message bodies incrementally and stops when the response budget is exhausted. File description initially reads stored metadata; actual file content is conditional on expansion. [A incremental message reads](/tmp/lossless-claw-v1.0.0/src/retrieval.ts:481), [A metadata-first file description](/tmp/lossless-claw-v1.0.0/src/retrieval.ts:236)

**What B does.** Unless the caller supplies `source_limit`, `_expand_message_sources` passes *all remaining source IDs* to `get_batch` before checking the token budget. `get_batch` constructs one `IN` query and materializes all selected rows. Child expansion similarly loads its selected children before budgeting output. [B eager message reads](/home/agent/projects/agentimprovement/betterlcm/tools.py:1239), [B batch query](/home/agent/projects/agentimprovement/betterlcm/store.py:659), [B eager child reads](/home/agent/projects/agentimprovement/betterlcm/tools.py:1382)

**Reproduction:** expanding a 1,000-source node with a one-token page passed all 1,000 IDs to `get_batch`, while returning one message.

B also describes an externalized payload by loading and decoding the entire JSON file, then retaining a 500-character preview. [B externalized describe](/home/agent/projects/agentimprovement/betterlcm/tools.py:5297), [B full-file loader](/home/agent/projects/agentimprovement/betterlcm/externalize.py:953)

**Why it matters.** Output limits currently fail to bound much of the underlying I/O and allocation. At large windows, a cheap-looking drill-down can read a large backlog, hold database resources unnecessarily, or encounter SQLite’s parameter limit.

**Port plan.** Add `retrieval_io.py`, hooked into message/child expansion and externalized describe. Fetch bodies in small ordered batches, stop fetching when the page is complete, and preserve B’s existing content offsets. Reuse its already implemented bounded externalized-prefix reader. [B bounded reader](/home/agent/projects/agentimprovement/betterlcm/externalize.py:1137)

Test fetched-row counts, IDs beyond the connection’s variable limit, oversized first messages, exact reconstruction across pages, and bounded file reads. Use existing weighted output budgets; any new preference-sized batch tuning belongs in `window_scaling.py`.

Claw still loads the source-ID list and can read one oversized message, so this is an incremental-I/O advantage, not proof of completely bounded memory.

**Effort: medium. Value: high, especially at 1M.**
