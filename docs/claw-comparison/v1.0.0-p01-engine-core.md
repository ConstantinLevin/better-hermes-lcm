## A. **Per-file verdicts**

The three most consequential conclusions are:

- **Publication and session ownership are not reliably coupled.** A failed rotate can advance recovery state without its marker; carry-over can break expansion through descendants; late work can publish or ingest under a different session.
- **Removing L3 did not establish the no-loss contract.** There are still unmarked removals, indexes that describe only the ends of their sources, and an optional GC path that can replace an original with a reference to a sanitized version.
- **The large-window controls do not consistently implement their advertised behavior.** Default threshold application, condensation gating, frontier enumeration, deadlines and protected-tail handling all have defects.

I read all **8,043 assigned lines**, including all 6,941 lines of `engine.py`, and checked relevant dependencies, Hermes host code and A’s implementation. The report contains **41 finding groups**, including related manifestations grouped under one repair.

“Documented deployment” below means the described 1M workflow: ordinary non-sweep compaction, concurrency six, and assembly caps/deferred maintenance off. Externalization and active stubbing are recommended but their configuration defaults remain off; I have not inferred their live state from that recommendation. The configuration evidence is [README.md:129](/home/agent/projects/agentimprovement/betterlcm/README.md:129), [README.md:486](/home/agent/projects/agentimprovement/betterlcm/README.md:486), [README.md:569](/home/agent/projects/agentimprovement/betterlcm/README.md:569) and [fork-design.md:373](/home/agent/projects/agentimprovement/betterlcm/docs/fork-design.md:373).
