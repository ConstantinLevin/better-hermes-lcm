## A. Per-file verdicts

The three most consequential results are:

- **Adaptive retrieval can certify incomplete evidence as complete and finish with stale quotations.** Its completion test counts references; it does not establish that all relevant evidence was retrieved. **AD1–AD2.**
- **The assertion sidecar can publish unsupported state and then present it as current.** Confirmed examples include “completed” from an explicitly negative source, cancellation across unrelated scopes, and an expired assertion labeled current. **AE1, AE3, ST1.**
- **Provenance and recovery can break after storage succeeds.** A rollup read can combine one generation’s summary with another generation’s sources; retrieval wrappers discard continuation information; selective compilation can reassign evidence handles. **RS2, AD3, SC7.**

I read all **8,386 lines across the 12 assigned files**, inspected the relevant callers and storage contracts, and ran isolated probes against real functions using in-memory SQLite and controlled external boundaries. No repository files or on-disk databases were modified.

The findings below concern B at commit `f38ed61f2746ced66d7466e905fdd0d0d05b9318`. Comparing the assigned files against B’s recorded upstream base showed that **only `rollup_builder.py` differs**. Consequently, most findings are inherited defects under the operator’s doctrine, rather than fork-introduced regressions.

### 1. `rollup_store.py`

Responsibility: persist temporal rollups, their source-node membership, build leases, invalidations, and lifecycle transitions.

- **RS1 — Publication validation does not hold a database write transaction from its first read.** `_write_transaction()` uses the connection context manager; `mark_ready()` performs its ownership and pending-invalidation reads before its first DML statement. A source mutation can commit between validation and publication. **Trigger: T, concurrent source mutation.** A controlled interleaving returned `True` from `mark_ready()`, leaving a rollup `ready` while a covering invalidation was pending. The pending-invalidation checks in serving code mitigate exposure, but the publication invariant itself is false. [rollup_store.py:95](rollup_store.py:95), [rollup_store.py:240](rollup_store.py:240), [rollup_store.py:275](rollup_store.py:275), [rollup_store.py:310](rollup_store.py:310).

- **RS2 — A read can combine an old summary with new provenance.** `get_rollup()` fetches the main row, then `_row_to_rollup()` separately queries source IDs without a shared read snapshot. **Trigger: T, rebuild between those reads.** The probe returned `"old summary"`, generation `1`, and the replacement publication’s source ID `200`. That is incorrect provenance even though both generations were individually valid. The same shaping helper is used for window reads. [rollup_store.py:120](rollup_store.py:120), [rollup_store.py:149](rollup_store.py:149), [rollup_store.py:734](rollup_store.py:734).

Checked and cleared: generation/nonce/status predicates prevent ordinary stale-token terminal transitions; bounded invalidation draining retains continuation state instead of silently discarding the remaining events. These protections do not close RS1’s transaction gap. [rollup_store.py:382](rollup_store.py:382), [rollup_store.py:647](rollup_store.py:647).

### 2. `rollup_builder.py`

Responsibility: select canonical temporal sources, summarize day/week/month rollups, and schedule bounded maintenance work.

- **RB1 — A complete rollup must still meet a hard acceptance cap.** `_summarize_capped()` repeatedly summarizes its preceding summary until it fits `max_tokens`; a nonconverging result raises. Thus a complete, informative overshoot is either compressed again or rejected solely for size. Intermediate summaries are not retained as indexed DAG generations. **Trigger: T, complete output above the configured daily/aggregate maximum.** This conflicts with advisory length targets and can progressively thin an index. **The deterministic truncation fallback is indeed gone:** the nonconverging branch raises rather than slicing text. [rollup_builder.py:257](rollup_builder.py:257).

- **RB2 — Daily summaries receive whole multi-day summaries without the temporal boundaries needed to interpret them.** `_daily_sources()` selects an entire parent for every intersecting day, then discards its coverage bounds. `build_day()` supplies only node ID and summary text, without the requested day or each source’s interval. **Trigger: T, a condensed frontier node spans multiple days.** The probe selected identical multi-day content for two different daily rollups. The model cannot reliably distinguish the day’s events from surrounding events unless the previous summary happens to preserve sufficient dates. [rollup_builder.py:223](rollup_builder.py:223), [rollup_builder.py:349](rollup_builder.py:349). A supplies child coverage intervals in condensation input; that particular mechanism is useful here: [A/src/compaction.ts:2402](lossless-claw v1.0.0 src/compaction.ts:2402).

- **RB3 — The 4,096-node limit measures accumulated history, creating a permanent rollup cliff.** Scope loading probes every summary node in the session before computing its frontier. Therefore a scope with thousands of historical children and a tiny current frontier eventually becomes unbuildable. Aggregate enumeration and lineage work have related absolute limits. **Trigger: T, sufficiently large retained DAG; especially relevant to long-lived 1M operation.** This fails explicitly, rather than returning a truncated frontier, but repeated retries cannot make progress without changing or removing retained history. [rollup_builder.py:26](rollup_builder.py:26), [rollup_builder.py:124](rollup_builder.py:124), [rollup_builder.py:204](rollup_builder.py:204), [rollup_builder.py:485](rollup_builder.py:485).

- **RB4 — The maintenance time budget does not bound a build.** The elapsed-time check occurs only between builders. A builder can make multiple summarizer calls through the unbounded convergence loop, each with its own timeout. **Trigger: T, slow generation or repeated oversized output.** A nominal short maintenance pass can occupy its worker for substantially longer than its budget; the budget does not constrain the work it starts. [rollup_builder.py:273](rollup_builder.py:273), [rollup_builder.py:810](rollup_builder.py:810).

- **RB5 — Rollups bypass existing window-resolved summarization controls.** `_summary_controls()` reads raw configuration values for timeout and L2 ratio; the background scheduler passes a copy of raw `_config`, while resolved values live separately in `_window_scaled`. **Trigger: T, W above 262,144, without explicit overrides.** At 1M this path still receives the raw defaults of 60 seconds and `0.5`, rather than the declared 200 seconds and `0.8`. Rollup-specific size preferences also have no entries in the central anchor table. [rollup_builder.py:247](rollup_builder.py:247), [engine.py:1792](engine.py:1792), [window_scaled_mixin.py:63](window_scaled_mixin.py:63), [window_scaling.py:70](window_scaling.py:70), [window_scaling.py:86](window_scaling.py:86).

- **RB6 — Some unavailable/error states become ordinary no-work results.** The maintenance-level exception handler logs at debug level and returns `0`, indistinguishable to its caller from no builds being available. Separately, frontier helpers return `[]` for a closed DAG; `build_day()` interprets an empty result as a genuinely source-free period and resolves it by deleting the claimed rollup. **Trigger: T, maintenance setup/query failure; or a builder invoked with a closed DAG.** The latter is a conditional helper/lifecycle failure, not something demonstrated in the normal private-DAG worker. The contract nevertheless conflates unavailable sources with absent sources. [rollup_builder.py:97](rollup_builder.py:97), [rollup_builder.py:335](rollup_builder.py:335), [rollup_builder.py:475](rollup_builder.py:475), [rollup_builder.py:824](rollup_builder.py:824), [rollup_store.py:592](rollup_store.py:592).

### 4. `assertion_store.py`

Responsibility: snapshot raw sources, publish typed assertions and relations transactionally, track extraction receipts, and query source-valid derived records.

- **AS1 — Unknown observation time becomes a fabricated observation time.** `_snapshot_from_row()` substitutes ingestion `timestamp` when `observed_at` is null, and publication writes that value as assertion `observed_at`. **Trigger: S, imported/legacy source with unknown observation time.** The probe converted an unknown observation into `1000`. This silently changes temporal meaning rather than preserving uncertainty. [assertion_store.py:326](assertion_store.py:326), [assertion_store.py:459](assertion_store.py:459). The raw store explicitly distinguishes these clocks: [store.py:425](store.py:425).

- **AS2 — Source metadata changes leave assertions and receipts apparently current.** Receipt freshness uses the content hash. Query-time provenance validation checks content and span, not the role, observation time, source identity, or other metadata used to derive the assertion. The invalidation trigger only watches content changes. **Trigger: S, metadata correction without a text change.** After changing a raw row from `user`/time `100` to `assistant`/time `200`, the probe retained a current receipt and returned the old attribution/time. Initial publication’s full snapshot comparison is correct; subsequent freshness is weaker. [assertion_store.py:348](assertion_store.py:348), [assertion_store.py:577](assertion_store.py:577), [assertion_store.py:841](assertion_store.py:841), [db_bootstrap.py:2056](db_bootstrap.py:2056).

- **AS3 — The object-value size guard also limits whole assertion records and whole publication batches.** `_canonical_json()` always enforces 32,768 characters, but it is used to hash both complete records and the entire candidate collection. **Trigger: S, individually valid assertions whose combined provenance exceeds that size.** Six assertions with valid 6,000-character source spans failed the probe with `assertion object_value exceeds 32768 characters`, although their object values were tiny. This is an unintended indexing capacity limit and feeds rebuild starvation; it fails explicitly rather than clipping. [assertion_store.py:161](assertion_store.py:161), [assertion_store.py:468](assertion_store.py:468), [assertion_store.py:563](assertion_store.py:563).

- **AS4 — Assertion and relation query limits have no enumeration continuation.** Queries default to 100 and reject limits above 500. They return lists without a cursor or sentinel metadata. Relations select the oldest first; later lifecycle evidence can remain beyond the fixed query boundary. **Trigger: S, more matches than the requested limit.** The state wrapper adds truncation flags, but those flags do not provide a way to enumerate the omitted assertion/relation IDs. Timestamp filters are not a complete replacement for pagination, particularly when many records share a timestamp. Ordering occurs before the SQL limit, which is correct; the defect is the unrecoverable query boundary. [assertion_store.py:780](assertion_store.py:780), [assertion_store.py:854](assertion_store.py:854), [assertion_store.py:879](assertion_store.py:879), [assertion_store.py:991](assertion_store.py:991).

### 10. `retrieval_core.py`

### 12. `selective_compiler.py`

Responsibility: prepare model-visible evidence handles, invoke a minimal selector, validate selected exact spans, and produce deterministic compiled evidence.

- **SC1 — The selector does not receive the question it must answer.** Preparation derives a request but retains only operation, cutoff, facet, and expected operand count. [selective_compiler.py:148](selective_compiler.py:148), [selective_compiler.py:187](selective_compiler.py:187), [selective_compiler.py:469](selective_compiler.py:469).

[selective_compiler.py:410](selective_compiler.py:410), [selective_compiler.py:418](selective_compiler.py:418), [selective_compiler.py:453](selective_compiler.py:453).

[selective_compiler.py:291](selective_compiler.py:291), [selective_compiler.py:303](selective_compiler.py:303).

- **SC5 — Temporal filtering conflates observation and ingestion times and chooses the maximum supplied clock.** `_ref_observed_at()` falls back to stored `timestamp`, mixes raw metadata/date candidates, then takes their maximum. **Trigger: C with an as-of question, especially imported or uncertain-time sources.** A source dated 2020 with unknown observation time and later ingestion time was assigned the ingestion epoch and excluded from historical handles in the probe. [selective_compiler.py:111](selective_compiler.py:111), [selective_compiler.py:166](selective_compiler.py:166).

- **SC6 — The claimed hard selector deadline is only a transport timeout argument.** The function clamps the argument to eight seconds but directly waits on `call_llm()` without an absolute deadline guard. **Trigger: C, a transport whose timeout is per-read/idle, particularly progress-streamed auxiliary calls.** The host explicitly gives such calls an idle timeout and a total ceiling of at least 600 seconds. [selective_compiler.py:279](selective_compiler.py:279), auxiliary_client.py:6124 (Hermes Agent host internals; path elided).

## D. Cross-partition notes

1. **The temporal tool presentation removes the source-node recovery path that the rollup store provides.** `_recent_rollup_sections()` drops `source_node_ids`, returning a rollup ID and text. Its provenance list repeats rollup ID/status rather than DAG sources. The response limiter can then shorten the text. It marks that shortening, but does not attach recovery arguments for the omitted rollup text. This belongs to the tool/schema partition and should be fixed alongside RS2/RB2. [tools.py:2275](tools.py:2275), [tools.py:2307](tools.py:2307), [tools.py:2328](tools.py:2328), [rollup_store.py:140](rollup_store.py:140).

2. **`lcm_recent` fallback can turn canonicalization failures into empty results and understate the available section count.** The fallback catches frontier errors and returns an empty list; it also limits frontier rows before the response formatter calculates `total_sections`. On the rollup branch, sections are likewise sliced before that calculation, although `rollups_covered` separately preserves the rollup count. Recovery requires explicit errors and pageable unsliced candidate counts. [tools.py:2248](tools.py:2248), [tools.py:2256](tools.py:2256), [tools.py:2294](tools.py:2294), [tools.py:2383](tools.py:2383).

3. **Legitimately empty days prevent otherwise available multi-day rollups from being served.** The builder resolves a day without sources by deleting its row, while `_recent_has_unready_rollups()` requires a ready row for every calendar day in the window. An empty day is therefore indistinguishable from missing maintenance coverage. Introduce an explicit source-free completed period rather than requiring a fabricated summary. [rollup_store.py:577](rollup_store.py:577), [tools.py:1971](tools.py:1971).

4. **Automatic assertion extraction does not durably queue all omitted sources.** Scheduling selects at most the configured four sources by default, capped at eight, from the supplied compaction messages. A busy process slot skips the batch. The shown scheduling path does not persist the remainder as extraction jobs. This creates the incomplete-index condition discussed in ST2 independently of rebuild starvation. [engine.py:5093](engine.py:5093), [engine.py:5106](engine.py:5106), [engine.py:5121](engine.py:5121).

5. **Prompt injection receives context strings, not the surrounding structured omission trace.** The pre-answer hook extracts only `context` from session and compiler results. Consequently, placing an adequate omission marker solely in `trace` cannot satisfy the prompt-facing doctrine. Recovery information must survive inside the injected content as well. [__init__.py:300](__init__.py:300).

6. **Schema changes must be coordinated across partitions.** AS2 requires changes to the assertion invalidation trigger in `db_bootstrap.py`; QV1 requires observation-time-aware query-view schema/dependencies. Fixing only Python query checks would leave extraction receipts or corpus watermarks stale. [db_bootstrap.py:2056](db_bootstrap.py:2056), [query_view_store.py:400](query_view_store.py:400).

7. **Completion and deadline handling should be shared, but remain provider-neutral.** AE5 and SC4 independently discard completion metadata at their auxiliary seams. RB4 and SC6 also need caller-owned deadlines because the host’s timeout may mean idle time. A shared normalized completion/deadline contract is preferable to model-name rules. A’s incomplete-signal detection is a useful reference, not proof that all of A’s retry/acceptance behavior satisfies this doctrine. [assertion_extraction.py:169](assertion_extraction.py:169), [selective_compiler.py:301](selective_compiler.py:301), auxiliary_client.py:6124 (Hermes Agent host internals; path elided), [A/src/summarize.ts:1044](lossless-claw v1.0.0 src/summarize.ts:1044).

8. **A is useful for specific mechanisms, not as an automatically compliant replacement.** Its description response includes the summary body and lineage; its focus-brief writer transactionally creates a new record and source memberships while superseding older drafts. However, its expansion code also silently skips missing summaries/messages, and its condensation input sanitizer can discard records. Port the useful mechanisms with B’s stricter markers and validation, rather than copying these paths wholesale. [A/src/retrieval.ts:198](lossless-claw v1.0.0 src/retrieval.ts:198), [A/src/store/focus-brief-store.ts:283](lossless-claw v1.0.0 src/store/focus-brief-store.ts:283), [A/src/retrieval.ts:445](lossless-claw v1.0.0 src/retrieval.ts:445), [A/src/retrieval.ts:490](lossless-claw v1.0.0 src/retrieval.ts:490), [A/src/compaction.ts:2408](lossless-claw v1.0.0 src/compaction.ts:2408).
