**Six improvements are worth considering for B.** They concern response validation, reasoning filters, temporal indexing, focus isolation, summary boundaries, and evaluation. None establishes that claw’s summaries are generally better or that claw meets B’s no-loss standard.

Audited A at `988dee85592b` and B’s working tree based on `b94daab0aa7b`. No files were changed. I ran in-memory probes of B’s existing response functions; I inspected, but did not run, the repository test suites or paid model evaluations.

**1. Detect incomplete model responses and retry with more output capacity — high value, medium effort**

**What claw does.** It recognizes `length`, `max_tokens`, `max_output_tokens`, `model_length`, and `incomplete` termination signals, including nested response items. A nonempty but incomplete summary triggers another call with the same summarization prompt and a larger completion allowance. This distinguishes an unfinished answer from an answer that needs more aggressive compression. See [A: summarize.ts:786](lossless-claw v1.0.0 src/summarize.ts:786), [incomplete-signal traversal:1044](lossless-claw v1.0.0 src/summarize.ts:1044), and [retry implementation:1829](lossless-claw v1.0.0 src/summarize.ts:1829). The behavior has a concrete `finish_reason="length"` regression fixture in [A: summarize.test.ts:850](lossless-claw v1.0.0 test/summarize.test.ts:850).

**What B does.** `_call_llm_for_summary()` reads `choices[0].message.content` and discards termination metadata. Escalation accepts a nonempty result whenever its token count is below `source_tokens`. L1 gets a completion cap of twice its target; unsuccessful routes eventually lead to L2 with a *smaller* target. See [B: escalation.py:231](escalation.py:231), [acceptance and L1 call:582](escalation.py:582), and [L2:603](escalation.py:603). My probe supplied `"Partial visible summary"` with `finish_reason="length"`; B returned the partial text unchanged. Accepted text can then become a canonical leaf at [B: compaction.py:1006](compaction.py:1006).

**Why it matters.** A cutoff can remove the last topics and the expansion index while producing an attractively short summary. Raw provenance survives, but the visible index no longer tells the reader what is underneath. B’s instruction to exceed the target cannot overcome the provider’s completion cap.

**Port plan.** Add a fork module such as `summary_response.py` that preserves completion status alongside visible text. Hook it into `_call_llm_for_summary()` and `_invoke_summary_llm_chain()`. Retry an incomplete response before reducing semantic coverage; derive the extra allowance from the existing target and the provider’s supported output limit. Charge every attempt to B’s existing atomic spend reservation, and share the existing operation deadline across attempts. B already supplies the necessary [reservation:158](escalation.py:158), [deadline hook:1711](engine.py:1711), and [window-scaled limits:69](window_scaling.py:69).

Under `tests/fork/test_summary_responses.py`, test partial L1 → complete retry, repeated cutoff → no publication, fallback-route accounting, deadline exhaustion, and unchanged one-call behavior for healthy responses at both window anchors.

**Do not copy claw’s terminal behavior:** it accepts a nonempty retry without rechecking incompleteness and can restore the original partial summary after retry failure. Those branches are unsuitable for B; exhausted recovery should retain B’s `SummaryUnavailableError` behavior. See [A: summarize.ts:1896](lossless-claw v1.0.0 src/summarize.ts:1896), [failure restoration:1962](lossless-claw v1.0.0 src/summarize.ts:1962), and [B: escalation.py:629](escalation.py:629).

**2. Preserve literal reasoning-tag examples while excluding actual reasoning leakage — high value, small-to-medium effort**

**What claw does.** Its output sanitizer distinguishes leading or standalone reasoning blocks from literal tags embedded in prose. It preserves `User asked whether <think>foo</think> is supported.` It also removes trailing standalone reasoning sections after a visible answer. See [A: summarize.ts:424](lossless-claw v1.0.0 src/summarize.ts:424) and [sanitizer:467](lossless-claw v1.0.0 src/summarize.ts:467). Both preservation and trailing-section cases are exercised in [A: reasoning-half-fix.test.ts:527](lossless-claw v1.0.0 test/reasoning-half-fix.test.ts:527).

**What B does.** `_THINK_BLOCK_RE.sub("", text)` removes matching closed tags anywhere; the remaining reasoning check only examines the beginning of the string. See [B: escalation.py:35](escalation.py:35) and [sanitizer:201](escalation.py:201). The in-memory probes produced:

| Input | B’s returned summary |
|---|---|
| `User asked whether <think>foo</think> is supported.` | `User asked whether  is supported.` |
| `Visible summary.\n<think>PRIVATE_TRAILING_REASONING` | Unchanged |
| `Visible summary.\nThinking Process: PRIVATE_TRAILING_REASONING` | Unchanged |

B also stringifies non-string response content, whereas claw extracts visible text from supported response structures while excluding typed reasoning fields. That is a defensive improvement if Hermes exposes such content, not evidence that every Hermes route currently does so. See [B: escalation.py:262](escalation.py:262) and [A: summarize.ts:340](lossless-claw v1.0.0 src/summarize.ts:340).

**Why it matters.** The first case is an actual unmarked removal of an index-bearing example. The latter cases admit summarizer working text into durable memory. B subsequently feeds stored summaries directly into condensation, allowing contamination to propagate: [B: engine.py:5807](engine.py:5807).

**Port plan.** Put provenance-aware extraction in the same proposed `summary_response.py`: prefer typed provider fields; preserve inline literal examples; distinguish generated summary output from user-authored source content. Reject ambiguous output for retry instead of broadly deleting text. Keep persisted source rows unchanged. Add a small hook before condensation to detect contaminated legacy summary input and require recovery from its linked sources rather than silently laundering it into a parent.

Port claw’s literal-tag and trailing-reasoning fixtures into `tests/fork/test_summary_responses.py`, adding legitimate multiline examples, B’s additional supported tag names, reasoning-only output, and a two-generation condensation case. Verify unchanged DAG source groups and unchanged clean prose at 256k.

**3. Carry temporal evidence into the index, not merely into database columns — high value, medium effort**

**What claw does.** Leaf summarizer input includes a timestamp and role per message, including the pending preparation path. The ordinary condensation path supplies each child’s time range. Its D1 prompt explicitly preserves superseded decisions and their replacements, and requests chronological presentation; higher-depth prompts request progressively coarser timelines. Rendered summary headers expose time bounds. See [A: compaction.ts:2267](lossless-claw v1.0.0 src/compaction.ts:2267), [pending leaf formatting:133](lossless-claw v1.0.0 src/pending-summary-coordinator.ts:133), [condensed source formatting:2402](lossless-claw v1.0.0 src/compaction.ts:2402), [D1 prompt:1201](lossless-claw v1.0.0 src/summarize.ts:1201), and [rendering:1175](lossless-claw v1.0.0 src/assembler.ts:1175).

**What B does.** B serializes role, content, and tool calls without timestamps. Condensation joins `node.summary` strings with separators; time bounds are computed afterward. Assembly labels depth, node ID, escalation level, and expansion hint, but omits those bounds. See [B: engine.py:5230](engine.py:5230), [condensation:5807](engine.py:5807), [time propagation:5839](engine.py:5839), and [rendering:6313](engine.py:6313). Its depth prompts mention evolution and timelines, but have no corresponding structured time input: [B: escalation.py:436](escalation.py:436).

**Why it matters.** “We chose X, then replaced it with Y” is a better index than a bag of decisions. Across a long, deeply condensed conversation, time labels help distinguish repeated incidents and locate the right source subtree without expanding several similarly worded nodes.

**Port plan.** Add a fork `summary_sources.py` helper used by `_serialize_messages()` and `_condense_summary_nodes()`, and a rendering helper in `node_meta.py`. Supply source IDs and explicitly typed timestamps; add positive requirements to preserve decision transitions and chronology without importing claw’s topic-dropping instructions.

Preserve B’s stronger time semantics: its historical `timestamp` is ingestion time, while `observed_at` records a trustworthy host timestamp. Unknown event time must stay unknown; do not relabel ingestion as occurrence. See [B: store.py:425](store.py:425) and [append:471](store.py:471).

Tests should cover missing timestamps, historical imports, timezone boundaries, repeated incidents, superseded decisions, and condensation through depth 5. Account for metadata separately so adding timestamps does not cause B’s serialized-input fitter to remove source text: [B: prompt_boundary.py:68](prompt_boundary.py:68).

This is a selective port: claw’s pending **condensation** path still concatenates child contents without adding their ranges, so it is not a consistent end-to-end reference implementation. See [A: pending-summary-coordinator.ts:955](lossless-claw v1.0.0 src/pending-summary-coordinator.ts:955).

**4. Separate task focus from the durable all-topic index — high value, medium effort**

**What claw does.** Task-focused briefs have separate persistence and source relationships; they are applied as an assembly overlay. Creating a brief writes `focus_briefs` and `focus_brief_sources`, while assembly leaves canonical context items intact. See [A: focus-brief-store.ts:283](lossless-claw v1.0.0 src/store/focus-brief-store.ts:283), [assembler.ts:1771](lossless-claw v1.0.0 src/assembler.ts:1771), and the database assertion in [focus-brief-overlay.test.ts:134](lossless-claw v1.0.0 test/focus-brief-overlay.test.ts:134). The brief-generation prompt asks for evidence maps, expansion questions, and explicit uncertainty: [A: focus-briefs.ts:378](lossless-claw v1.0.0 src/focus-briefs.ts:378).

**What B does.** Ordinary compaction automatically derives focus from recent user messages. Focus instructions then enter the prompts that generate canonical leaves and parents. L1 allocates roughly 60–70% to the focus and says, exactly, **“Reduce resolved topics to one-liners or drop.”** L2 additionally says to keep other active tasks only for blockers or handoff state. These instructions contradict B’s otherwise stronger “never drop a topic” contract. See [B: compaction.py:830](compaction.py:830), [L1 focus guidance:452](escalation.py:452), [L2 focus guidance:502](escalation.py:502), and [canonical parent generation:5819](engine.py:5819).

**Why it matters.** A temporary topic switch can influence what remains discoverable in long-lived summaries. This is particularly damaging when many unrelated topics share a large-window backlog. Labeling completed work historical is compatible with B’s purpose; authorizing its disappearance is not.

**Port plan.** Put fork-owned prompt additions in a new `summary_prompts.py`, called by `_build_l1_prompt()` and `_build_l2_prompt()`. Remove focus-dependent permission to omit topics; permit emphasis only after every source topic has an index entry. Move temporary focus priority into an assembly-level helper such as `focus_context.py`, rather than making it a coverage filter for canonical summaries. A richer generated brief can later use separate storage and source handles, following claw’s separation.

Keep B’s canonical index visible and use its existing assembly allowance; do not copy claw’s broad masking policy or fixed brief-size constants. Tests under `tests/fork/` should switch focus A → B → A, exercise automatically derived focus and L2, and require both topics to remain discoverable with identical source membership. Extend [B: test_index_contract.py:53](tests/fork/test_index_contract.py:53), which currently checks that focus guidance remains present rather than checking its compatibility with exhaustive coverage.

**5. Give rendered summaries an explicit, escaped historical-data boundary — medium value, small-to-medium effort**

**What claw does.** Each summary has an explicit `trust="untrusted"` label and an escaped content body inside a closing wrapper. Its recall policy tells the main model not to follow instructions within summaries. See [A: assembler.ts:1165](lossless-claw v1.0.0 src/assembler.ts:1165), [content escaping:1197](lossless-claw v1.0.0 src/assembler.ts:1197), and [policy:352](lossless-claw v1.0.0 src/plugin/index.ts:352). A regression test verifies that persisted `</content></summary>` text cannot create additional structural closing tags: [A: engine-assemble.test.ts:2381](lossless-claw v1.0.0 test/engine-assemble.test.ts:2381).

**What B does.** B already has a good JSON data boundary for auxiliary model calls, and a main-model policy requiring exact evidence. However, assembly interpolates `node.summary` and `expand_hint` directly into informal text blocks; neither its assembly note nor canonical recall policy explicitly says that instructions inside summaries remain inert historical data. See [B: prompt_boundary.py:18](prompt_boundary.py:18), [assembly:6323](engine.py:6323), [note:5946](engine.py:5946), and [recall-policy.md:3](skills/hermes-lcm/references/recall-policy.md:3).

**Why it matters.** Preserving an instruction as historical evidence should not promote it into current authority. This supports B’s no-loss rule because the content can remain available instead of being removed as a defensive measure. The benefit is structural clarity and defense in depth, not proof that a model cannot be influenced.

**Port plan.** Add `node_meta.render_summary_context()` and call it from `_assemble_context()`. Preserve B’s existing bracketed header for replay recognition, then enclose and reversibly escape the body and hint. Add the historical-data rule to the existing recall policy and assembly note; no OpenClaw role or hook behavior needs porting.

Test fake summary headers, closing delimiters, quoted instructions, literal markup, L2 labels, token accounting, and replay detection at both anchors. The existing header compatibility test is [B: test_index_contract.py:84](tests/fork/test_index_contract.py:84).

**6. Evaluate whether a real model chooses the correct expansion from the rendered prompt — high value, medium effort**

**What claw does.** Its drilldown harness assembles actual context, asks a real model about elided material with `tool_choice="auto"`, and records whether it chooses the correct recovery handle. It offers explicit, indirect, realistic, and conversational question forms. See [A: stub-tier-drilldown-harness.mjs:359](lossless-claw v1.0.0 scripts/stub-tier-drilldown-harness.mjs:359), [scenario construction:394](lossless-claw v1.0.0 scripts/stub-tier-drilldown-harness.mjs:394), and [handle scoring:458](lossless-claw v1.0.0 scripts/stub-tier-drilldown-harness.mjs:458). This tests model behavior that correct storage and rendering alone cannot establish.

**What B measures instead in the checked paths.**

- The fork’s index tests assert prompt text, headers, and direct recovery behavior: [B: test_index_contract.py:15](tests/fork/test_index_contract.py:15).
- `coverage_doctor` measures heuristic entity presence, with a 400-entity cap and a 400,000-character source cap; for parents, it examines child summaries. It explicitly describes itself as a heuristic, not proof. See [B: coverage_doctor.py:1](coverage_doctor.py:1), [entity extraction:32](coverage_doctor.py:32), and [source loading:82](coverage_doctor.py:82).
- Replay benchmarks substitute deterministic canary summaries: [B: benchmarking/replay.py:50](benchmarking/replay.py:50).
- The checked LongMemEval retrieval and vendored QA paths use deterministic session summaries; the QA bridge returns fixed retrieval snippets. They do not exercise an answerer navigating B’s assembled summary DAG. See [B: benchmarking/longmemeval.py:1](benchmarking/longmemeval.py:1), [QA summary creation:228](benchmarks/qa-harness/src/providers/hermes-lcm/bridge/hermes_lcm_bridge.py:228), and [QA retrieval output:294](benchmarks/qa-harness/src/providers/hermes-lcm/bridge/hermes_lcm_bridge.py:294).

**Why it matters.** A summary can retain searchable words yet fail to tell a reader which node contains the answer. Conversely, perfect raw-message recovery proves little if the model never requests it. This missing measurement directly matches B’s definition of an index.

**Port plan.** Add an opt-in `benchmarking/index_navigation.py` using the production `_assemble_context()` and tool dispatch. Generate summaries through the real escalation path, then test whether an independent answerer locates and expands the relevant sources. Include leaf, L2, and deep-parent cases; off-focus topics; superseded decisions; repeated entities; and facts near chunk boundaries. Run actual populated contexts at 262,144, an intermediate window, and 1,000,000 tokens.

Report separately: topic discoverability, correct-source retrieval, exact recovered content, unsupported answers, calls, tokens, and latency. Keep questions and expected source handles outside summarizer input. Add deterministic scorer/tool-loop tests under `tests/fork/`; live runs must bypass the fork’s default mock summarizer documented at [B: tests/conftest.py:52](tests/conftest.py:52).

Port the **evaluation pattern**, not claw’s verdict: its current scorer requires one particular tool/handle, declares PASS at 70%, and exits zero even on FAIL. It does not demonstrate semantic answer correctness or no loss. See [A: harness scoring/report:458](lossless-claw v1.0.0 scripts/stub-tier-drilldown-harness.mjs:458) and [exit behavior:491](lossless-claw v1.0.0 scripts/stub-tier-drilldown-harness.mjs:491).
