## B. Ranked findings and fixes

### F1 — Critical: migration preserves a projection, not the source archive

**Confirmed losses:**

1. A explicitly stores reasoning, file, patch, subtask and other parts. B only loads selected columns and consumes text/tool parts; ignored/synthetic parts are discarded too. **A:** `src/db/migration.ts:1218`, `src/message-content.ts:642`; **B:** `scripts/import_lossless_claw.py:305`, `:380`, `:387`.
2. Existing top-level content suppresses additional text-part content. `scripts/import_lossless_claw.py:436`.
3. JSONL imports choose an active leaf and silently exclude other valid importable branch rows from the destination. `scripts/import_lossless_claw.py:2059`, `:2830`.
4. Certain unmatched tool results are omitted without a durable raw-record representation. `scripts/import_lossless_claw.py:2630`, `:3018`, `:3113`.
5. A’s `large_files` catalog, storage URI and summary `file_ids` have no corresponding migration. A’s embedded instruction `lcm_describe(id=..., expandFile=true)` is not B’s tool contract. **A:** `src/db/migration.ts:1215`, `:1284`, `src/large-files.ts:525`; **B:** `scripts/import_lossless_claw.py:305`, `:533`, `tools.py:5291`.

**Probes:** a reasoning-only part became empty content; an additional text part disappeared behind existing top-level content; a root with two valid branches yielded active import lines `{1, 3}`, excluding line 2.

**Fix:** archive original records/envelopes and all parts before normalization; retain branch identities and unmatched records; migrate or durably reference and verify every external payload. Emit a complete source-accounting manifest with reasons and recovery handles for every excluded projection. Successful migration must support recovery after the A checkout and payload directory are unavailable.

Do not “fix” this by importing malformed records into the active prompt: preserve them in the archive and distinguish their replay eligibility.

### F2 — High: import identity and time can silently misattribute history

The ledger checks source keys without a source-content digest or destination-row existence check. Changed source records are skipped, and deleting a target row does not remove its receipt. The importer directly inserts `timestamp` while omitting `ingested_at`, `observed_at`, `observed_at_source` and `conversation_id`. Numeric milliseconds are accepted as seconds; invalid timestamps become the import-time fallback. `scripts/import_lossless_claw.py:228`, `:674`, `:959`, `:1045`; compare normal storage at `store.py:459` and `:537`.

Other identity limitations include path-derived fallback identities and same-import-ID mapping changes. JSONL discovery and import also read the source in separate passes without a frozen snapshot. `scripts/import_lossless_claw.py:222`, `:3168`, `:3179`; the mapping-change behavior is candidly documented at `docs/retrieval-tools.md:322`.

**Probe:** direct candidate insertion produced `(timestamp=1700000000, ingested_at=None, observed_at=None, observed_at_source=None, conversation_id=None)`. A ledger record survived deletion of its destination row.

**Fix:** persist source identity, original timestamp representation/unit, normalized observation time, actual ingest time, content hash and revision relationship. Reconcile ledger receipts against target existence and content. Freeze input identity/snapshot; reject inconsistent remapping or make it an explicit separately versioned import. Report partial completion through exit status as well as counters.

### F3 — High: QA container names collide, and output paths can overwrite inputs

`_safe("a/b")`, `_safe("a?b")` and `_safe("a-b")` all produce `a-b`. Those IDs therefore share one database; `clear` unlinks the database, WAL, SHM and date sidecar. No durable ownership check precedes deletion. `benchmarks/qa-harness/src/providers/hermes-lcm/bridge/hermes_lcm_bridge.py:65`, `:136`, `:334`.

The state embedding backfill accepts `--summary` or `--ledger` equal to its input database path. The former calls `write_text` on that path; the latter appends JSON to it. `benchmarking/state_embedding_backfill.py:143`, `:203`, `:255`.

**Fix:** derive filenames from a collision-resistant full identity hash; store and verify ownership metadata; isolate each run in a newly owned workspace; reject input/output aliases using resolved paths and file identity. Make cleanup failure explicit, and terminate outstanding bridge work before reporting a timeout as terminal.

Hermes already uses a useful filename pattern: sanitize plus a hash when transformation occurs. **Hermes:** `agent/session_persistence.py:56`.

### F4 — High: “backup-first” instructions do not preserve the complete recoverable corpus

The documented supported online backup and stopped-writer copy procedure cover SQLite only. Externalized content resides elsewhere, including always-on media protection paths. A restore can contain valid references to absent payloads. `docs/operator-guide.md:84`, `maintenance.py:79`, `ingest_protection.py:1335`.

A’s database backup also only performs `VACUUM INTO`; copying that implementation would not solve this. **A:** `src/plugin/lcm-db-backup.ts:45`.

**Fix:** publish a consistent corpus bundle containing SQLite, every referenced payload and an identity/hash manifest; verify restoration into a fresh directory with the original payload directory unavailable. Update upgrade, rotate, diagnostics and downgrade instructions together. Preserve fork metadata before recommending its deletion.

### F5 — High: retrieval scores are being interpreted as evidence recovery and answer quality

The LongMemEval summary function returns the first 1,200 characters without a cut/recovery marker. Nodes have no source IDs. Yet one summary hit is credited with every relevant turn in its session. The turn-NDCG ideal denominator counts only relevant items that appeared in the retrieved list. `benchmarking/longmemeval.py:271`, `:339`, `:364`, `:903`.

**Probe:** one of two relevant exact turns retrieved at rank 1 scored turn-NDCG **1.0**; ordinary NDCG for that same relevance set is approximately **0.613147**. A session marker scored full turn recall without examining its content.

Dates are also distorted: raw rows get current ingestion time while summaries receive `created_at=float(order)`. This invalidates the assertion that observed recency effects are simply faithful production behavior. `benchmarking/longmemeval.py:878`, `:911`; `benchmarks/METHODOLOGY.md:83`.

The published rerank conclusions include a run with **zero actual reranker calls**. `benchmarks/results/longmemeval-v3-500q-fastembed-metrics.json:838`.

**Fix:** separate session discovery, exact-span retrieval, index navigation and answering metrics. Score a turn only when its evidence was actually delivered or expanded. Normalize NDCG against the declared relevant corpus. Preserve source times and real edges. Re-score both baselines and candidates, version the measurement change, and withdraw unsupported claims about fact layers, rerank benefit and other models.

### F6 — High: deterministic gates can pass without testing the named failure or recovery property

- Timeout/refusal fixture metadata does not change the successful summarizer stub. `benchmarking/replay.py:83`, `:183`.
- `lcm_benchmark` returns zero even with recorded failures; release validation treats that process status as a gate. `scripts/lcm_benchmark.py:112`, `scripts/validate_release.sh:213`.
- Zero published assertions can yield coverage 1.0. `scripts/measure_assertion_store.py:171`.
- Zero stubs can yield `recovery_equal=true`. `benchmarks/benchmark_active_tool_stubbing.py:154`.
- Stress may skip exact expansion when no store ID is present and checks doctor’s top-level error rather than all failed checks. `benchmarking/stress.py:598`, `:1074`.
- The shared test summarizer and disconnected carry-over fixtures do not exercise semantic indexes or real ancestry. `tests/conftest.py:100`, `tests/fork/test_marked_loss.py:219`.

**Fix:** inject actual timeout/refusal/incomplete-generation outcomes; assert that required work occurred; fail on missing evidence or skipped required checks; propagate recorded failures to process status. Keep deterministic tests, but label them as mechanical. Add the already-proposed real index-navigation evaluation with exact recovery and independent answer correctness.

### F7 — High: skill guidance does not teach all recovery paths and their real limitations

The strongest positive rules—summaries are cues, use exact refs, do not claim open-ended completeness—are already present. The failure is operational: the model is sent toward synthesis before being taught complete source paging, field-level omissions, foreign-session payload restrictions, or the distinction between transcript enumeration and session rebinding. `skills/hermes-lcm/references/recall-policy.md:9`, `recall-tools.md:39`.

Direct expansion can return empty content and `has_more=false` for an assistant whose substantive data is in `tool_calls`; the session loader is the existing alternate path. `tools.py:5455`, `:1826`. `lcm_expand_query` reads answer content without checking completion status. `tools.py:1762`.

**Fix:** generate a tested recovery reference from actual schemas/serializers. Teach exact pages first, synthesis second. Require the model to inspect continuation and coverage flags. Explain unavailable recovery explicitly. Add behavioral skill tests where the answer is in tool arguments, a later page, an old-session payload, a child-summary tail and a missing source.

Documentation alone cannot repair the missing module capabilities.

### F8 — High: configuration advice can defeat B’s intended window behavior or install upstream

At 1M, the default curve resolves threshold **0.80**, tail count **400**, and tail-token cap **150,000**; the guide says threshold .35/350,000 and presents low-anchor values as universal defaults. `window_scaling.py:59`, `:73`; `docs/operator-guide.md:189`, `:518`.

Explicitly setting those old values is not equivalent to leaving the curve enabled. Provider-labeled presets are supported by deterministic experiments, not route-specific model measurements. The install/update story is split between upstream instructions and FORK.md’s maintained deployment. `benchmarking/policies.py:27`, `docs/operator-guide.md:412`, `FORK.md:23`.

**Fix:** publish low-anchor, high-anchor and current resolved values together; distinguish defaults from explicit overrides. Derive documentation/status examples from one resolver. Document the fork checkout/pin/update route consistently. Add actual upstream/B differential tests at 256k, intermediate-window boundary tests and populated 1M evaluations.

### F9 — High: privacy/exclusion and hard-ceiling instructions conflict with strict no-loss operation

Sensitive-pattern redaction is intentionally irreversible before storage; ignored/stateless scopes are not archived by B. These can be legitimate operator choices, but they are not compatible with an unconditional no-loss profile. `docs/operator-guide.md:199`, `ingest_protection.py:667`, `:1344`.

Rollup code repeatedly summarizes until below a hard ceiling, and tests require that policy. This is not an advisory target. `rollup_builder.py:257`, `tests/test_rollup_builder.py:131`.

“Ollama is local” is also not a reliable data-handling boundary: its configured URL is used directly. `docs/embeddings-setup.md:193`, `embedding_provider.py:1345`, `:1393`.

**Fix:** define a strict archival profile that cannot silently enable destructive exclusions/redaction; preserve excluded content only through an explicitly authorized recoverable archive. Make summary lengths advisory. Classify data egress by actual endpoint/capability, not provider name. Document model-download preparation for offline use.

### F10 — High: release publication is not bound to validation of the fork and actual host

CI’s branch filter excludes ordinary pushes/PRs targeting `betterlcm`; its host is an ABC stub. The real-host test can skip on arbitrary import failure.
